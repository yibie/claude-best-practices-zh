# 自适应思考

> **分类**：模型与能力 ｜ **英文**：Adaptive Thinking ｜ **出现于 3 篇文章**

## 摘要

自适应思考（Adaptive Thinking）是 Claude 最新模型的一种推理机制：模型根据每个请求的复杂度，动态决定是否思考、何时思考以及投入多少推理深度，而不再依赖手动设定的思考 token 预算。它重要在于把"想多深"从调用方的固定配置变成模型的运行时决策，从而在简单请求上更快、在复杂步骤上把思考 token 用在最需要的地方。

## 关键做法

- 不再手动设置思考 token 预算，把推理深度交给模型按请求复杂度自行判断。
- 通过 `thinking` 参数配合 effort 级别控制深度：`low`、`medium`、`high`、`xhigh`（Opus 4.7 支持）和 `max`。
- 权衡成本与延迟：更多思考意味着每个动作更多推理，但也带来更多输出 token、更高延迟和更高成本，按任务价值选择 effort。
- 需要逐轮改变 effort 时使用自适应思考；`between_tools` 模式不支持在对话中途改变 effort。
- 若要在响应中看到思考过程，将 `thinking.display` 设为 `"updates"`（beta，需 `thinking-display-updates-2026-08-18` 标头）或 `"summarized"`，并在其后的 `tool_use` 块之前渲染每个非空的 `thinking` 块。

## 在 Claude 里的用法

在 Claude Code 中使用 Opus 4.7 时，自适应思考取代了带固定思考预算的扩展思考，思考在每一步都是可选的，简单查询可快速响应、无收益的步骤可跳过思考，从而在一次智能体运行轮次中累积出更快的响应。在计算机使用场景中，Claude 借助它思考屏幕上看到的内容、规划多步交互，并在确定点击或按键之前自我纠正。在 Sonnet 5.5 上，不带 `thinking` 字段的请求默认以自适应思考运行（`thinking: {"type": "disabled"}` 会返回 400 错误），需要更细粒度控制时可改用 `between_tools` 设置。

## 常见误区

- 认为可以继续用固定思考预算控制 Opus 4.7：该模型不支持带固定思考预算的扩展思考，应改用自适应思考。
- 认为可以关闭思考：在 Sonnet 5.5 上发送 `thinking: {"type": "disabled"}` 会返回 400 错误。
- 把 `between_tools` 与自适应思考混用：`between_tools` 仅在 `low`、`medium`、`high` effort 下可用，在 `xhigh` 或 `max` 下会返回 400 错误，这些级别需使用自适应思考。

## 相关概念

- [扩展思考](扩展思考.md) —— 自适应思考是其替代方案，用动态深度决策取代固定思考预算。
