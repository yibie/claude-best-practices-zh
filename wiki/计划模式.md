# 计划模式

> **分类**：Claude Code 与编程 ｜ **英文**：Plan Mode ｜ **出现于 2 篇文章**

## 摘要

计划模式（Plan Mode）是 Claude Code 的一种工作模式：智能体先以只读方式探索代码库、产出计划，经确认后再进入执行。它把“想清楚”与“动手改”分开，降低误改风险，也让计划本身成为可审查的产物。在 AI 原生开发流程中，计划模式常被用作从已批准的规格（`spec.md`）过渡到实现的关键环节。

## 关键做法

- 进入计划模式后，只做只读探索：阅读代码库、梳理约束、识别关注点，不编辑任何文件。
- 把计划写清楚再退出：计划完成时通过调用 ExitPlanMode 结束该模式，让计划成为显式的交付物。
- 用工具建模状态转换，而不是替换工具集：始终保留全部工具，通过 EnterPlanMode / ExitPlanMode 切换状态，避免破坏提示词缓存。
- 状态变更通过对话中的系统消息传达（说明当前处于计划模式及相应指令），而不是修改系统提示词。
- 在流程中把计划模式接在规格之后：将已批准的 `spec.md` 交给 Claude，让它采访工程师、迭代计划直到满意，再进入实现。

## 在 Claude 里的用法

在 Claude Code 中，用户可开启计划模式，智能体会收到一条系统消息，被告知处于计划模式、应探索代码库、不要编辑文件，并在计划完成时调用 ExitPlanMode。该模式以工具形式（EnterPlanMode / ExitPlanMode）实现，工具定义从不改变，从而与提示词缓存的前缀匹配约束兼容。在团队流程里，计划模式通常由被批准的 `spec.md` 触发，工程师在会话中与 Claude 反复迭代计划后再放行执行。

## 常见误区

- 认为进入计划模式就该把工具集换成只读工具：这会破坏缓存，正确做法是保留全部工具、用工具建模状态转换。
- 通过修改系统提示词来进入计划模式：更合适的做法是把指令作为消息插入对话。
- 把计划模式当成一次性开关：它更适合与规格、审查等环节串联，计划需经人确认后才进入执行。

## 相关概念

- [提示缓存](提示缓存.md) —— 计划模式的设计直接受缓存前缀匹配约束，用工具而非更换工具集来建模状态正是为保护缓存。
