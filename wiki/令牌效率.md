# 令牌效率

> **分类**：成本与性能 ｜ **英文**：Token Efficiency ｜ **出现于 2 篇文章**

## 摘要

令牌效率指以更少的令牌完成同等工作的能力，是衡量模型与执行框架在成本与性能之间平衡程度的核心指标。它之所以重要，是因为模型升级、分词器变化与 effort 级别调整都会直接改变 token 用量，进而影响长会话的成本与响应表现。

## 关键做法

- 在替换模型版本时预留调优环节：Opus 4.7 相对 Opus 4.6 更新了分词器，并在更高 effort 级别下倾向于思考更多，直接替换未必达到最佳性能，需要对提示词和执行框架做微调。
- 按部署形态区分预期：更自主、异步、单用户轮次的编程智能体，与更交互、同步、多用户轮次的编程智能体，token 用量与行为并不相同。
- 在交互式场景中留意后续轮次的推理开销：模型在用户轮次之后会进行更多推理，这提升了长会话的连贯性与指令遵循，但也倾向于消耗更多 token。
- 用评估集衡量效率与质量的平衡：借助贴近真实提问方式（描述不充分、含错误假设）的评估任务，观察模型在合适 effort 下能否以可接受的用量取得高分。

## 在 Claude 里的用法

在 Claude Code 中使用 Opus 4.7 时，应把令牌效率当作需要主动调优的变量：结合 [努力等级](努力等级.md) 的设置，观察长会话后续轮次的 token 消耗，并对提示词与执行框架做小幅调整。评估模型表现时，可参考 CursorBench 这类贴近真实工程师提问方式的基准，在 Max effort 等设置下同时看成绩与用量。

## 常见误区

- 认为升级到更强模型就必然更省令牌：分词器更新与更高 effort 下思考更多，都可能改变 token 用量，需要重新调优。
- 用同一套预期对待所有部署形态：自主异步的单轮智能体与交互式多轮智能体的 token 行为不同，不能一概而论。
