# 定时部署

> **分类**：企业落地与组织 ｜ **英文**：scheduled deployment ｜ **出现于 2 篇文章**

## 摘要

定时部署（scheduled deployment）是指按设定的时区与频率自动运行智能体的部署方式，让智能体在后台按计划收集上下文并主动产出所需信息。它把"每次手动交代任务"变成"到点自动执行"，是智能体自动化从个人试验走向团队日常运转的关键一环。

## 关键做法

- 明确运行节奏与来源：先确定智能体按什么频率、在什么时区运行，以及每次要读取哪些自定义来源（例如 Slack 和 GitHub 仓库）。
- 跟踪增量变化：让智能体对比自上次运行以来的变化，只汇报新增或变动的内容，而不是每次全量重读。
- 把产出发布到固定去处：将结果主动推送到团队已在使用的渠道（例如发布到 Slack），减少人工追问。
- 沉淀纠正与偏好：把对智能体输出的一次次纠正保存下来，逐步固化为可复用的配置，避免同类错误反复出现。
- 集中管理配置：每个智能体由 Skill、定时任务和共享文件夹组成，应统一维护，避免同一 Skill 从多个对话里被分散修改而难以追踪。

## 在 Claude 里的用法

在 Claude 中，定时部署主要依托 Claude Managed Agents（beta）实现：按计划读取 Slack、GitHub 等来源，跟踪变化并发布结果。官方提供了每日简报（daily brief）的参考实现，可在 Claude Code 中运行一条命令完成配置，`claude-api` skill 会按指引协助设置该智能体。实际使用中，用户常把一项日常事务交给 Claude，纠正其错误并保存纠正，逐步发展为多个各司其职的定时智能体。

## 常见误区

- 以为部署完就一劳永逸：智能体可能在无人察觉的情况下失去对某个来源的访问权限，需要持续关注。
- 忽视偏好维护：若不把纠正和偏好沉淀下来，智能体可能无法遵循使用者的习惯。
- 配置散落各处：把 Skill、定时任务分散在随手打开的对话里修改，会让配置越来越难以追踪。
