# 合并队列

> **分类**：Claude Code 与编程 ｜ **英文**：merge queue ｜ **出现于 2 篇文章**

## 摘要

合并队列（merge queue）是一种在变更合入主分支之前，针对最新 main 重新运行全部检查的机制，用来避免两个各自通过的 PR 组合后产生损坏的 main。它之所以重要，是因为在智能体大规模并发的场景下，传统的合并队列假设正在被重新审视，团队需要以其他自动化手段（如合并后与部署前测试）来保障主干健康。

## 关键做法

- 在应用变更的前提下，针对 main 重新运行每一项检查，而不是只依赖 PR 分支上的通过结果。
- 把新行为先通过功能开关发布给内部重度用户，让回归在到达外部用户之前暴露。
- 公开发布按渠道分阶段推进：先进入 `latest` 渠道，`stable` 渠道随后跟进。
- 配套使用一键回滚，并把事故与回滚转化为评估集，在审查器的提示词、工具或模型变更时重新打分。
- 以回滚率和事故率作为护栏指标，同时衡量人所花费的时间。

## 在 Claude 里的用法

在 Claude Code 团队的代码审查实践中，合并队列与功能开关、先内部使用、分阶段发布、一键回滚一起构成发布保障组合。Anthropic 内部还以 Claude 驱动的“超级粉丝”监控各组件健康，其中就包括针对合并队列的监控实例，它们访问遥测与日志来发现微妙异常。不过在智能体规模下，团队发现照搬业界标准的合并队列全局仓库锁难以有效复制，因而转向投资合并后与部署前的自动化测试，并依赖 Claude 更快地识别和修复并发变更带来的冲突。

## 常见误区

- 认为合并队列在智能体规模下仍然必要且有效：资料指出，当数百甚至数千个变更在测试运行时合并，正规合并队列的意义已不明显。
- 认为有了合并队列就不会出现冲突：放弃全局仓库锁后，并发变更仍可能冲突，只是 Claude 通常能比人类更快地修复。
