# 测试驱动开发

> **分类**：Claude Code 与编程 ｜ **英文**：test-driven development ｜ **出现于 2 篇文章**

## 摘要

测试驱动开发（test-driven development）是一种先写测试、用测试定义成功标准，再增量实现功能的开发方式。它把"什么算做对了"提前固化下来，使代码更可靠、更易于测试，也让智能体编程的产出更容易被验证。在 Anthropic 内部团队使用 Claude Code 的实践中，这一做法被视为提升代码质量的关键工作流环节。

## 关键做法

- 先让 Claude 给出伪代码，理清实现思路，再引导它进入测试驱动开发流程，而不是直接生成完整代码。
- 在写实现之前先写测试，用测试明确成功标准，让"完成"有可检验的定义。
- 采用增量方式推进：小步实现、小步验证，避免一次性产出难以审查的大块代码。
- 定期检查进展，在过程中持续确认方向是否正确，而不是只在最后验收。
- 把测试作为遗留系统现代化的保障手段：迁移旧代码库时仍需仔细监督和测试，以正确保留业务逻辑。

## 在 Claude 里的用法

在 Claude Code 中，可以让 Claude 先输出伪代码，再按测试驱动开发的节奏逐步实现功能，并在每个阶段检查它的进展。安全工程团队的实践就是把工作流从"设计文档 → 粗糙代码 → 重构 → 放弃测试"转变为这种先伪代码、再测试驱动、定期检查的方式。在组织层面推广智能体编程时，也应把这类执行细节纳入规划，因为成功与挣扎的实施之间差别往往在于执行。

## 常见误区

- 把测试驱动开发当成写完代码后的补充测试，而不是先写测试来定义成功标准。
- 直接让 Claude 生成完整实现、跳过伪代码与测试环节，导致代码难以测试、可靠性下降。
- 在遗留系统迁移等场景中因追求速度而放松监督和测试，忽视业务逻辑的正确保留。

## 相关概念

- [智能体编程](智能体编程.md) —— 测试驱动开发为智能体编程提供可验证的成功标准，是其实施中被启用的做法。
