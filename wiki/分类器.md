# 分类器

> **分类**：安全与治理 ｜ **英文**：Classifier ｜ **出现于 2 篇文章**

## 摘要

分类器（Classifier）是自动判断智能体动作是否具有潜在危害的模型组件，属于安全与治理层面的机制。它让 Claude 能在减少人工确认的前提下继续执行任务，同时把真正危险的操作拦下来，因此在自动模式与护栏体系中处于核心位置。

## 关键做法

- 把分类器当作自动判断层，而不是唯一防线：在它之外仍配置明确的硬性拒绝规则，例如在设置中直接拒绝递归删除这类最危险的命令。
- 让分类器在既有护栏之内做判断，形成"外层硬规则 + 内层智能判断"的分层结构，而不是依赖单一机制。
- 用拒绝率验证分类器是否真的在工作：观察会话记录中自动模式拒绝出现的比例，确认它既拦住了危险动作，又没有拖累正当任务。
- 关注分类器带来的效率收益：由于会话暂停频率降低，Claude 在两次中断之间的工作时长显著延长，跨仓库与无人值守任务可以连续运行。
- 对特定高风险领域（如网络安全、生物化学）使用专门的分类器，并在触发时切换到替代模型处理、同时告知用户。

## 在 Claude 里的用法

在 Claude Code 的自动模式中，分类器负责判断每个动作是否具有潜在危害，从而替代大量手动点击权限提示的环节。团队通常配合 Skills 与设置中的命令拒绝规则一起使用，让分类器只在护栏范围内做判断。在 Claude Cowork 中使用 Claude Fable 5 时，配套的新分类器会检测网络安全或生物化学相关请求中的滥用行为，触发后响应自动改由 Claude Opus 4.8 处理并告知用户，对话此后停留在 Opus 上，需开启新对话才能回到 Claude Fable 5。

## 常见误区

- 认为启用分类器就可以不受约束地运行：实际做法是分类器在护栏之内做判断，最危险的命令仍由人工在设置中直接拒绝。
- 把分类器触发等同于任务失败：触发只说明该动作被判定为有风险，正当任务整体上仍可连续执行。
- 认为分类器触发后能自动回到原模型：在 Claude Fable 5 的场景中，触发后对话会停留在 Opus 上，需要新开对话才能恢复。

## 相关概念

- [护栏](护栏.md) —— 分类器在护栏划定的边界内做判断，二者共同构成分层防护。
- [自动模式](自动模式.md) —— 分类器是自动模式得以减少权限提示、连续执行任务所依赖的判断组件。
