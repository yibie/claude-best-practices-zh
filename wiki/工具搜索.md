# 工具搜索

> **分类**：上下文工程 ｜ **英文**：Tool Search ｜ **出现于 4 篇文章**

## 摘要

工具搜索（Tool Search）是一种上下文工程手段：不把所有工具定义预先塞进上下文，而是让智能体在运行时按需检索工具目录，只把相关工具的定义延迟加载进来。它之所以重要，是因为工具数量增长会让工具定义本身占据大量上下文，而工具搜索在测试中往往能把工具定义的 token 减少 85% 以上，同时保持较高的选择准确率。

## 关键做法

- 延迟加载工具定义：智能体只看到工具的简短描述，只有在确实需要时才完整加载该工具的定义，避免预先加载整个目录。
- 让智能体在运行时搜索目录：把工具选择从“启动时一次性决定”改为“执行中按需检索”，由模型根据当前任务拉入相关工具。
- 与 Skills 的渐进式披露配合使用：Skills 与工具都先只暴露简短描述，需要时再展开，二者共同压缩常驻上下文。
- 把硬性前置条件移入工具内部：例如工具 Y 依赖工具 X 的输出时，由 Y 自己检查并返回一条模型可据此行动的指令，而不是在上下文里预先声明依赖。
- 把权限检查放进工具：每个工具检查调用用户能看到或做什么，并返回模型可读的明确拒绝，从而让一个循环服务不同权限级别的用户，无需为每种权限单独搭建智能体。

## 在 Claude 里的用法

在 Claude 平台上，工具搜索以 tool search tool 的形式提供（见 platform.claude.com 的 agents-and-tools/tool-use/tool-search-tool 文档），用于在工具数量庞大时按需加载工具定义。构建智能体时，可以把它与 Skills 的渐进式披露搭配：智能体先看到简短的 Skills 与工具描述，再按需完整加载。Claude Agent SDK（由 Claude Code SDK 更名而来）用于驱动这类智能体循环，Claude Code 本身也是该执行框架的应用之一。

## 常见误区

- 认为工具越多就必须全部预先加载：工具搜索的价值恰恰在于推迟加载，预先全量加载会让工具定义挤占上下文。
- 把权限与前置条件都堆在上下文里声明：更有效的做法是让工具自身检查并返回可读的拒绝或指令，而不是为每种权限级别单独设置智能体。
- 把工具搜索当成编排器-子智能体架构的替代品：资料的建议是，相比为跨团队专家搭建编排器-子智能体，通常更有效的是用 Skills 与工具搜索做渐进式披露。
