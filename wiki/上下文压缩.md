# 上下文压缩

> **分类**：上下文工程 ｜ **英文**：Compaction ｜ **出现于 7 篇文章**

## 摘要

上下文压缩（Compaction）是当对话接近上下文窗口上限时，由 Claude 把此前的历史摘要成一段更简短的描述，并在新的上下文窗口中继续工作的机制。它让长时程任务在硬性上限之下保持连续性，是上下文工程里维持长会话可用的关键手段。压缩做得好不好，直接影响长任务能否收敛以及 token 成本。

## 关键做法

- **在接近上限前主动压缩，而不是等到用尽。** 上下文窗口是硬性上限，接近末尾时任务会被自动摘要；你也可以自行触发压缩，在离开键盘休息前运行 `/compact` 尤其划算，因为提示词缓存一小时后过期，趁对话仍被缓存时总结更便宜。
- **压缩调用要复用父对话的完整前缀。** 使用与父对话完全相同的系统提示词、用户上下文、系统上下文和工具定义，在前面接上父对话消息，再把压缩提示词作为一条新的用户消息追加在末尾，这样提示词缓存才能命中。
- **避免用独立 API 调用做总结。** 另起一次带不同系统提示词、不带工具的「总结这段」调用，会让前缀在第一个 token 处就分叉，缓存完全失效，需按全额未缓存费率支付整段对话——对话越长越贵。
- **用 `/clear` 分隔无关任务。** 在任务之间清空会话，防止先前无关的上下文被反复重发，从源头上减少需要压缩的量。
- **注意压缩对按需加载内容的影响。** 根目录 `CLAUDE.md` 在压缩后会被重新读取；子目录中的 `CLAUDE.md` 与路径限定规则一样，压缩后会丢失，直到再次触及该子目录。

## 在 Claude 里的用法

在 Claude Code 中，上下文压缩会在会话接近上下文窗口末尾时自动发生，模型在新窗口中继续原任务；你也可以用 `/compact` 手动触发，用 `/clear` 在任务间重置，用 `/context` 查看当前已加载的内容（如 `CLAUDE.md`、MCP 工具定义）以便删减不必要项。构建智能体时，可通过 Claude Agent SDK（原 Claude Code SDK）驱动的执行框架获得同样的压缩能力，平台文档见 compaction 一节。压缩效果与模型能力相关：在 BrowseComp 这类智能体式搜索任务上，Sonnet 4.5 无论给多少压缩预算都停留在 43%，Opus 4.5 在相同设置下扩展到 68%，Opus 4.6 达到 84%。

## 常见误区

- **以为压缩只是一次廉价的摘要调用。** 若总结请求与主对话的系统提示词或工具集不一致，缓存前缀失效，反而要为整段对话支付全额输入费用。
- **以为压缩后一切上下文都还在。** 按需加载的子目录 `CLAUDE.md` 和路径限定规则在压缩后会丢失，需要重新触及相关路径才会恢复。
- **只靠压缩省 token。** 减少上下文确实省 token，但若因此导致任务没做完，一次重试的花费会超过节省的部分。
