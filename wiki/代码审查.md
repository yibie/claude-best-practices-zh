# 代码审查

> **分类**：Claude Code 与编程 ｜ **英文**：Code Review ｜ **出现于 3 篇文章**

## 摘要

代码审查（Code Review）是对代码变更进行检查、以发现缺陷与改进点的实践。在智能体编程普及后，写代码本身不再是瓶颈，验证与代码审查反而成为工程团队新的节奏控制点，因此代码审查正在从纯人工活动演变为可被 Claude Code 与自定义智能体部分承担的关键环节。

## 关键做法

- 把代码审查纳入自动化流程：针对经过审核的技术与合规框架运行自动化代码审查，标记关键问题。
- 在交付前设置路由环节，把建议的改动分派给合适的审查者，而不是让审查停留在工具输出里。
- 为代码审查、测试和 CI 构建自定义智能体，把审查能力固化为可复用的团队资产。
- 采用“多角度审查”思路：让审查智能体分散到一次改动的各个部分，从多个视角检查后再综合结论。
- 重视构建循环而非一次性部署，把审查作为循环中的固定环节持续运行。

## 在 Claude 里的用法

在 Claude Code 中，团队可以让 Claude 读取代码库与 CLAUDE.md 文件，理解改动上下文后再执行审查，从而减少审查者自行梳理依赖关系的时间。部分团队进一步构建了专门的自定义审查智能体，例如 Translucent 的“代码审查员”会拆分改动、多角度审查并综合结果。随着智能体编程加速代码产出，代码审查成为团队需要主动设计流程来跟上的环节。

## 常见误区

- 认为智能体编程让写代码变快就等于整体交付变快：实际上验证与代码审查会取代编码成为新瓶颈。
- 把代码审查当作一次性关卡：资料中的实践强调构建循环，审查应持续嵌入流程而非只在交付前执行一次。

## 相关概念

- [智能体编程](智能体编程.md) —— 智能体编程消除了大量手写代码的需求，同时也把瓶颈转移到代码审查，因而催生了对审查智能体的需求。
