# 内部试用

> **分类**：企业落地与组织 ｜ **英文**：Dogfooding ｜ **出现于 3 篇文章**

## 摘要
内部试用（Dogfooding）指团队先把自己构建的智能体或工具在内部真实工作中使用，再根据反馈决定是否产品化。它之所以重要，是因为内部真实使用能比基准数字更早、更可信地暴露问题与价值，缩短从内部工具到面向客户产品的路径。

## 关键做法
- 先把智能体做成内部工具，在团队真实工作流中运行，收集一线反馈后再决定是否对外产品化。
- 让整个团队（包括跨职能伙伴和管理者）都亲自使用自家产品，而不是只由少数人评估。
- 把内部试用结果当作判断依据：当内部试用表现与基准数字一致时，可以更快形成共识、减少争论。
- 内部验证通过后，再借助 Claude API、SDK 或 Claude Managed Agents 将其提升为面向客户的产品。
- 保持团队扁平，让管理者以个人贡献者身份亲自交付，从而真正经历并理解产品的使用体验。

## 在 Claude 里的用法
在 Claude 生态中，内部试用体现为团队用 Claude Code 构建内部智能体并日常使用，Claude Code 团队成员（含跨职能伙伴）同时使用 Claude Code 与 Claude Cowork。内部验证成熟后，通常通过 Claude API、SDK 或 Claude Managed Agents 将同一能力升级为面向客户的产品。

## 常见误区
- 把内部试用当成一次性演示或基准测试：它要求团队在真实工作中持续使用，而非只看跑分。
- 认为只有工程团队需要试用：资料强调跨职能伙伴与管理者的参与同样关键。
- 跳过内部阶段直接产品化：反复出现的模式是先内部使用、再依据反馈对外发布。

## 相关概念

- [Claude Cowork](Claude-Cowork.md) —— 团队在内部试用中同时使用 Claude Code 与 Claude Cowork。
- [自我改进循环](自我改进循环.md) —— 内部试用为自我改进循环提供真实使用反馈，是其依赖的输入。
