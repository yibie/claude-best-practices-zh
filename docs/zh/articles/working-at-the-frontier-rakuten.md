# 在前沿工作：Rakuten 如何借助 Claude Fable 5 在一夜之间构建智能体

作为 Rakuten 业务 AI 总经理，Yusuke Kaji 的工作是"找到变革性创新的种子，并将其推广到整个公司"。

其中一颗种子就是 Claude。

自 2025 年 3 月起，Rakuten 一直使用 Claude，通过 Claude Code 加速软件开发、[在各业务职能中搭建智能体](https://claude.dev/blog/building-effective-agent-automations/)，并为数百万客户提供 AI 功能支持。据 Kaji 所说，Rakuten 选择与 Anthropic 合作，是因为其对企业市场的专注、领导力以及产品品味。

在近十几次模型发布中，他眼看着可以交给智能体的工作不断增长：先是使用 Claude Code [交付生产软件](https://claude.com/customers/rakuten)，随后为公司各团队构建定制的 [Claude Managed Agents](https://claude.com/customers/rakuten-qa)。他把测试新模型比作踏上"新的探索之旅"。

"就像一位优秀的领导者会为下属准备挑战性目标一样，我们也会为新版 Claude 准备挑战性任务，"他补充道。"也许 Claude 也在推动我们不断突破。"

当他测试 Claude Fable 5 时，他意识到有些东西不一样了。这个模型能够比前代模型自主运行长得多的时间，并且第一次能够在 Kaji 睡觉时检查自己的工作、[在一夜之间完成细致复杂的任务](https://claude.com/resources/articles/working-at-the-frontier-how-cognition-trusts-claude-fable-5-to-work-through-the-night)。

正是这种额外的自主性，让 Rakuten 能够把更大、运行时间更长的任务交给智能体，并改变他们的工作方式。

### **构建 AI 原生劳动力**

Rakuten 正在围绕 AI 重塑自身，这个项目被称为 AI-nization——这是全公司范围的行动，旨在将 AI 融入他们为客户、业务伙伴和员工所做的一切。当 Claude Managed Agents 推出时，Rakuten 在一周内就在产品、销售、营销和财务部门部署了智能体，并接入 Slack、Microsoft Teams 和公司自己的任务系统。

对 Kaji 和他的团队来说，过去构建智能体的限制在于谁能写代码；现在，限制在于谁理解业务问题。

"现代企业的设计初衷是尽量减少沟通成本，"他说。"我相信，当我们与 Claude Code 这样的智能体协作，同样尽量减少新创新的成本时——比如从想法到生产的快速转化——它们就能大放异彩。"给一个有能力的员工配备能够保持上下文和品味的智能体，"就能让隐藏的人才释放潜能，并将其潜能放大 100 倍。"

但在每个职能中全天候运行智能体会暴露一个新的限制：人类判断。虽然 Rakuten 的智能体在每个领域都能以大约 10 倍的速度关闭问题，但组织承担的任务数量也在不断上升。增加更多智能体并不能增加判断力。因此，智能体运行得越快，组织的进展就越依赖于人来完成闭环。

### **驱动无人值守运行数小时的智能体**

对大多数构建者来说，构建长时程智能体最难的部分是让它们在最少监督下成功运行。将其连接到正确的工具和上下文是一回事，但根据 Kaji 的经验，智能体在需要人工介入验证其工作之前能运行多久，总是存在限制。

在 Claude Fable 5 之前，让智能体在无人监督下执行数小时的任务始终是一场赌博。"如果它们在第一步就选对了路径，一切都没问题，"Kaji 说。"但如果它们在第一次尝试中选错了方向，智能体就会花费大量时间来修正路径，甚至无法到达目的地。"在一个本应运行五小时或一整天的任务中，一个早期的错误假设可能会烧掉整个运行轮次，而唯一能发现它的方式就是有人去检查。

这种失败模式源于缺乏[自我验证](https://claude.com/resources/articles/building-verification-loops-in-claude-code-with-skills)。任何模型都可能迈出错误的第一步。早期模型的问题在于，它们不会在运行过程中检查自己的工作，因此早期的错误转向不会被察觉。错误会在整个运行过程中不断累积，并在数小时后产生次优结果。

据 Kaji 所说，Claude Fable 5 改变了对持续数天的智能体式运行的权衡，因为它在运行过程中检查自己的工作，频率远高于任何之前的模型。

"我们测试了 Fable，我们非常喜欢它的自我反思和自我验证能力，"Kaji 说。"与之前的模型相比，它在我凌晨 2 点或 3 点指出错误之前就能意识到自己的错误——这样我就能安心睡觉了。"

### **Claude Fable 5 的独特之处**

Kaji 的团队列举了三种行为，将 Claude Fable 5 与其前代模型区分开来，并标志着前沿智能的一次跨越式进步：

-   **它会重新检查自己的假设。** 当任务状态在运行中途发生变化时，Fable 5 会注意到并在采取行动之前纠正错误假设，而不是坚持一条错误路径并在数小时后才发现问题。
-   **它在每一步都回归第一性原理。** 它会在无人告知的情况下对照原始意图重新验证，这正是 Kaji 过去在运行开始偏离路径时必须亲自做的方向纠正。
-   **它符合团队的品味。** 即使在最少的指导下，它在模糊判断上的判断力也与团队一致。Kaji 为此创造了一个术语：品味对齐（taste alignment）。"与贵公司之前任何模型、以及我们用过的任何其他模型相比，Fable 的品味对齐都更加流畅。"

最重要的是，更长的自主性改变了 Kaji 可以委派的工作单元。

"在 Fable 之前，我们不得不把工作拆分成定义明确的块，交给智能体执行，"他说。现在他可以交出整个任务，并同时运行多个。

Claude Fable 5 改变了中间发生的一切。它在每一步进行反思，捕捉早期的错误假设，并自行找到回归第一性原理的路径——无需任何人操控就能重新导航到正确的结果。由于模型在运行中途自我纠正，签核（sign-off）第一次变得可行，Kaji 委派的工作单元也从任务转变为决策。智能体还能在运行轮次之间携带记忆："我们带有记忆的智能体记得过去会话中出了什么问题，并避免重复那些错误。"

结果，任务的绝对数量持续攀升，但真正需要人类介入的任务保持在可聚焦的水平。他说，不必在运行中途跳进去操控，是最大的生产力提升——这让他的团队把时间花在只有人才能做的决策上，并让 AI 原生组织持续加速，而不是因人工方向纠正而停滞。

#### 平衡成本与效率

前沿能力伴随着前沿价格，Kaji 直言成本决定了他能部署多广泛。

"作为一家大型企业，我们希望平衡智能与成本，"他说。他的团队在衡量单任务成本的同时衡量任务完成率，然后将额外能力能改变结果的工作交给 Fable 5，其余工作交给更小的模型。

对 Kaji 来说，有两件事让这笔账在 Fable 5 这边算得过来：它用更少的 token 和更少的错误转向完成更多工作，并且需要更少的人工照看。

### **下一步**

Kaji 现在测试的前沿不是个体速度，而是让智能体协调人员。Claude Code 加快了他自己和同事的工作，但任何组织的难点都在于人与人之间的对齐——将一个人的上下文和品味与另一个人的匹配起来。他正在探索能够"协调或组织、更像管理者"的智能体，保留通常在团队成员之间丢失的细微之处。

"我们不把 AI 智能体视为未来的同事或竞争对手。它们是我们周围的系统。"他要求 Anthropic 践行自己的建议：应该为三个月或六个月后到来的模型构建，而不是为眼前的模型构建。

"我认为我们作为一个社会，还没有找到 Claude Fable 5 的模型—任务匹配，"他说，"但它已经脱颖而出，成为一个跨越了界线、来到我们世界的模型。"
