# 零风险不是目标：CISO 的智能体式 AI 指南

安全负责人正被要求批准几个月前还不存在的智能体式 AI 用例。董事会想知道这些是否受到治理，而在你组织的某个角落，某位员工已经在你不知情的情况下把某个智能体连接到了某个系统。

对这些请求说"不"，会产生影子采用——它没有任何遥测，通常也没有关闭开关。在没有管控的情况下说"是"，则会产生安全事件，而你公司第一起严重的智能体事件会让你的 AI 项目倒退。

在智能体式 AI 时代，CISO 的职责不是实现零风险。相反，我们的职责是让智能体风险变得可理解、有边界。这样，我们就能有意识地接受我们能够管理的风险，让业务按照我们的条件推进，而不是绕过我们。

在本文中，我将分享我们评估智能体安全风险的框架，解释"有边界"在实践中意味着什么，并预告我们工作的下一步方向。

## 后 Mythos 时代：AI 带来的外部风险与内部风险

在[之前的一篇博客文章](https://claude.com/resources/articles/preparing-your-security-program-for-ai-accelerated-offense)中，我和同事分享了 AI 如何缩短漏洞存在与可用漏洞利用之间的时间，并重点介绍了组织如何缓解这些风险。在未来几个月里，我们预计大量长期潜伏在代码中、有时长达数年未被发现的漏洞，将被 AI 模型发现并串联成可用的漏洞利用。像 [Claude Mythos Preview](https://red.anthropic.com/2026/mythos-preview/) 和 [Claude Mythos 5](https://www.anthropic.com/news/claude-fable-5-mythos-5) 这样的前沿模型，已经在发现多年人工审查都未能发现的[严重漏洞](https://www.anthropic.com/glasswing)，包括 OpenBSD、Linux 内核和 [Mozilla Firefox](https://blog.mozilla.org/en/privacy-security/ai-security-zero-day-vulnerabilities/) 中的漏洞。

这些对任何 GRC 项目都是严重风险。缓解和填补漏洞缺口，以及为即将到来的漏洞利用浪潮做好准备，应当是首要任务。关于这个话题，我们准备了一份单独的文档：[为 AI 加速的攻击做好准备](https://claude.com/resources/articles/preparing-your-security-program-for-ai-accelerated-offense)。本指南将聚焦内部风险。

## 治理内部风险

对许多组织而言，智能体系统最可能的威胁途径是：通过监督不足的个人智能体连接不同系统，从而导致数据泄露。另一个担忧是[提示词注入](https://www.anthropic.com/research/prompt-injection-defenses)：攻击者将指令隐藏在智能体读取的内容中，智能体便听从攻击者而非用户。任何接触不可信内容的智能体都可能因此暴露，具体取决于模型防御的稳健程度。随着模型能力日益增强，它们在抵御注入方面正显著变好。虽然[攻击成功率持续下降](http://anthropic.com/research/prompt-injection-defenses)，但并未归零。除这两个例子之外还有许多担忧，而大量涌现的新类别担忧可能让人不堪重负。

### 评估智能体式 AI 风险的四个问题

当某个智能体式用例进入我们的审查流程时，我们通过四个问题来评估其风险：

1.  **它摄取哪些不可信内容？** 不可信是指攻击者有可能编写或篡改的任何内容，包括外部电子邮件、开放网络、第三方文档或公共代码仓库。如果答案是"没有"，那么智能体特有的风险接近于零，你应当快速推进。
2.  **它可以采取哪些行动，代表谁采取？** 只读与读写在关注点上截然不同。工具调用、代码执行和网络出口各自都会扩大敞口。每个行动都在某种身份下发生，你需要知道是哪种身份。
3.  **如果它偏离对齐，影响范围有多大？** 范围乘以严重程度是快速计算法：不良行为者或对齐事件能接触到的是一个文件还是整个组织？它会是一个异常、一个麻烦、一次数据暴露，还是一次真正的事件？
4.  **我有哪些可观测性？** 你能区分智能体行动与用户行动吗？它会进入你的 SIEM 吗？

这四个问题的答案让你对风险有整体认识，而最小代理原则告诉你该如何应对：授予仍能完成任务的最窄能力（更多内容请参阅我们的[AI 智能体零信任](https://assets.claude.com/4e89a59711a145138bd8edbe7539331abc14ac0b.pdf)白皮书）。我们在 Anthropic 的默认姿态是管理员节奏的推广（rollout）：先启用一小部分人，观察遥测，然后扩大访问范围。把这些问题的思路应用到思考有风险智能体系统的新范式上。

一个偏离你意图的智能体，与内部攻击难以区分。安全行业在 2019 至 2022 年间将[内部风险作为一门学科](https://www.cisa.gov/resources-tools/resources/insider-threat-mitigation-guide)正式确立，与边界防御区分开来——认识到系统中最危险的外部攻击途径，往往是通过攻陷一个已经拥有合法访问权限的人。

运营上的差异在于响应时间：[Ponemon Institute 的 2026 年内部风险成本报告](https://www.ponemon.org/news-updates/blog/security/lessons-learned-from-the-2026-global-cost-of-insider-risks.html)发现，组织平均需要 67 天才能控制住一起内部事件——即便在多年投资于专门的内部风险项目之后。以智能体的执行速度而言，以天计的响应太慢了。

## 智能体身份光谱

我们部署的一切都位于[身份访问模型](https://claude.com/resources/articles/agent-identity-access-model)光谱的两端之一。

一端是**系统服务账号**：一个自包含、单一用途、最小权限的身份，只为业务做一件事，不附带任何人类身份。事件响应智能体（见下文）、工单分诊智能体或自主代码审查者都是例子。另一个例子是 [Claude Tag](https://www.anthropic.com/news/introducing-claude-tag)，这是我们新的共享工作区智能体，让人类团队可以在 Slack 等共享工作区中通过 @ 提及 Claude 与智能体协作。

另一端是**人类凭证**。当员工在笔记本电脑上使用聊天界面或个人智能体执行框架（harness），如 Claude Cowork 时，键盘前的人对结果负责，就像他们对用自己凭证做的任何其他事情负责一样。

光谱的中间地带——智能体将某人的委托身份带入此人并未在旁监视的系统——正是问责变得模糊的地方。问责模糊，正是事件变得无法解释的原因。

## 案例研究：一个事件响应智能体

一年多以前，我们把 Claude 指向了我们的事件响应流程。任何为生产应用做过 on-call 的人都知道这个问题：凌晨 2 点你因安全事件被呼叫，你创建一个事件响应频道，拉入合适的人，然后开始工作。这个过程繁琐、文档繁重、节奏飞快。但是，只要具备关于生产环境代码库的正确上下文，其中大部分都可以自动化。

于是我们构建了一个智能体来做这件事。我们给了该智能体访问三个工具的权限：对我们生产日志的只读访问（日志不含 PII）；访问 Slack，用于开启事件频道并运行流程；以及在事件解决后起草 Google Doc 用于事后复盘的能力。

我们用四个问题对它进行了评估：

-   **不可信内容：** 没有。输入是我们自己的日志和我们自己的内部 Slack，两者都在信任边界之内，因此注入需要内部人员或被盗账号，而非匿名攻击者。
-   **行动：** 到处读取，写入仅限于新文档和 Slack 消息。没有编辑或删除，没有权限变更，没有外部端点。
-   **影响范围：** 我们能构造出的最坏结果是，一些轻度敏感的日志行被发布到一个本就已锁定的应急频道中。
-   **可观测性：** 每个行动都进入我们的 SIEM，因此任何异常都会在几分钟内而非几周内浮现。

虽然该智能体并非零风险，但它在有边界的写入面上运行，且具备完整的审计覆盖，这是一个我们能够接受的风险画像。

然而，这个故事有一个有趣的补充：随着每一次模型发布，该智能体都变得更聪明。2025 年 11 月，我们将该智能体从 Claude Opus 4 迁移到 Claude Opus 4.5，其他什么都没改——没有新工具、权限或提示词。紧接着，第一次出现这样的情况：仅凭智能水平的提升，就足以让该智能体在事件处理过程中注意到，它已经在堆栈跟踪中找到了根本原因，而在尚未到场的人类缺席的情况下，它可以尝试自行修复生产环境——通过联系另一个拥有相应代码访问权限的智能体来生成代码变更。

事后我们审查了日志：我们在思考轨迹中看它如何推演：_我已经完成了被要求做的事。人类不在。如果我修复了问题会怎样？_ 在 Anthropic 内部，我们有一个类似 Claude Tag 技术的内部变体，可以编写代码变更并上传供人工审查。它自行通过 Slack 联系了这个类似 Claude Tag 的实例，要求它编写修复。修复被提交到一个拉取请求，由人工审查后才推送到生产环境。

这种涌现出的智能体间通信所扩大的影响范围，本身也受我们原则的治理：最坏的情况不过是上传了一个包含生产日志行的代码变更。这种智能体间通信如今已成为我们事件响应根本原因分析和修复实践的常规组成部分；全程都有人类在环上（human-on-the-loop）监控。

这种涌现行为教会了我们两件事。第一：新能力可能在智能体部署的边界内出现。重要的是限制访问和行动，但不要围绕你认为当今模型的能力极限来限制。第二：即使面对这样的随机性智能体，管控也是有效的。新行为之所以处于人类在环上监控之下，是因为它发生在一个 Slack 频道中，而唯一类似写入的行动仍然需要人工审查。

如今，在事件响应之外，聊天频道内的智能体间通信、在人们工作之处由人类在环上监控，已成为常态。

## 案例研究：Claude Cowork

事件响应智能体是一个服务账号，在一个有边界的服务账号内做一项工作。[Claude Cowork](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork) 则处于光谱的人类操作者一端：键盘前的员工对结果负责，智能体随后代表他们在其授权的系统中行动——而且越来越多地运行在云端。

Claude Cowork 的威胁模型很直接，因为该智能体本质上就是 Claude Code，在本地或托管界面内运行。桌面应用仍然是本地文件访问、浏览器使用和计算机使用所必需的；这些能力直接触及本地机器，需要应用来实现。因此完整的系统面分为两部分：一个（可能是远程的）执行环境，负责编排、MCP 调用和出站网络请求；以及一个用于文件和屏幕访问的本地桥接。

上述四个问题对每个 Claude Cowork 用例都会给出不同答案。但只要管控到位，你就能为它们划定边界，更好地控制任何可能的风险。

下面每项管控都陈述两遍：先是任何智能体环境都应能满足的要求，然后是它在 Claude Cowork 中如何落实：

**身份来自你的 IdP：** 智能体的身份必须在你已经签发和撤销其他一切身份的地方签发和撤销，以你现有的组作为策略单位。Claude Cowork 使用 SAML 或 OIDC 登录，使用 SCIM 进行配置。在 Enterprise 计划中，自定义角色让你可以按组限定能力范围。

**连接器允许列表划定你的数据边界：** 连接器（MCP）的允许列表让你决定智能体可以触及哪些系统。Claude Cowork 采用双门模型：管理员在组织范围内启用每个连接器，然后每个用户再单独授权自己的账号。有按角色的连接器管控，因此启用某个连接器会使其对该角色中的所有人可用（来自你 IdP 的组可以分配到角色）。管理员关于启用哪些连接器的决定，也就是关于智能体可以触及哪些数据的决定。让连接器留在你的企业/生产数据边界的企业一侧；或者，如果它们访问来自不可信来源的信息，确保任何破坏性或单向决策都需要人工审查。例如，如果个人智能体被用于处理电子邮件，但把网络搜索结果作为其输入的一部分，一个极佳的默认做法是只允许创建邮件_草稿_，绝不允许在无人工审查的情况下自动对外发送。如果数据必须跨越边界，应当经过 DLP 或 DSPM 管控。

**按工具、按行动的审批是风险削减变得精细的地方：** 智能体的工具列表是更细粒度的权限边界，因此你需要能够移除某个特定连接器的动词/行动，而不仅仅是整个连接器系统。在 Claude Enterprise Chat 和 Cowork 中，管理员现在可以在组织范围和按角色限制每个连接器内可用的行动：允许起草文档但绝不自动发送，允许读取和搜索但绝不删除。如果让你夜不能寐的故障模式是"生产数据库被删除"，那就把删除动词从智能体的世界中彻底移除。它永远不会尝试不在其工具列表中的行动。（关于这一点补充一句：Claude in Chrome 和 Claude Code 提供更多自由度，因此如果治理不当风险更高。智能体可能利用工程师的浏览器删除生产资源，或用其命令行 CLI 工具做同样的事。更多内容请参阅我们的[保护 Claude Code](https://code.claude.com/docs/en/security) 指南。）

**沙箱化执行让智能体的工作环境远离生产凭证：** 我们在 Anthropic 坚持的一个原则是，智能体循环运行的环境绝不应持有值得窃取的凭证。在 Claude Cowork 的远程会话中，智能体循环运行在 Anthropic 管理的基础设施上一个隔离的临时沙箱中。连接器授权令牌从不进入沙箱，因为连接器调用通过一个注入真实凭证的反向代理进行，因此沙箱从不持有可被窃取的凭证。截至 2026 年 7 月，Anthropic 提交拉取请求的所有代码中，超过 50% 由我们内部版本的类似 Claude Tag 系统编写。我们能安全运行这一切的主要原因在于：所有操作都发生在与生产密钥和账号隔离的临时 VM 中，任何内容落地前都有人工审查。

**出口允许列表是你对抗提示词注入的最强管控：** 离开智能体执行环境的所有流量都应经过一个该环境无法重新配置或绕过的代理，且只有你选择的目的地可达。其逻辑是：如果智能体被它读到的内容攻陷，攻击者仍然必须把数据送出去，而当出站请求只能到达你选择的域名时，就没有攻击者可控的地方可以发送任何东西。在 Claude Cowork 的远程会话中，离开沙箱的所有流量都经过一个沙箱无法重新配置或绕过的强制代理，只有允许列表中的目的地可达。该功能也是 Claude Managed Agents 的一部分。

**遥测通过 OpenTelemetry 进入你的 SIEM：** 智能体行动必须在你已经用于调查的系统里与用户行动可区分，供应商应将其作为你可以指向任意位置的流来交付，而不是你必须去访问的仪表盘。在 Claude Cowork 中，管理员可以在组织设置中配置 OTLP 端点，智能体会流式输出每次工具调用——工具名称、MCP 服务器、参数、成功或失败以及持续时间——并附带用户身份和会话上下文。注意：Claude Cowork 活动目前未纳入 Anthropic 的 Compliance API 或正式审计日志，但我们知道这是客户的重要需求。OpenTelemetry 流是原生的监控路径，而且与 Claude Code 中需主动选择加入不同，Claude Cowork 的 OTel 输出默认包含提示词内容。如果你的留存或隐私审查对 SIEM 中的提示词内容有意见，请在开启该流之前提出。

**有一个组织范围的关闭开关：** 在 Claude Cowork 的组织设置中，一个开关即可同时为所有用户禁用连接器，包括活动会话。在 Enterprise 计划中，同一控制面让你可以在归零之前先收窄范围：RBAC 让你可以从特定组收回访问权限，同时让其他组继续运行；按连接器的管控让你可以禁用某个特定集成的写操作，而不影响部署的其余部分。正确的事件响应计划应当在你需要之前就把这三层都规划好。

## 治理不必成为瓶颈

我从其他 CISO 那里听到最多的观察是，董事会要求他们快速行动，而治理（即回答这些问题并强制实施这些管控）让安全看起来像瓶颈。其实不必如此。

事实上，我们的治理、风险与合规团队自己就在运行智能体。例子包括安全问卷回复、阅读供应商问卷回复和子处理者变更通知，并标记出我们应当反对的那些。

以下是我们从运行这些智能体中总结的三点经验：

-   **先处理风险登记册。** 每季度审查一次的登记册，无法治理那些变化速度快于风险治理流程记录新风险速度的系统。找到自动化这一流程的方法，或许可以将智能体与安全审查流程集成。
-   **了解是谁构建了它们以及为什么。** 在我们的案例中，非工程师使用 Claude Code 在一个用于托管业务应用的内部平台上构建了 GRC 智能体。人们绕过安全，是因为受认可的路径太慢，而这正是大多数影子采用的起源。一个合规分析师能够在你可见的地方构建自己需要的工具，这不算影子采用。
-   **人类问责是工作流的一部分。** 有意识地接受风险，是由拥有接受权限的人类实施的行为。如果你有 ISO 42001 或类似标准，背后有实时的风险登记册和高管风险委员会，那么产出就有去处：重新评分会到达能够接受它们的人手中，被标记的供应商条款会到达谈判它们的人手中。如果你已有 ISO 27001，通常增加 42001 只是与你现有审计师一起的增量补充。

## 为不断演进的模型智能设计你的安全协议

如果你按照模型今天能做什么来设计新项目，那么等项目上线时你就已经落后了。要按模型六个月后的水平来设计。模型智能的提升带来更多自由度，并使那些依赖精心设计提示词的复杂脚手架过时；如果你依赖这些作为管控，它们将在未来几代内部应用中被从智能体中移除，让你失去管控点。

持有自己账号并运行多日工作流的智能体，已经在 Anthropic 和其他组织内借助 Claude Tag 等工具运行，它们需要像你治理人一样被治理：身份、最小权限、监控，以及一个能在几分钟内响应的内部风险项目。现在就在上述这类低风险智能体上锻炼这种能力的组织，将在高自主性用例到来时准备好说"是"。

## 开始实践智能体式 AI 安全

上述框架只有在你组织中改变了某个决策时才有用。以下是三个入手点：

1.  **挑选内部压力最大的智能体式用例，用四个问题过一遍。** 目标是找到你会批准它的条件，而不是给出一个裁决。
2.  **把上述七项要求带给你已经在付费的、构建智能体的团队和供应商。** 问问你的 IdP、你的 SIEM 以及任何智能体供应商，其中哪些他们能在你当前的栈中展示为可用。
3.  **确定你的信任边界。** 写下在你的环境中什么算作不可信内容。一旦这条线存在，未来每个智能体决策都会更容易。

等待零风险意味着永远等待。网络是对抗性的，模型在快速演进，而现在学会衡量并接受这种风险的组织，才是获得优势的组织。
