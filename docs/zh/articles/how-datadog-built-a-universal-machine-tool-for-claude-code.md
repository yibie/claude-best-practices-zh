# Datadog 如何为 Claude Code 打造“通用机床”
智能体、机械化与工业化

Datadog 的所有工程师都在使用 AI 编码工具编写生产代码，其中至少三分之二由 Claude Code 驱动。借助 Claude Code，他们在软件开发生命周期中生成个性化的流程，涵盖四个不同的类别：

-   **针对性改动：** 数十个棘手的缺陷修复、性能优化，以及连接现有服务的桥接层。
-   **大规模重构：** 三天内重构一个自定义 protobuf 解析器，以及在不到三个月内将指标控制平面从 FoundationDB 重写到 Postgres。
-   **替换大型组件：** 新的分片算法和自动扩缩容重新设计。
-   **构建完整系统**：用 Postgres 替换 MongoDB、BYOC 控制平面，以及从零构建的摄取流水线。

然而，随着工作在这张版图上流动，他们发现：在一个维度上生成变得越来越复杂，在另一个维度上验证则变得越来越模糊。

## 流程问题

对工程师而言，流程曾经意味着意图与代码之间的直接关系。你理解问题、编写代码、测试、审查、发布、运维，然后重复。有了智能体之后，这种抽象正在迅速改变。

“你不再是在写代码，而是在塑造工作本身。你在决定智能体应该看到什么、应该拥有哪些工具、成功的含义是什么、失败应该如何被检测……就好像每个人都被提升了三级，进入了管理层，而他们当初并没有为此签约，因为他们是工程师，”Datadog 工程副总裁 Sesh Nalla 说。

借助 [Claude Managed Agents](https://platform.claude.com/docs/en/managed-agents/overview) 这类方案，Datadog 的会话运行时间更长，有时长达数天。每个智能体都会发明自己的工具、自己的胶水代码和自己的约定。智能体变得明显更有用，但仍需要人类来弥合智能体执行与为人类设计的工具之间的差距。

机床就是你在制造业中看到的夹具、工装、量具和铣床。它们生产精确、可重复的零件，你再把这些零件组装成更大、更复杂的机器，比如发动机、飞机、核反应堆和登月舱。它们是工业化的突破所在，因为零件变得可组合、可检验、可替换。

Temper 就是 Sesh 所说的 Datadog 对智能体系统“通用机床”的尝试。换句话说，它是智能体以安全、精确的方式构建所需之物所必需的最小内核。

“正是在这个节点上，我感到我们需要一些更具结构性的东西，”Sesh 说。“如果智能体要构建并运维我们系统的大部分、我们的数据库——这些任务关键的部分——它们就需要这个机床概念的等价物。Temper 就是 Datadog 的那台机床。”

## 通往 Temper 之路

机械化意味着智能体现在承担了更多工作。而工业化意味着工作变得可重复、可验证、可控且可扩展。在 Datadog，这一切并非一蹴而就：通往 Temper 的道路经过了另外三个项目——Courier、BitsEvolve 和 Helix。每一个项目都暴露了下一个项目的瓶颈，也让他们得以提升自己的雄心。

2024 年，他们推出了 [**Courier**](https://www.datadoghq.com/blog/engineering/formal-modeling-and-simulation/)，一个分布式队列系统。他们花了一年时间完全手工、从零构建它。

“困难不在于构建各个部件，而在于让部件之间的交互可观测、可测试、可验证，”Sesh 说。“所以我们在形式化建模和仿真上非常严格……找出那些一旦出错代价高昂或难以逆转的部分，并在那里提高严格程度。”

2025 年 9 月，他们构建了 [**BitsEvolve**](https://www.datadoghq.com/blog/engineering/self-optimizing-system/)，一个闭环进化优化测试框架。一个模型委员会生成代码变体。一连串的[基准测试](https://www.datadoghq.com/blog/ai/production-grounded-code-optimization/)、测试和生产可观测性决定哪些变体存活下来。

“这是我第一次窥见，软件的某些部分可以像活体生物一样被培育——通过带反馈的变异和适应来生长，”Sesh 说。

问题在于：进化的好坏取决于它所适应的环境，而 BitsEvolve 的瓶颈正是这个反馈回路。于是他们构建了 [**Helix**](https://www.datadoghq.com/blog/ai/fully-autonomous-optimization/)，一个可与 Kafka 相媲美的流式服务。Claude Code 完成了大部分构建工作，由一个人掌舵。

“令我们难以置信的是，几天之内我们就有了一个功能完整、可与 Kafka 媲美的系统，”Sesh 说。“［构建速度很快］，我们开始对它做影子运行，并看到了它可以便宜 2 到 5 倍的机会。”

不过，要让它进入生产环境，还需要多得多的磨合：运维层面的加固只能随时间积累，而且需要不止一个人参与，目前仍在推广（rollout）过程中。

“瓶颈又转移了：智能体可以构建系统的大部分……但人类仍然必须通过为人类构建的工具和机制来协调，把工作发布到生产环境，”Sesh 说。

Datadog 需要一种方式，让智能体能够在一个经过验证、由策略驱动的运行时环境中构建自己的工具。这个运行时就是 [**Temper**](https://github.com/nerdsane/temper)。

## Temper

智能体产出代码的速度超过任何团队手工审查的速度，但它们也会犯错。

对 Sesh 而言，智能体生成的内容与通过验证的内容之间的这道鸿沟，正是失败模式累积之处。然而，简单地把智能体包在一个传统代码库外面，只是把问题当作吞吐量问题来处理，并没有弥合验证鸿沟本身。

Temper 把这个等式反过来：智能体不产出应用代码，而是产出规格说明。内核读取每一份规格说明，通过四层分析进行验证，然后部署该规格说明所描述的运行系统。由于规格说明既是那个被证明的产物，也是那个被执行的产物，因此被验证的内容与正在运行的内容之间不存在漂移。

“Temper 改变了系统的_中心_。智能体不再需要为每一个局部需求不断发明互不相连的工具。相反，它产出精确的描述，作为意图和问题域的规格说明。它是一台机床，就像夹具或 CNC 机床一样，你给它们提供关于螺纹规格的说明。它极其可重复。你可以运行它们，用它们来制造飞机和类似的复杂事物，”Sesh 说。

所以在这种情况下，智能体不会每次都即兴发挥最终的机制。它可以产出一份精确的描述，并与 Temper（或类似 Temper 的机制）迭代，先让某个东西运转起来，然后再把它变成可重复、可检验、可复用的东西，这样你就能真正围绕自己的代码库构建一座软件工厂。

每项能力由三份契约描述：

-   **行为**：状态、转换、前置条件，以及必须成立的安全属性。
-   **数据契约**：实体类型、它们的属性，以及每种类型支持的操作，以机器可解析的形式发布，使智能体无需文档即可发现完整的 API。
-   **授权**：默认拒绝、基于范围的审批，拒绝记录为待决决策，人类可以批准并热加载到策略引擎中。

每一份规格说明都要通过四个独立的层，内核才会加载它。符号推理证明每个守卫条件可满足、每个不变式具有归纳性。穷尽式状态探索访问每一个可达状态。

确定性仿真以带种子的故障注入运行真实的生产代码路径——丢包、延迟、重排序、崩溃——因此失败在相同种子下可以精确复现。

随机化属性测试运行约一千条伪随机动作序列，并将任何违规收缩为最小反例。对于一份小型规格说明，整个级联过程在远不到一秒内完成。

## Helix 的暗工厂

Simon Willison 推广了“暗工厂”（dark factory）一词，指的是一种软件流程：智能体在虚拟工厂车间里无需人类持续工作。在 Helix 暗工厂中，Temper 扮演三个角色。

它是面向托管智能体的**智能体控制平面**——会话、角色、工作队列、生命周期。它是**工具构建器**层，让智能体用小型 Temper 应用桥接 SDLC 工具（Git、CI、部署）。它还是 **Helix 控制 API**，即围绕承载工作负载的数据平面的生命周期接口。

“令人意外的是，它开始感觉比智能体基础设施更通用。很多软件，如果你眯着眼看，不过是围绕数据库 API 的控制逻辑：状态、围绕变更的策略、生命周期转换、与外部系统的集成。Temper 可以是通用的，从这个意义上说，它可以应用于任何具有我所描述形态的软件，”Sesh 说。

## 为什么不直接构建一个 CRUD 应用？

“Claude Code 能非常好地［用 TypeScript 或 Python 构建 CRUD 应用］。然而，在普通的 CRUD 应用中，控制逻辑分散在路由、数据库约束、服务代码、后台任务和文档之中。它可能有良好的测试和覆盖率，但运维模式——通常以状态机的形式存在——隐含在代码库中，”Sesh 说。

“Temper 让那个状态机显式化。智能体产出的是精确的描述，而不是任意代码。编译步骤在 LLM 之外，就像你把 Rust 代码交给 Rust 编译器一样。转换表是数据，而不是埋在服务方法里的意大利面式控制流。智能体可以动态地、安全地修改它，并在不经过 CI 的情况下热重载它，”他解释道。

## 这将走向何方

Temper 背后的理念是：每个产物都应该小到能装进你的脑子里。航空和金融系统这类高保障软件几十年来一直是这样构建的，但用人类来达到这种严格程度的成本对一般软件来说太高了，直到智能体进入画面。

工业革命之所以成为可能，是因为机床让零件变得可组合、可检验、可替换，因此我们能够制造越来越大、越来越复杂的机器。

“如果智能体能够在这种纪律下，在工厂里自主构建软件，也许我们不必止步于暗工厂。以这种方式构建的软件开始感觉像一个有机体，我们可以通过反馈、选择和适应来培育、栽培和进化它，”Sesh 说。
