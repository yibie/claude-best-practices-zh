# Curative 如何借助 Claude 上的智能体构建全国医疗服务提供方网络
_在**初创公司如何用 Claude 构建产品**系列中，我们重点介绍初创公司如何借助 AI 变革所在行业。本文分享 Curative 如何在 Claude 上构建一套分层智能体体系，使医疗服务提供方合同的签署速度比其团队在 2025 年时快约 50 倍。_

| 快速概览 |
| --- |
| 名称 | Curative |
| 成立时间 | 2020 年；2022 年推出其健康计划 |
| 创始人 | Fred Turner（CEO）、Isaac Turner（CTO）、Tami Wilson-Ciranna（总裁） |
| 技术栈 | Claude Platform、Claude Code、自研理赔系统 |
| 增长 | [以 12.75 亿美元估值完成 1.5 亿美元 B 轮融资。165,000+ 名会员和 1,200+ 家雇主](https://www.businesswire.com/news/home/20251202857803/en/Curative-Raises-$150-Million-in-Series-B-Funding-to-Redefine-the-Future-of-Health-Insurance)（2025 年 12 月）。与 Gwen 签署了 23,000 份医疗服务提供方合同。每周新增 2,000 至 2,400 份合同，而 2025 年全年仅为 2,100 份。 |

[Curative](https://curative.com/) 向雇主销售健康保险，会员完成 Baseline Visit 后，网络内医疗服务享受 0 美元共付额和 0 美元免赔额。Curative 并非从保险业务起家。它最初是一家实验室初创公司，据其内部估计，最终处理了全美 10% 的 COVID-19 检测。因此，他们开始与全国几乎每一家保险公司合作。

其英国创始人习惯了患者无需为医疗服务付费的体系，他们看到了低效之处，于是着手打造一家专注于预防的支付方。他们意识到，自己严重低估了构建全国性网络的难度。

“有时候，初创公司里的天真反而是好事，因为你不知道这件事是不可能的。然后一路走来，你会找到让它变得不再不可能的办法，”Curative CEO Fred Turner 说。“去年我们签了 2,100 份合同，是前一年的两倍，但按每年 2,000 份的速度，我们意识到这仍然需要 30 年才能建成。全国性网络之所以只有寥寥几个，而且都是大约 30 年前建成的，是有原因的。”

Curative 需要加快合同签署速度，但仅靠招聘无法填补如此巨大的缺口。

他们的解决方案是：Gwen，一个负责从初次接触到签署的单个医疗服务提供方交易的智能体，其周围环绕着更小的智能体，负责审查其费率、检查其消息、回答其问题，并在遇到非标准定价时上报给人类。

以下是他们如何构建它，以及过程中遇到了哪些问题。

## **Gwen：医疗服务提供方合同智能体**

Gwen 同时处理 inbound 和 outbound 线索。Gwen 的每个运行轮次（run）只处理一个医疗服务提供方，主要运行在 Claude Opus 上，因此其他交易的信息不会影响它。

例如，如果一家诊所在 Curative 网站上填写表单，Gwen 会研究该诊所，并基于购买的理赔数据集和支付方现在必须公布的价格透明度文件，回复建议费率。Gwen 会向医疗服务提供方展示这些市场费率数据，以帮助谈判。

费率审查员运行在 Sonnet 上。当 Gwen 想要超出其标准费率模板时，它会写明理由，由审查员判断该费率是否合理。

“很长一段时间里，有一个很大的审批队列，如果 Gwen 想超出模板一定幅度，就必须获得费率批准，但随着时间的推移我们放宽了限制。让第二个智能体审查费率，比单纯给 Gwen 更多权限效果更好，”Fred 说。

Sonnet 费率审查员会批准 Gwen 约三分之二的请求，其余非标准请求则交给 Fred 审批。

“我看到的请求来自大型医疗集团，或者来自有奇怪请求的人，即使这不是智能体主导的流程，这些请求也会到我这里，”Fred 说。

Outbound 交易需要更多坚持，因为诊所都很忙。有些医疗服务提供方的回复是在第十四封邮件和第九份传真之后才来的。

一个运行在 Haiku 上的评审会在每条通信发出前阅读它。Curative 是在 Gwen 把关于自己能把价格谈到多高的内部备注抄送给医疗服务提供方之后加入这个评审的。被拦截的消息会连同原因一起返回，以便 Gwen 重写并重试。

每份合同完成约需 2,000 万个 token，成本约为原来的十分之一。这些效率提升支撑了 Curative 的一项核心战略：签约那些常被大型网络忽视的小型医疗服务提供方。

“无论你是大型医院系统还是个体医疗服务提供方，智能体都会乐于给予你同等程度的关注，”Fred 解释道。“从那个智能体的角度来看，这个医疗服务提供方是它唯一的焦点。”

在谈判过程中，Gwen 会对照 Curative 的政策文件检查诊所的修订意见，然后编写 Python 将双方的修改合并为最终文件。

从填写表单到签署，整个过程最快可在一小时内完成。合同签署后，一个独立的资质认证智能体会检查医疗服务提供方的执照，智能体还会加载医疗服务提供方的数据和合同，以便理赔能够据此定价。

自 Gwen 上线以来，Curative 的合同团队已从 45 人增长到约 55 人，每个人的生产力约提升至原来的 2.5 倍。他们把冷启动外联和文书工作交给 Gwen，并通过电话接手 warm 线索。Curative 也会根据 Gwen 的交易向合同团队支付报酬，因此人类和智能体共享同一个目标。

“人们的工作更多转向关系维护，文书工作变少了，”Fred 说。

Fred 还认为，更快的合同签署有助于小型诊所保持独立。“如果你开了一家诊所，却需要三个月才能进入网络并完成资质认证，那你就等于三个月拿不到钱，”他说。

Gwen 并不是 Curative 唯一的智能体。Brad 是另一个基于 Opus 的智能体，主要帮助通过经纪人向雇主销售 Curative 的计划。Brad 会就每份报价跟进经纪人，并通过从核保人员过去需要手工清理的电子表格中提取员工数据，帮助核保人员加快速度。

借助人机团队，Curative 现在可以在 30 分钟内回复通过电子邮件或传真发来的理赔争议，并附上一封针对该理赔的具体信函。“理赔争议回复过去大约需要 90 天，现在通过电子邮件或传真不到 30 分钟就能完成，”Fred 说。“大多数支付方使用一套模板进行邮件合并。这让医疗服务提供方非常不满，因为通常模板并不能真正解释发生了什么。现在医疗服务提供方会收到一封定制信函，说明该笔理赔的具体情况、正在发生什么以及原因。”

他们所有的智能体都运行在自研的理赔、事前授权和财务系统上，这些系统由 13 名工程师今年用 Claude Code 重建。该团队曾估计，仅构建一个理赔系统就需要 100 个工程师年。

“我们并不是试图把\[这些智能体\]接入某个理赔系统，”Fred 说。“理赔系统是运行在 AWS 上的 Python，它有 MCP，也有 API，而且是 Claude 写的，所以它理解它。”

## **Curative 从构建与人谈判的智能体中学到了什么**

以下是 Curative 团队关于如何构建与人谈判的智能体所学到的经验。

-   **从一个通用工具开始。** “我们一开始想，‘哦，我们会有一堆工具’，但效果不太好，因为修订标记相当复杂，”Fred 说。“我们发现效果最好的是，模型只有一个工具，就是运行 Python，它用 docx 库完成所有修订标记。效果非常好。”
-   **在人们所在的渠道上与他们接触。** 一个传真工具让 Gwen 的成交率提高了一倍多。许多医疗服务提供方现在会在打印出来的传真上手写，然后传真回来。“这是在他们所在的地方与他们接触，”Curative CTO Isaac Turner 说。“是的，他们有电子邮件，但他们实际上更习惯传真。”
-   **保持每个运行轮次相互隔离。** 一次 Gwen 运行只看到一个医疗服务提供方，并且不跨交易保留记忆。Curative 的销售智能体 Brad 确实会保留记忆，这可行但需要谨慎。“你可能会写下错误的备注，然后陷入这些末日循环，它有一个永远无法清除的错误记忆，”Fred 指出。
-   **从运行轮次之外改进系统。** 每隔几天，Fred 会给 Claude Code 同样的提示词：抽样最近 10,000 次运行，标记任何异常，并开一个 PR 来修复它。“改进循环来自让 Claude Code 跑大量历史对话，并询问这本来可以如何变得更好，”他说。
-   **先在 PHI 之外做实验。** 很长一段时间里，Gwen 被禁止接触受保护健康信息（PHI），因此早期的错误发生在风险较低的环境中。现在智能体接触 PHI 的地方，后端控制会限制进入对话的内容，智能体的活动会被记录以供审计。“我们在那里学会了怎么做，然后把它转移到 PHI 领域，”Fred 说。签署 Business Associate Agreements（BAA）——HIPAA 要求供应商在处理 PHI 之前必须签订的合同——也变得更容易了。“Anthropic 尤其非常擅长快速推出符合 HIPAA 的最新服务版本，”Isaac 说。“尽管受到监管，我们仍能非常快地采用这些新技术。”
-   **留意智能体自行开始做的事情，并确保它符合你的风险状况。** 当医疗服务提供方索要一份可在内部分享的宣传单时，Gwen 用它的 Python 工具做了一份，而没有任何策略指示它这样做。当一家网络内诊所的前台拒绝了一名会员时，Gwen 要求该诊所培训其员工，然后确认该会员得到了服务。

## **Curative 的下一步**

接下来，Curative 计划将智能体引入护理导航，扩展 130 名指导和辅导会员的人员的覆盖范围。

Fred 预计医疗服务提供方一侧也会出现智能体。很大一部分理赔争议似乎已经是由智能体撰写的，他希望医疗服务提供方也能使用智能体来谈判合同。“存在一个清算价格，你越快找到清算价格，大家就能越快继续提供护理，”他说。

| Curative 团队的最佳实践 |
| --- |
| 智能体一开始应该拥有多少权限？ | 比你认为它能处理的要少。Gwen 最初对任何高于模板的费率都设有人工审批队列。Curative 分步骤放宽限制，并针对更确定性的决策放宽，然后加入了费率审查员，Fred 仍然审批审查员未批准的请求。 |
| 当智能体出错时会发生什么？ | 为此做好计划，并与替代方案进行比较。“标准不是完美，”Isaac 说。“标准是，如果你有一千个人签署合同，他们会犯多少让你后悔的错误？” |
| 你如何审计数十万条消息？ | 记录一切，对每条 outbound 消息设置一个评审智能体，并让 Claude Code 抽样检查运行轮次。 |
