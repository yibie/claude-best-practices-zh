# Claude Fable 5 实战指南：发现你的未知

在使用 Claude Code 时，我常常想起地图与疆域之间的区别。

地图是对待完成工作的表征，是我的提示词、[Skills（技能）](https://claude.com/resources/articles/skills-explained)和上下文，是我交给 Claude 的东西。疆域则是工作真正需要发生的地方——代码库、真实世界，以及它实际的约束。

地图与疆域之间的差异，就是我所说的*未知*。当 Claude 遇到未知时，它需要基于对我意图的最佳猜测做出决定。完成的工作越多，Claude 可能遇到的未知就越多。

Claude Fable 是我遇到的第一个模型：其工作质量受限于我澄清未知的能力。

重要的是，仅仅提前规划并不总是足够。你可能会在实现深处发现未知，或者你的未知可能指向这样一个事实：你其实应该用完全不同的方式来解决这个问题。

我发现，与 Fable 协作是一个在实现之前、之中和之后不断发现未知的迭代过程。
