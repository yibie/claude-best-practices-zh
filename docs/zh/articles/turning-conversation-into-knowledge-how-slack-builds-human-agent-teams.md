# 将对话转化为知识：Slack 如何构建人机团队
_这是关于构建人机团队系列文章的第二篇。[第一篇](https://claude.com/resources/articles/building-effective-human-agent-teams)分享了我们在 Anthropic 用多人协作式 AI 构建团队的经验。在本文中，我们分享一家早在 AI 到来之前就在思考人机团队的公司的最佳实践。_

Jaime DeLanghe 于 2017 年加入 Slack，从事搜索与机器学习相关工作，使命是将职场对话转化为组织知识。如今身为公司首席产品官的她，从一开始就相信要实现这一目标，人们需要公开地工作，把对话、决策和进行中的工作都保留在频道里，让公司里任何人都能阅读和搜索。在她最近的文章[《工作即对话》](https://jaimedelanghe.medium.com/the-work-is-the-conversation-50a1d61f8f9e)中，她为智能体提出了同样的主张：围绕工作的对话正是智能体发挥作用所需的上下文，并最终帮助我们实现这个数十年之久的目标——把零散的知识转化为生产力。

为了解这在 Slack 的实践中是什么样子，我们与 Jaime 聊了聊她构建高效人机团队、推广这些新工作方式的最佳实践。

## 把对话历史当作知识库

多年来，职场对话——人们协作共事产生的"尾气"——会累积成组织知识，这一承诺从未兑现。

"我在 Slack 早期有很多研究论文表明，实际上，对话并不会转化为知识，"Jaime 说。"你希望它会，但实际上它只是一大堆东西摆在那里，人们仍然得反复重复自己说过的话。"

理清所有这些"尾气"根本不是人力所能及的。现在，这是智能体的工作。

### 如何付诸实践

-   **默认使用公开频道**：智能体只能从它看得见的内容中学习。在私信或私密线程中做出的决策对它们不可见——并且对组织而言永远丢失了。
-   **向智能体询问推理过程，而不只是记录**：不要只搜索决定了什么，而是让智能体重构*为什么*这样决定，以及此后上下文发生了怎样的变化。
-   **扩大接触面**：Slack 和 Claude 这类工具正在把会议、邮件、日历和文档库串联起来——你连接的上下文越多，团队重复自己的次数就越少。

## 学会在智能体与人类之间交接任务

人机团队的核心节奏是交接的循环。由 Slack 中的 Claude 驱动，智能体承担生产性工作——起草、总结、监控、准备——并把结果交给人类。人类审阅、决策、调整方向，然后把工作交回给智能体执行下一步。

要看这一切在实践中的样子，看看 Jaime 如何开始她的一周就知道了。

"现在是周一早上，我刚刚收到了一个智能体为我构建的每日简报，"Jaime 说。

同样等待她审阅的还有：上周产品研讨会的回顾以及被标记的升级事项、一份关于全网 AI 动态的报告、当天会议的简报，以及一份她交给智能体重写的过时个人简介。在每一轮循环结束时，人类根据智能体的行动进行审阅并做出决策。

### 如何付诸实践：

-   **以智能体构建的简报开启一天。** 回顾、升级事项、会议准备和网络资讯汇总都是适合由智能体驱动、人类审阅的任务。
-   **把工作锚定在共享频道中。** 把所有工作放在共享频道里，让人类和智能体可以一起分诊，由人类主导优先级排序。
-   **让轻量信号可执行。** 在 Jaime 的频道里，一个 emoji 表情回应就会把一个事项加入列表，智能体会接手这个任务。

## 为智能体分配明确的角色

如果你的心智模型是一对一的聊天机器人，那么与一群专业化的 Claude 智能体协作可能会让人感到迷茫。Jaime 的方法是社会性的而非技术性的："我喜欢把智能体看作某种同事。"

正如人类队友有角色和职责，智能体也应当有明确的目标和专注领域。"如果智能体的价值感觉是被强加的，而不是被使用它的人清晰地感受和理解到的，那就很难记住这东西到底是干什么用的，"她说。

**如何付诸实践：**

-   **把常规的事务性任务交给通用智能体。** 与其让人们记住某个专用工具，不如训练一个智能体处理重复性任务，比如提交帮助台工单，或把上周的指标整理进状态更新。
-   **让价值被感受到，而不是被强加。** 如果人们说不清一个智能体是干什么用的，也许该让它退役了。

Slack 从最早的日子起就推荐默认公开的频道："你是在为接下来所有的工作构建共享的理解、共享的上下文，"Jaime 说。

她建议保持频道公开，除非有特定理由需要限制上下文和知识。智能体可用来参考和支撑其工作的信息越多，它们作为队友就越高效。

开放的上下文会累积——新人上手时面对的是历史记录而不是空收件箱，没有人需要重复自己。现在智能体也从中受益，而这些上下文和工作记忆又回流给人类。

**如何付诸实践：**

-   **把日常业务工作保持在公开状态。** 让非敏感项目、公告和问答频道保持公开，这样智能体同事就能获得发挥最大作用所需的知识。
-   **记住你的智能体读的是你团队读的内容。** 私密频道对每一个需要汇报它的智能体来说都是盲区。
-   **让心理安全感来划定界限。** 一旦真正敏感的材料被隔离起来，工作退回到私信的主要原因就不是保密——而是不愿被看到过程中的样子。人们应当有信心在公开场合做日常工作，包括粗糙的草稿和未成形的提问，并相信同事会以善意回应。而这种开放会累积："你通过给予信任来获得信任。"

## 通过展示可能性来推广采用

学习一种新工作方式最快的方法，就是看队友怎么做。Jaime 在 Salesforce 见过这种情况：员工在一个名为 _How I Slackbot_ 的全公司频道里分享技能、调试技巧和工作流窍门，据她估计该频道有数千名成员。在那个默认公开的频道里，一个来自销售流程的窍门最终可能重塑一个工程流程。

在 Slack 内部，推动产品经理使用 Claude 的举措"是你所能想象的最自组织的事情"。一位产品经理请开发者体验负责人帮他完成设置，然后写了一份画布，展示他做了什么以及怎么做的。其他产品经理照搬了这个格式。各团队组织了工作坊，还建了自己的 git 仓库。

**如何付诸实践：**

-   **建立一个全公司范围的展示分享频道。** 给员工一个公开的地方分享技能、调试技巧和工作流窍门，让一个职能的窍门可以重塑另一个职能。
-   **鼓励别人可以照抄的书面记录。** 一份简短的"我做了什么、怎么做的"文档，能把一个人的设置变成团队模板或技能。

## 衡量结果，而非活动量

从在 Slack 的早期日子起，Jaime 就一直在琢磨如何衡量生产力。"我们想让人们发更多消息吗？"她说。"也许不想。发消息可能并不意味着他们从 Slack 中获得了更多价值。更多消息可能意味着人们找不到他们需要的东西，或者没法第一次就把意思说清楚。"

如今，衡量 AI 价值的问题看起来颇为相似——而对于如此复杂的事物，简单的指标并不管用。token 用量告诉你灯是亮着的，但知道这一点虽然重要，却并不充分。

**如何付诸实践：**

-   **把用量指标当作脉搏检查，而非价值证明。** 活动量告诉你采用正在发生，而不是它在起作用。
-   **准备好运用你自己的判断。** 没有干净的方法能证明人们使用这些工具的方式会带来更好的业务结果。正如 Jaime 所说，把两者联系起来仍然需要"很多信念的飞跃"，没有任何仪表盘或用量统计能替你证明这一点。

## 一起改变工作方式

对于试图落地人机团队的组织，Jaime 最重要的一条建议是重新构想每一个工作流："我们将不得不弄清楚如何改变我们的工作方式，而不只是把同一种工作做得更快更多。而这将是一项团队运动。"

对于构建高效人机团队，她最重要的建议是什么？尽早开始，但从小处开始。把一群人带进一个有 Claude 的共享频道，给他们同一套资源，让他们工作。如果 Slack 的经验有任何指导意义，他们构建的东西会自行传播开来。
