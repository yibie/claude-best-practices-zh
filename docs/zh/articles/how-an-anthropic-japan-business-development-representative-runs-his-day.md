# Anthropic 日本的一位 BDR 如何用 Claude Managed Agents 度过一天

作为 Anthropic 日本团队的一名业务拓展代表（BDR），我的工作是向日本企业展示 Claude 如何简化和自动化他们的工作流，但直到今年早些时候，我的大部分工作仍然是手工完成的。我每天早上要花几个小时分配和筛选线索，然后用日语或英语写邮件。在剩下的时间里，我更新 CRM，通常落后一天甚至更久。现在，我的智能体在我一天开始之前就把大部分工作准备好了，我只需要审阅。

我搭建的第一个由 Claude 运行的工作流相当粗糙，但它管用。我一次把一项工作交给 Claude，纠正它做错的地方，并把这些纠正保存下来。随着时间推移，这逐渐发展成了几个智能体，每个负责一项不同的日常事务。

消息很快传开了，同事们开始向我要我的提示词和 Skills，好搭建他们自己的。我能发给他们的只有一个 zip 文件，里面是我的 Skills 和知识库里的几个 Markdown 文件，他们得先上传到 Claude，然后回答一轮设置问题，才能让任何东西跑起来。我自己的配置也越来越难以追踪。每个智能体都是一个 Skill、一个定时任务和一个共享文件夹，而我是在手头随便哪个打开的聊天里让 Claude 改的，所以同一个 Skill 会从许多不同的对话里被编辑。

我想在一个地方把每个智能体定义一次，并且能看到我对它做过的每一次改动。所以我决定试试 [Claude Managed Agents（在新标签页中打开）](https://platform.claude.com/docs/en/managed-agents/overview)（beta），这是我们在 Claude Platform 上的托管智能体基础设施。

一开始我有些犹豫。文档里讲的是调度、工具和凭据保险库，而我是个销售代表，所以我以为 Managed Agents 是给那些能搭建和维护必要基础设施的开发者用的。我还是试了，因为我的智能体已经存在了，我只需要把它们迁移过去。

结果发现我并不需要成为开发者。我用平实的语言描述每个智能体的工作，Claude 写了几个简短的设置脚本，我在笔记本电脑的终端里运行它们。（如果你是从零开始，Console 里也有一个[快速入门](https://platform.claude.com/workspaces/default/agent-quickstart)，带有现成的智能体模板。）从那以后，就没有任何基础设施需要我照看了。

在这篇文章里，我会讲我如何设计和原型化这支智能体队伍，为什么把它迁移到 Managed Agents，Claude Tag 如何接手任何超出常规的事项，它如何改变了我的每周工作，以及我会对那些想搭建自己的智能体来自动化手工、重复性工作流的销售人员说些什么。

## 设计我的智能体队伍

我把我的工作流拆分到几个智能体上，并给每个智能体一个明确的职责。单一职责让每个智能体都容易理解、容易追踪，尤其是在出问题的时候。我还给每个智能体起了日语名字，因为它们主要用日语工作。它们合起来叫 _Nakama_，意为“伙伴们”，或者更字面地说，是与你共事的同伴：

-   **_Furiwake_**（“分拣”）最先启动：它读取每日入站队列，把每条线索分配给团队里合适的代表，平衡线索数量和每条线索的优先级，并查看当天谁在岗，这样在我们任何人开始一天之前，每条线索都有负责人。每次运行结束时，它会向一个专门的 Slack 频道发布报告（所有进来的线索、所有已分配的线索），这样我就能追踪交接情况。
-   **_Sabaki_**（“处理”）对我被分配的线索进行分诊：它筛选每条线索，按预设标准分类，为该类别采取既定的下一步（起草一封引导对方使用自助服务的回复，或精心撰写一封定制化的首封邮件），更新 Salesforce 中的线索记录，并起草首次接触邮件。它从 _Nakama_ 的共享知识库中获取草稿内容，这是一个每个智能体都会读写的[记忆存储（在新标签页中打开）](https://claude.com/resources/articles/claude-managed-agents-memory)（详见下文）。
-   **_Henji_**（“回复”）每小时扫描我的收件箱，找出需要回复的客户邮件，并根据邮件线程用日语或英语准备一封回复草稿，所用知识库与 _Sabaki_ 相同。我可以审阅、编辑并发送草稿。
-   **_Shoudan_**（“商机”）读取近期的客户互动，并把更新推送到 [Salesforce](https://claude.com/resources/articles/salesforce-in-claude)，这样商机记录无需手工录入就能保持最新。
-   **_Nokori_**（“剩余事项”）在一天结束时运行：它扫描我的日历，读取附带的会议转录，总结每次会议，并起草后续跟进，同样来自同一个知识库。

每个智能体都按[调度](https://claude.com/resources/articles/whats-new-in-claude-managed-agents)运行。第六个智能体是 Nakama 的协调器，是这支队伍的运营经理。它在各次运行之间更新智能体的指令和共享知识库。当我想改变某个智能体的工作方式时，我在 Nakama 的 Slack 频道里用平实的语言写下我想要的内容。只有我能发布更改智能体指令和系统提示词的请求。协调器大约每 15 分钟检查一次那个频道，接收请求并完成更新。

## 在 Claude 中原型化这支队伍

你不需要 Managed Agents 就能开始。我先在 Claude 中原型化了整支队伍，用了以下几样东西：

-   每个智能体一个 Skill：一项工作的指令。
-   每个 Skill 一个定时任务，这样我就不需要手动运行它。
-   我笔记本电脑上的一个共享文件夹作为知识库，每个 Skill 都把自己的学习成果写回其中：它起草的内容与我实际发送的内容之间的差异，以及它沿途挖掘到的任何新信息。

在 Managed Agents 上，Skill 变成了智能体的系统提示词，定时任务变成了[智能体部署上的调度（在新标签页中打开）](https://platform.claude.com/docs/en/managed-agents/scheduled-deployments)，共享文件夹变成了记忆存储。我仍然用平实的语言请求更改，但现在我都在一个 Slack 频道里做，而且每次对智能体指令的更改都会保存为新版本，所以每个智能体都保留着一份带编号的指令历史。我建议先在 Claude 中开始，等你拥有的智能体多到难以轻松追踪时，再把它们迁移到 Managed Agents。

## 在 Claude Managed Agents 上运行这支队伍

在 Managed Agents 上，对我的工作流最重要的有三件事：

**智能体可以在后台运行**

无论我的笔记本电脑是否打开，甚至离线时，智能体都按调度运行。调度是每个智能体部署的一部分。我也可以在 Claude 中调度 Skills，但那些调度每一个都是我自己的应用里设置的任务。在 Managed Agents 上，我在 Console 中设置运行频率和时区，就在已部署智能体的指令和工具旁边，而且我没有任何 cron 任务需要在旁边维护。如果某次运行出了问题，我可以在 Console 中打开它，查看智能体采取的每一步。而且当我在试用对某个智能体的更改时，定时运行会继续使用已部署的版本，所以半途而废的编辑不会进入明天的运行。

**Nakama 共享一份记忆，并从我的编辑中学习**

每个智能体都读写同一个[记忆存储（在新标签页中打开）](https://claude.com/resources/articles/claude-managed-agents-memory)，所以任何智能体都能使用其他智能体的学习成果。智能体会把它们写的草稿与我发送的邮件进行比较，并把每一处差异保存为一条关于我会如何措辞的笔记。它们还会保留在调研答案时挖掘到的任何新信息，来自我们的内部文档和我们的官方网站。我在 Henji 的草稿中修正一次措辞，Sabaki 和 Nokori 就不再犯同样的错误。

**凭据存放在带作用域权限的托管保险库中**

我的智能体可以访问我的电子邮件和我们的 Salesforce 记录，但由于这些是客户对话和公司记录，我希望这种访问受到控制。凭据存放在[托管保险库（在新标签页中打开）](https://platform.claude.com/docs/en/managed-agents/vaults)中，它保护智能体用于登录外部服务的凭据，例如 OAuth 访问令牌和刷新令牌、API 密钥以及个人访问令牌。每个智能体的部署只使用其工作所需的保险库，它永远看不到凭据，而且我可以一步撤销访问权限。

## 把下一步交给 Claude Tag

对于 Nakama 产出的大部分内容，我只需要在收件箱里读一份草稿并发送，或者瞥一眼更新后的 Salesforce 记录。但有些事项需要后续步骤，例如弄清楚升级路径或采购途径，或者把问题上报给另一个团队。

对于这些，智能体不会停下来等我。它们把事项交给 [Claude Tag（在新标签页中打开）](https://www.anthropic.com/news/introducing-claude-tag)（beta 版）。Claude Tag 是作为我们 Slack 工作区成员设置的 Claude：它已加入的频道里的任何人，无论是人还是我的某个智能体，都可以 @Claude 提出请求，它会接收请求并在该线程中处理。一旦在你的工作区中配置好，就没有什么新东西要学了。你像 @ 一位同事那样 @ Claude。

在我的配置中，它是这样工作的。智能体把行动事项发布到 Nakama 的 Slack 频道并 @ Claude。Claude 读取该线程，检查我们的规则和适用的条款，列出选项，并起草所需内容。当某个步骤需要我审阅或签核时，它会 @ 我。当需要客户或其他团队先回复时，Claude 会为自己设置一个提醒，在指定的日子回来查看。在下面的线程中，它设置了周二的提醒，用来检查客户是否已回复，以及交易台是否已答复工单。当提醒到期时，Claude 会检查两者，并在同一线程中发布进展。如果有人需要提醒，它会起草消息并 @ 我去发送。

![一张模拟人类、Claude 和智能体之间对话的截图](https://assets.claude.com/407d1a67eadd3ebd1d4ec34fd1fabebb42b64829.png)

Claude 还会发布一份关于产品和定价更新的晨间简报。Nakama 协调器会接收这份简报，并把必要的更改写入共享知识库。

## 我的每周工作发生了什么变化

现在 Claude 准备入站回复并保持 CRM 记录最新（大部分情况下）无需我手工输入，我的角色是审阅任何需要人类判断的内容。一份书面规则手册定义了每个智能体的职责范围，而定价问题、敏感客户或含糊的请求等事项会转交给我。来自 Henji、Sabaki 或 Nokori 的每份邮件草稿顶部都附有一段简短摘要，说明当前情况，所以我不必追溯整个线程来理解上下文：我读摘要、确认、修改并发送。

![一张由 Claude 起草、供人类审阅的邮件截图。](https://assets.claude.com/209fde33711300fd8cfb2f1fc7005f21bca2a20d.png)

查看 Nakama 每周完成事项的日志，并把每项任务按我手工完成所需的时间计算，这支队伍每周为我节省约 60 小时的工作。我把腾出来的时间花在智能体（目前）无法有效完成的工作上：与客户对话、外呼策略、跨职能项目，以及帮助同事搭建他们自己的队伍。

## 设计更高效的智能体

定时智能体每天都运行，无论我是否在看着，所以浪费会累积起来，体现在成本和可靠性上。一些最常见的错误包括：在现有指令上追加而不是更新它们、给智能体提供超出其任务所需的上下文，以及用最大的模型、最高的努力级别运行每一项工作。

让智能体保持高效的，大部分在于我如何设计这支队伍：每个智能体只有一项工作，所以它的指令始终聚焦于那项工作；每个工作智能体按调度运行，所以它醒来、完成自己的一轮、然后停止；智能体共享记忆，所以做一次纠正就能在各处复用。

另一个重要因素是每个智能体运行在哪个模型上。一旦智能体的工作被明确定义，它可能不需要我们能力最强的模型。Furiwake 和 Shoudan 遵循一份书面规则手册，所以它们运行在 Sonnet 上，这是我们较小的模型。Sabaki、Nokori 和协调器运行在 Opus 上，这是我们较大的模型，因为它们的工作需要更多判断。协调器最需要它，因为它编辑其他智能体的指令，一次糟糕的编辑会波及每个智能体。Henji 需要和 Sabaki 一样多的判断，因为每个客户的邮件都不同，但它也比任何其他智能体运行得更频繁，贯穿整个工作日。每次都让它运行在 Opus 上会是最昂贵的选择，所以我在 Managed Agents 中使用了[顾问策略（在新标签页中打开）](https://claude.com/resources/articles/the-advisor-strategy)：Henji 运行在 Sonnet 上，当它遇到自己无法做出的决定时，它会向 Opus 寻求建议。顾问读取 Henji 到目前为止所做的工作，并返回一个计划、一处纠正或一个停止信号，然后 Henji 完成草稿供我审阅。我还把每个智能体的努力级别（模型在回答前思考多久）与其模型分开设置，只在推理困难的地方调高，比如 Henji 的回复。

## 我的收获

有三件事我会告诉任何搭建自己队伍的人。

1.  **你不需要每次都写详细的提示词。** 把工作描述一次，让 Claude 起草，修正草稿，让它保留修正。
2.  **知识库比提示词更重要。** 每一次纠正和过往互动都保存在所有智能体都能读写的地方，所以 Claude 从那里获取上下文，而不是从更长的提示词中获取。花了几百轮廉价的起草、修正和保存，才让草稿听起来像我。
3.  **更早地给 Claude 更多空间。** 起初我一直做那些我以为需要我的任务：更新知识库，或者手工编辑每个智能体的指令。一旦我放手，两者都运转良好。现在智能体自己把学到的东西写入知识库，而当我用平实的英语提出请求时，协调器会更新其他智能体的指令。对于那些我可以放心交给智能体的工作，我之前太谨慎了。
