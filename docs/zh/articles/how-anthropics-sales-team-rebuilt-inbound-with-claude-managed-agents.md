# Anthropic 的销售团队如何用 Claude Managed Agents 重建入站流程
作为一名销售负责人，我很不情愿地承认：不久前，那些想为公司购买 Claude 的人并不能足够快地得到他们需要的答案。他们填写了我们的 Contact Sales 表单，却要等太久才能收到回复，有时要等好几天。他们的大多数问题都很简单：某个方案多少钱、是否有席位最低要求，或者我们能否满足 HIPAA 的合同要求。答案就在我们的文档和支持文章里，但客户希望有人能快速带他们走一遍。

于是我们在 Claude Managed Agents（beta）上构建了一个购买智能体，把潜在客户从「我想为公司购买 Claude」一路带到完成购买。这个购买智能体现在每天进行数千次对话，回答客户最迫切的问题，并帮助他们完成结账。它升级给我们团队的客户在到来时已经受过充分了解，也更准备好做出购买决策：他们转化为商机的频率是旧表单线索的两倍多，成交速度快了约五天。我们有意将这一体验设为可选加入，也就是说，客户在一开始就可以根据自己的偏好选择是与智能体对话还是与销售代表对话。



## **为什么旧的入站流程失效了**

在构建购买智能体之前，我们的入站流程相当直接。买家填写表单，线索被分配给一位业务开发代表，由其进行资格审核后转交给客户主管。当一个团队能够与每一位对产品感兴趣的人交谈时，这套流程仍然运作良好。

我们每月有数万条入站请求，而我们的入站 BDR 团队无法跟上。销售代表们整天都在回答文档里已经涵盖的问题，而我们也没有有效的方式触达队列中的所有客户。这不是我们想给客户的体验。

我们希望每一位客户在任何时间、任何语言下都能得到专业的回答，并且能够以他们偏好的方式购买，这往往意味着无需与销售代表交谈。我们希望销售代表把时间花在那些能够改变结果走向的对话上。

## **一个弥合差距的购买智能体**

我们把智能体部署在客户已经在提问的地方：我们的 [Contact Sales](https://claude.com/contact-sales) 和 [Pricing](https://claude.com/pricing#team-&-enterprise) 页面、产品内部，以及我们的邮件中。任何客户都可以在我们的 [Claude.ai](http://claude.ai/redirect/claudedotcom.v1.ee75aee5-99ec-4d92-b8cc-75bd37002391) 产品中找到这个购买智能体，它是一个简单的聊天体验，帮助客户了解哪个方案最适合他们。客户描述其团队的需求，智能体提出几个后续问题，然后回答有关定价、安全和数据的问题，再推荐一个方案和席位数。每次对话以三种方式之一结束：

-   **购买。** 买家直接进入结账。
-   **转交。** 对于更大或更复杂的交易，智能体将买家连同完整的对话详情转交给销售代表。
-   **快速解答。** 有时客户需要的仅此而已。

我们构建这个智能体时，让它遵循我们销售代表的相同工作方式，也就是理解客户想要解决什么问题、他们当前的 Claude 用量情况如何，以及我们怎样才能最好地帮助他们。



## **我们为什么使用 Claude Managed Agents？**

在底层，这个购买智能体很简单：一个提示词、少量工具，以及运行在 Claude Managed Agents 上的 Claude。由于平台负责托管、会话管理和工具编排，我们的工程师把时间花在与销售团队一起设计购买体验上，而不是构建基础设施。

我们最终选择 Managed Agents 的原因如下：

-   **快速上线。** 一位工程师仅用几周时间就在 Managed Agents 上构建了最初的购买智能体。
-   **技术与非技术贡献者都能参与。** 工程团队负责代码，但销售和内容负责人直接在 Console 中审阅和编辑系统提示词。变更会先进入我们的预发布智能体，这样任何人都可以在改动触达客户之前先试一试。
-   **专注于业务领域，而非执行框架。** Managed Agents 负责运行智能体循环、会话和托管。我们把时间花在提示词、工具和知识库上——这三样是销售所特有的。
-   **版本管理让迭代成本更低。** 对智能体的每一次变更都会保存为独立版本。在内部测试约一周时我们就已经迭代到 v7，发布后我们每周持续交付提示词变更。需要时，我们可以轻松地将新会话指回之前的版本。
-   **灵活支持更多用例。** 如今，客户在我们的网站上发现这个智能体。Managed Agents 支持定时运行，这为我们探索其他类型的客户互动提供了路径。



## **构建购买智能体的经验**

**给 Claude 一个目标，而不是规则。** 解释智能体的目标比一份详细的指令清单效果更好。例如，像「你的目标是理解客户需求、审核潜在客户资格，并推荐最佳方案」这样简单的一句话，比用流程图列出每一项资格要求更有效。

**少即是多。** 我们试验了不同长度、复杂度和结构的提示词，发现「少即是多」这一原则效果最好。如今的模型能够理解复杂、细微的目标，并从目标倒推。在实践中，这意味着不要挡着 Claude，而是给它成功所需的知识和上下文，比如按席位定价涵盖哪些内容，或者账单周期何时运行。

**让领域专家参与开发循环。** 在智能体编码加速开发周期的今天，这一点正变得越来越有价值。得益于使用 Managed Agents 和 Claude Code 节省的时间，我们的工程师能够花更多时间与销售团队一起塑造以客户为中心的体验。我们能够尽早且频繁地测试智能体，从而实现快速迭代。

**专注于对客户正确的事。** 智能体常常把小团队引导到我们的 Team 方案而不是 Enterprise，因为在某些情况下那对他们才是正确答案。我们认为这是一个特性。一个选对了方案而不是被向上销售的买家，更有可能留下来并获得更好的体验。

**把每一次智能体转交销售代表都当作反馈。** 每次智能体将买家转交给销售代表时，它都会解释原因。早期，这些原因大多是客户目前还无法通过我们的自助服务产品自行完成的事情。这些原因塑造了我们改进体验的方式，而需要人工协助成交的对话占比已经下降了约一半。

## **客户方面发生了什么变化**

这个智能体现在每天 24 小时进行数千次对话。客户可以即时得到问题解答，而不必等待预约通话或花好几天来回发邮件。我们的许多客户实际上更喜欢与智能体而不是真人交谈，因为它能在问题出现时给出快速、有依据的回答。我们的许多新的自助服务 Enterprise 客户在购买前都会与购买智能体交谈，我们发现，事先与智能体交谈过的客户更清楚自己买的是什么。

## **智能体如何改变了我们的销售组织**

智能体改变了我们销售代表度过每一天的方式。我们现在能够把团队的大部分时间和精力集中在客户购买旅程的更早阶段去教育他们，进行更多实时客户对话，并花时间在活动现场与人面对面交流。

最具影响力的变化是，我们的销售代表现在获得的线索信息更充分，线索转化为销售机会的频率高于我们旧的联系表单，而且成交速度快了约五天。销售代表在开始对话时就已经知道客户需要什么、他们被告知了什么，以及我们怎样才能最好地帮助他们。

例如，我们的一位内部销售代表 Ojas 过去要来回约 10 封邮件才能成交；现在大约只需 6 封。自购买智能体上线以来，他的赢单产出提升了 2.5 倍，因为这让他能够专注于那些受过充分了解、准备就绪、只差临门一脚的客户。

不久前，入站还是我们团队无法跟上的队列。现在，它是任何买家在任何时间都可以开启的对话，而我们的销售代表也能更高效地利用时间。购买智能体是我们迈向覆盖整个客户关系的智能体的第一步。
