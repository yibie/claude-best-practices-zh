# Anthropic 的网络安全团队如何用 Claude Code 构建威胁检测平台

在整个职业生涯中，Jackie Bow 一直设想有这样一些工具：它们能接入真正重要的上下文——不只是日志和告警，还有 Slack 对话、内部文档和机构知识，这些信息能告诉你某件事是真正的威胁还是只是噪音——而且不需要人工承担梳理数据的重负。

加入 Anthropic 后，她终于有机会把这些工具造出来——Claude 就是她的协作伙伴。Jackie 领导 Anthropic 的检测平台工程团队，专注于防御性网络安全：检测威胁、响应潜在入侵，而不是主动探测漏洞。这项工作包括监控系统中的可疑活动、对安全告警进行分诊，以及在异常演变为事件之前展开调查。

对于一家构建能力日益强大的 AI 模型的公司来说，这项工作是基础性的。[Anthropic 的负责任扩展政策](https://www.anthropic.com/news/anthropics-responsible-scaling-policy)将产品发布直接与安全承诺挂钩，这意味着 Bow 的团队要帮助判断公司可以安全地发布什么。

"我觉得现在是安全工程师的黄金时代，"担任 Anthropic 检测平台工程团队技术负责人的 Bow 说，"我终于能构建我一直想要拥有的工具了。"

## **问题：淹没在数据和告警中**

安全领域的领导者对这一幕再熟悉不过。

一条告警触发。分析师打开终端，开始熟悉的仪式：在五六个不同工具之间来回跳转，每个工具都有自己的查询语言和心智模型。他们必须同时精通多个平台，并在不同界面和查询语法之间不断切换上下文。

每一次调查都变成一场数据考古，把散落在互不相连的系统中的碎片拼凑起来。对大多数团队来说，简单的调查要耗费数小时，复杂的调查可能拖上好几天。

"一个人一天能看的告警数量是有限的，超过之后，他们深入分析的细致程度就会下降，"Jackie 解释道。

她的团队决定做点什么。他们问自己：什么在消耗我们的精力？什么让人感觉重复？什么阻碍了我们做有影响力的工作？

答案很清楚。告警分诊可能耗掉数小时，分析师才能判断威胁是否真实。跨互不相连系统的手动关联拖慢了一切。而在查询语言和界面之间不断切换上下文，产生的认知负担会在一天中不断累积。

随着公司成长，攻击面也在扩大，对安全团队的要求也随之增加。

"如果不借助 Claude 这样的东西来增强能力，我们无法扩展到满足 Anthropic 的需求，"Jackie 说。

## **解决方案：Claude 查找证据（CLUE）**

在几个月的时间里，Bow 的团队构建了 CLUE，一个重新构想安全团队如何调查威胁的检测与响应平台。CLUE 没有在技术栈中再增加一个仪表盘，而是提供一个由 Claude 驱动的自然语言界面，通过工具调用直接连接 Anthropic 的内部系统。

用 Claude Code 构建 CLUE，把传统软件开发周期大幅压缩，让他们能在处理日常工作之余构建这个系统。Bow 的团队一天之内就跑通了概念验证。设计文档、开发步骤和实现在一周内完成。

"我们构建的东西，很大一部分是我们与 Claude Code 对话的产物，"Jackie 回忆道，"它既是设计伙伴，也是协作者。"

改变她认知的那一刻，是她让 Claude Code 在 CLUE 界面上加一个按钮。她本以为又要经历 JavaScript 框架和 CSS 调试的老一套折磨。Claude Code 立刻实现了这个功能，而且做得比她本人更好。

"那一刻我意识到，我不再受自己技术水平的限制。我能想到什么，就能构建什么，"她说。

### **CLUE Triage**

当告警涌入时，CLUE Triage 会在人类分析师看到之前完成第一轮分诊。Claude 使用工具，从 Anthropic 各系统中为每条告警补充额外上下文，包括 Slack 消息、内部文档、代码仓库和数据仓库。它给出处置结论：误报、真实告警、恶意或预期行为。每条告警都会获得一个置信度评分，让分析师知道该把注意力放在哪里。

这个补充上下文的步骤解决了任何安全分析师都熟悉的问题：告警到达时只是孤立的信号。一次失败的登录尝试。一次异常的 API 调用。一次配置变更。没有上下文，这些事件只是噪音。有了上下文（用户是谁、他们在做什么、这是否符合其团队的模式），清晰的信号就会浮现。

"这些内部上下文正是缺失的那一块，它真正帮助告警在你的环境中获得语境，"Jackie 解释道。

### **CLUE Investigate**

借助 CLUE，安全分析师现在可以用自然语言查询所有安全关键日志。想知道"过去一天这个系统所有失败的登录有哪些？"直接问 CLUE，Claude 会执行必要的 SQL 查询。

"Claude 写精确查询的能力比人类强得多，"Jackie 说。这个工具运行一个智能体循环：一个编排器向子智能体发出命令，子智能体并行执行查询、收集发现，并将结果综合成连贯的调查摘要。过去需要数小时手动关联的工作，现在三到四分钟就能完成。

数字印证了这一点。在所有调查中，CLUE 平均每个会话执行 25 次工具调用和近 11 次查询——远超分析师手动执行的合理范围，而且精度更高。这些工具调用中的每一次，原本都需要打开单独的控制台或切换到不同界面。

然而真正的差异化在于内部上下文。CLUE 通过工具直接连接 Anthropic 的系统，让 Claude 能访问外部安全平台永远无法触及的机构知识。当告警触发时，Claude 可以查看 Slack，看团队是否讨论过计划内维护。它可以查询数据仓库以了解基线行为。它可以检查代码仓库以了解某个服务实际做什么。

### **数据治理审查**

团队用一个常见的数据治理场景展示了 CLUE 的能力：检查三名承包商在过去两个月是否访问过任何他们不应访问的文档。

据 Bow 说，这类调查通常至少需要半天手动工作，包括查询访问日志、交叉核对权限、审查文档分类。有了 CLUE，Claude 读取请求、制定计划，并生成冗长的查询来抽象技术复杂性。调查几分钟内结束，产出摘要和建议，并且对每一次执行的查询都完全透明。

## **衡量影响**

团队在构建 CLUE 时，不仅想了解它是否感觉更快，还想知道能否量化结果。

**更少的误报**：在使用 CLUE Triage 之前，大约每三条告警中就有一条是误报。这一比例已降至 7%，意味着分析师把时间花在真正重要的信号上。\*

**更广的覆盖**：也许比速度更重要的是团队现在能检查什么。在使用 CLUE 之前，置信度较低的信号因为根本没有时间而被搁置。现在，CLUE Triage 会对每条传入告警进行补充上下文处理，批处理还能处理成千上万原本只是仪表盘上噪音的信号。

**规模化节省时间**：基于 30 天的使用数据，CLUE 自动化了约 12,000 次查询和 27,000 次工具调用——这些工作若手动完成，估计需要 1,870 小时（234 人天）。与手动分诊相比，相当于节省了 5-10 倍时间。\*

**仍在学习如何衡量的**：准确率比速度更难量化。团队会审查 CLUE 的处置结论并跟踪分歧，但他们仍在构建反馈回路，以了解 Claude 多久能发现分析师会漏掉的东西——以及反过来。转录记录有所帮助：每次调查都可以审计 Claude 究竟检查了什么、如何得出结论。

## **前进方向：让 Claude 像 Claude 一样调查**

AI 研究中有一个概念叫"[苦涩的教训](http://www.incompleteideas.net/IncIdeas/BitterLesson.html)"——即把人类特有的推理方式编码进模型，其效果始终不如赋予模型通用能力、让它们自己寻找方法。Bow 和她的团队一直在思考这对检测与响应意味着什么。

"在 CLUE 开发的早期，团队争论过应该在多大程度上约束 Claude 的调查路径，"Bow 说，"SOAR 时代的本能说：构建实战手册、定义每一步、让流程确定化。但我们不断注意到一件事。当我们给 Claude 探索的自由——给它工具和一个目标，而不是固定的步骤序列——它常常走出我们不会规定的调查路径。有时这些路径揭示了我们会漏掉的上下文。"

关键在于给 Claude 设定边界（它能用哪些工具、能访问哪些数据），同时让策略保持开放。这一洞见塑造了 CLUE 的下一步方向。

**从被动到主动**：今天，CLUE 响应告警。事件触发，Claude 调查。但架构支持更宏大的目标：持续探索。与其等待检测规则触发，Claude 智能体可以主动搜寻可疑模式——不匹配团队已编写的任何规则的异常、单独看正常但整体看异常的行为。

**从自身学习**：团队存储每一次调查的转录记录。这个语料库正在成为 Claude 可以查询的知识库，用于发现过去调查如何展开的模式。随着时间推移，CLUE 发展出任何人类分析师都无法维持的组织记忆。

**拥抱非确定性**：传统安全工具把不一致当作缺陷。CLUE 把它当作特性。同一条告警在不同日子可能以不同方式调查，这没关系——有时第二条路径会发现第一条漏掉的东西。团队正在试验并行运行多种调查策略并比较结果。

"安全运营的苦涩教训？我们花了多年构建编码人类如何调查的系统。下一代工具应该赋予模型调查的能力，让它们找到比我们规定的更好的方法，"Bow 补充道。
