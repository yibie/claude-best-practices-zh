# Anthropic 的业务拓展团队如何用 Claude 大规模处理入站与出站业务

在我职业生涯早期做业务拓展时，客户经理会递给我一份列着数百个客户的名录，我得逐个调查每家公司、找到合适的联系人、挖出邮箱地址，再起草外联邮件。入站这边的工作流同样繁琐又耗时。

去年夏天加入 Anthropic 时，我接手了管理销售收件箱的职责。我每天要花大约 5 个小时手动回复潜在客户的入站咨询，经常要回答关于我们产品的相同或类似问题，这还不算管理我自己负责的客户名录。

现在，这些工作中的很大一部分已经在 [Claude Cowork](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork) 中配置成了 Skills（技能）和定时任务。个性化的客户邮件会以草稿形式准备好，我只需在发送前审阅和定制。我的出站工作则从一份详尽的研究开始，而这份研究我不必再花几个小时去整理。

结果是，我和队友们花在手动、重复性工作上的时间更少，花在真正重要的事情上的时间更多：帮助我们的客户。

下面介绍 Claude Cowork 如何提升 Anthropic 业务拓展职能的水平，让我们能把更多时间投入到战略性工作、理解客户问题，以及帮助客户了解 Claude 如何解决这些问题上。

## **自动化行政与重复性任务**

业务拓展代表（BDR）处在销售流程的起点，负责筛选入站需求并为业务构建出站管道。在 Anthropic，这些动作现在都先经过 Claude Cowork。

我们入站配置的基础是一份文档，我在其中收集了销售收件箱最常收到的问题，以及我们对这些问题的最佳回答。这份文档充当我们的销售知识库，Claude 在起草我们发出的任何回复之前都会先读取它。这份文档是 Claude 帮我创建的（我只是把它指向相关的信息来源），现在它会持续验证文档是否最新，标出可能已经过时的信息，由用户来确认。

建立在这份文档之上最重的工作流是一个每小时运行一次的收件箱技能：它扫描某位代表的收件箱，找出该代表需要回复的每个会话线索，并起草一封回复供代表阅读、编辑和发送。这个技能由一段精简的系统提示词、作为上下文的知识库，以及该代表的写作风格画像组成（我们每个人也会用一个声音技能来创建自己的风格画像，该技能会通读我们写过的文档、消息和邮件）。



收件箱技能基于一段精简的系统提示词、作为产品事实来源的团队销售知识库，以及为每位代表定制的风格画像运行。



收件箱技能扫描某位代表的收件箱，并留下起草好的回复供审阅。本预览中的所有信息均已为发布而匿名化处理。

我还会借助两个较轻量的技能来处理我的行政工作负担。每个 BDR 都体会过客户爽约和潜在客户失联的痛苦。为此，我构建了一个技能来监视 Gmail 和 Google Calendar，在出现这种情况时通知我，以便我快速跟进。

另一个技能使用我们的 CRM 连接器扫描所有新线索，并起草个性化的首次触达。它按计划在一天中多次运行，确保我们不会让线索干等。

我们还有一个技能通过读取我们关于商机阶段的内部指引，并将其与 Gmail 和 Gong 中实际发生的情况进行比对，来让 Salesforce 保持最新。如果我们已经与客户会面并进入了价格问题阶段，商机大概就应该推进一个阶段。Claude 会提出每一项 Salesforce 更新并附上依据，然后等待批准。当我编辑或拒绝某项提议时，它会记录原因，以免重蹈覆辙。



管道扫描技能会提出 Salesforce 更新建议，供代表批准。此处展示的是演示数据，所有信息均已为发布而匿名化处理。

## **优化出站与营收工作**

平均而言，我随时都在跟进上百个客户。我能覆盖所有这些客户，靠的是一个作为定时任务在夜间运行的技能。它在我负责的整个名录中寻找潜在客户，观察每个客户的当前状态；例如，我们在与谁联系、他们目前如何使用 Claude，以及哪些信号是相关的。为此，Claude 会连接 Salesforce、Apollo 和 Common Room 等销售工具、Gong 以及我们的数据仓库，执行深度研究，并对照我们团队精心整理的出站指引和 ICP 标准进行验证。

这些组成部分为技能补充了上下文，帮助 Claude 更像 Anthropic 的 BDR 那样工作。早上，我打开 Claude Cowork，就能看到每个客户的简报、评分和出站打法。

随着每位 BDR 都能对 Claude 的结果提供反馈，而这些反馈又会回流到技能中，这个工作流会随着时间推移变得越来越有用。该技能会维护一个小型记忆文件和台账，避免重复或冗余的工作。

我们在后续对话中使用这些研究，因此我们的外联是有针对性的；与客户交谈时，我们了解他们的业务，也足够贴近他们的问题，能够进行更深入的战略讨论。

探索电话是我们出站动作中另一个正在用 Claude 改进的环节。我们用一个技能对照我们的探索电话实战手册（playbook）评估 Gong 转录文本，为每次通话生成记分卡，并基于对话给出具体反馈。反馈包括做得最好的三件事、最需要改进的三个领域、按我们的标准明确给出的通过或不通过评分，以及接下来最值得练习的一件事。



通话教练技能为我们的探索电话提供记分卡，并附上具体的改进建议。此处展示的是演示数据，所有信息均已为发布而匿名化处理。

## **简化一次性请求**

BDR 团队经常以临时方式收到请求，而 Claude 让我们能够以更具战略性的方式与客户经理（AE）协作。如果某位 AE 想了解某个重要客户的使用趋势，我们只需一个提示词就能提供一份清晰、描述详尽的仪表盘，突出相关趋势。



为目标客户生成的支出分析报告。

与 Claude 一起做数据分析和报告，在出站工作中同样派得上用场。我最喜欢的工作流之一是运行一个未发现用量提示词。它会考察某位 AE 的整个名录，找出那些我们尚未建立销售商机、但在客户层面存在用量信号的账户。这往往是一个很好的信号，提示我们开始接触客户，并与客户一起优化他们对 Claude 的使用和体验。



对某位 AE 名录进行以产品为中心的扫描，返回所有已在使用产品但尚无匹配商机的账户。此处展示的是演示数据，所有信息均已为发布而匿名化或修改。

我们还会用 Claude 做活动外联。我的一位 AE 最近提到我们即将举办一场 [Claude Code for Data Engineering](https://claude.com/resources/webinars/claude-code-for-data-engineering) 网络研讨会，问我能否在他负责的名录中找出有兴趣参加的客户。我没有为此专门做技能，但对这类请求，一个提示词就够了。Claude 检查了整个名录的用量数据和 CRM 历史，按我们的 ICP 为每个客户评分，并标出了最匹配、值得邀请联系人的客户。



在被要求为网络研讨会邀请找到合适的客户时，Claude 扫描名录，并按团队的理想客户画像为每个客户评分。

这些技能、定时任务以及我们精心整理的上下文加在一起，把 Claude 变成了一个常驻的业务拓展伙伴。

## **给业务拓展团队上手 Claude Cowork 的建议**

以下是给业务拓展团队上手 Claude Cowork 的一些建议：

-   **先建知识库，再建工作流。** 把团队反复回答的问题和你们的最佳回答收集到一份对外文档中。你不必手写：把 Claude 指向相关的产品文档和团队频道，让它构建第一版。
-   **给 Claude 提供你们团队工作方式的示例。** Claude 会基于你提供的上下文起草内容。对于出站工作，这可以包括奏效的消息示例和你的理想客户画像。每位代表还可以让 Claude 学习自己的写作风格，这样草稿到手时就像发件人本人写的。
-   **每次发送都要有人把关。** Claude 可以生成草稿，但我们仍然要阅读、编辑并发送。
-   **在团队中共享技能。** 我们团队把最常用的技能放在一个共享插件中，一旦确认代表们在日常工作中持续使用某个技能，就把它提升到那里。
-   **让技能足够通用，以适应整个团队的工作方式。** 不同代表的细分、名录和工作流各不相同，因此我们让共享技能保持足够通用以便适配，而不是只针对某个人的日常习惯。
-   **把反馈写回技能中。** 当你驳回一个钩子（hooks）或修正一份草稿时，让 Claude 在技能中记录原因，这样它就不会再犯同样的错误。

我最好的建议？直接开始尝试。你给它的上下文和工具越多，你能完成的事情就越多。
