# 三家 YC 初创公司如何用 Claude Code 打造自己的公司
[Y Combinator](https://www.ycombinator.com/) 是一家初创公司加速器，自 2005 年以来已孵化超过 5,000 家公司，总估值超过 8,000 亿美元，其中包括 Airbnb、Stripe 和 DoorDash 等家喻户晓的名字。

如今，像 [Claude Code](https://www.claude.com/product/claude-code) 这样的智能体式编程工具正在从根本上改变 YC 初创公司构建和扩展产品的方式。创始人现在可以直接从终端交付产品，将开发周期从数周压缩到数小时，甚至让非技术背景的创始人从第一天起就能与成熟玩家竞争。

我们采访了三家 YC 初创公司，他们展示了这种转变的实际发生：

-   [HumanLayer](https://www.humanlayer.dev/)（F24）用 Claude Code 构建了整个平台，并开创了上下文工程实践
-   [Ambral](https://www.ambral.com/)（W25）正在用 Claude Code 和 Claude Agent SDK 构建的精密子智能体驱动工作流，扩展 AI 驱动的客户账户管理
-   [Vulcan Technologies](https://vulcan-tech.com/)（S25）正在用 Claude Code 应对政府和行业的监管复杂性

让我们深入了解。

## **HumanLayer：从 SQL 智能体到规模化 AI 优先的工程团队**

Dexter Horthy 当时正在构建自主 AI 智能体来管理 SQL 数据仓库，他注意到智能体式应用落地面临一个根本性（但可以理解）的挑战：公司不愿意让 AI 应用在无人监督的情况下访问敏感操作，比如删除数据库表。

### **一切始于产品转型**

这一认识成为了 HumanLayer 的核心洞察：通常，任何软件中最有用的功能同时也是风险最高的，尤其是对于非确定性的 LLM 驱动系统而言。

"我们的 MVP 是一个智能体，它可以在 Slack 中与人类协调，并执行基本的清理工作，比如删除任何 90 多天未被查询过的表，"Horthy 解释道。"我们不放心让 AI 应用在无人监督的情况下运行原始 SQL，所以我们接入了一些基本的人工审批步骤。"

2024 年 8 月，Horthy 构建了一个 MVP，向旧金山各地的不同初创公司做了演示，并获得了第一批付费客户。

这一进展让 HumanLayer 进入了 YC F24 批次，团队全力投入提供一个 API 和 SDK，让 AI 智能体可以通过 Slack、电子邮件、短信和其他渠道联系人类获取反馈、输入和审批。

在 2025 年第一季度，HumanLayer 团队进行了广泛的客户发现，与数十个构建 AI 智能体的工程团队交谈，并意识到智能体开发循环中存在一个他们之前没有考虑到的缺口。

"每个团队都自己搭建了智能体架构，"Horthy 解释道。"我们意识到，我们不能只是构建一个更好的 API——我们需要帮助建立让生态系统成熟的模式和原则。"

这促使 Horthy 将他们的经验记录在"[12-Factor Agents：可靠 LLM 应用的模式](https://github.com/humanlayer/12-factor-agents)"中。该指南于 2025 年 4 月发布后迅速传播，综合了他们构建生产级智能体系统的经验，并强调了上下文工程这一新兴学科的最佳实践。

### **用 Claude Code 构建一切**

有了这些经验，HumanLayer 团队开始探索替代产品想法和转型方向。

当 Anthropic 推出 Claude Code 时，Horthy 和他的团队已经是 Claude 模型用于编程的坚定支持者。他们立即开始用它来构建这些实验。

"我们就用 Claude Code 写了一切，"Horthy 说。"当 Claude Agent SDK 随 Opus 4 和 Sonnet 4 发布，支持无头智能体执行时，我们知道这将是一件大事。"

在内部打磨 Claude Code 工作流数月后，Horthy 开始与关系密切的创始人朋友分享这些工作流。

"让我意识到我们需要全力投入的时刻，是与 BoundaryML（YC W23）的 Vaibhav 进行的一整天结对编程会话，"Horthy 回忆道。"Vaibhav 起初持怀疑态度，但当我们用 7 个小时交付了通常需要 1-2 周的工作后，他被说服了。我意识到这个工作流可以适用于其他团队和其他代码库。"

### **构建 CodeLayer：规模化 AI 优先的工程**

如今，HumanLayer 的产品 CodeLayer 帮助团队使用 worktree 和远程云工作器并行运行多个 Claude 智能体会话。他们发现了一个关键模式：一旦工程师掌握了 Claude Code，其生产力提升如此之大，真正的挑战变成了组织层面的——如何在整个团队中推广这些工作流。

"一旦你的团队中有多个人在交付 AI 编写的代码，你就会面临一种完全不同类型的问题，"Horthy 解释道。"这是一个沟通、协作、工具和管理的问题。你必须重新设计团队构建软件的一切方式。"

自 2025 年第四季度初以来，HumanLayer 已在各种规模的工程团队中完成了多个大型试点，部署这些工具和工作流，全部用 Claude Code 构建。

## **Ambral：用子智能体构建生产系统**

Jack Stettner 和 Sam Brickman 创立 Ambral 是为了解决每个 B2B 初创公司创始人和 CRO 都熟悉的问题：随着公司规模扩大，驱动早期增长的创始人级别的客户亲密关系变得无法维持。

### **用 Claude Agent SDK 变革客户账户管理**

无论是在经历超高速增长的早期公司，还是在成熟的企业公司，客户经理通常同时管理 50 到 100 个账户。"你无法用一个人 1/50 的注意力提供有效的客户账户管理体验，"Stettner 解释道。曾经装在创始人脑子里的客户上下文，现在分散在系统、日志、Slack 消息、会议记录和产品使用数据中。

Ambral 将客户活动和互动的信号综合成每个账户的 AI 驱动模型。系统精准定位谁需要关注以及为什么，自主推动或推荐扩展，同时捕捉早期的不满迹象以防止流失。

"我们试图提供每个客户都拥有一对一客户经理的体验，"Stettner 说。

作为这家年轻初创公司的 CTO 和唯一工程师，Stettner 严重依赖 Claude Code 进行开发，并用 Claude 的 Agent SDK 驱动产品本身。技术架构反映了对如何从不同 Claude 模型中提取最大价值的深刻理解。

### **委托式工作流：Opus 负责思考，Sonnet 负责构建，子智能体贯穿始终**

Stettner 采用了一套精确的工作流，利用不同 Claude 模型的优势并结合子智能体：

"我用 Opus 4.1 做研究和规划。Sonnet 4.5 在实现我在 Markdown 中创建的计划方面绝对是杀手级的，"Stettner 解释道。

他的开发过程遵循三个独立阶段：

1.  **研究阶段（Opus 4.1）**：对功能实现所需的任何背景进行深度研究。"我认为最重要的是在规划之前做研究，"Stettner 强调。"让 Claude 为你做研究，并创建一份大型的、详细的研究文档。"他使用一系列子智能体并行研究代码库的多个区域。
2.  **规划阶段（Opus 4.1）**：制定一个包含独立阶段的计划，说明如何实现该功能。"我会让 Opus 创建一个包含阶段的计划，即如何实际实现它的独立阶段，然后我会修改这个计划。也许我会和 Opus 讨论某些细节的问题，或者我会手动更新这个 markdown 文件。"
3.  **实现阶段（Sonnet 4.5）**：系统地执行计划的每个阶段。"然后我会用 Sonnet 4.5 去实现每个阶段。"

这种方法胜过了 Stettner 尝试过的其他工作流，并受到了 Horthy 在 HumanLayer 所做工作的一些影响："我试过每一种编程工具，也基本上试验了每一种模型。我只是认为 Anthropic 的模型目前在工具调用方面是最好的，而这会转化为代码质量。"

### **构建强大的研究引擎**

产品本身也反映了这种多智能体方法。Stettner 使用 Claude Agent SDK 构建了 Ambral 的核心研究引擎，为每种数据类型配备了专门的子智能体。

"我花了很多时间使用 Claude Agent SDK 来构建一个非常强大的研究引擎，可以在所有这些数据上运行，"Stettner 解释道。"它基于 Claude 子智能体，对于每种数据类型，我们都有一个专门的子智能体，它是理解该数据的专家。"

无论用户是与系统对话，还是 Ambral 为客户构建自动化，一切都由 [Claude Agent SDK](https://docs.claude.com/en/api/agent-sdk/overview) 和一系列子智能体支撑，这些子智能体在使用数据、Slack 消息、会议记录和产品互动中进行检索和推理。

架构灵感直接来自 Stettner 的开发体验："我认为 Claude Code 子智能体表现得有多好、帮助我进行开发的程度，正是启发我想要把这些相同的子智能体用于产品本身的研究引擎的原因。"

## **Vulcan Technologies：赋能非技术创始人发布产品**

对于 Vulcan 的 CEO 兼联合创始人 Tanner Jones 来说，Claude Code 的影响远远超出了生产力——它构成了公司构建的民主化。创立初创公司时，Vulcan 团队相信一定有一个产品可以让政府更好地为公民服务。如果没有 Claude Code，这个愿景将无法实现，因为两位创始人都不具备工程背景。

### **在没有专职工程师的情况下交付产品**

Vulcan 解决的是一个积累了数个世纪的问题：[监管法规](https://en.wikipedia.org/wiki/Code_of_Federal_Regulations)的复杂性。弗吉尼亚州的下议院（House of Burgesses）是世界上延续时间最长的民主机构，就是这一挑战的典型例子。400 多年的监管积累创造了美国最细微和复杂的法规之一。

当 Aleksander Mekhanik 和 Tanner Jones 于 2025 年 4 月共同创立 Vulcan 时，两人都没有传统的工程背景。Mekhanik 在大学学习机器学习和数学，而 Jones 上一次编程经历是高中时的一门 AP JavaScript 课程，当时他们用纸笔写代码。然而，这对搭档在 5 月 1 日之前为弗吉尼亚州州长办公室构建了第一个产品的原型——并击败了成熟的咨询公司赢得了合同。

"整个原型都是用 Claude 做的，"Jones 解释道。"这是在 Claude Code 之前。当时就是把脚本复制粘贴到 Web 应用中，替换方法。"构建原型后，他们聘请了 CTO Christopher Minge，他曾在 Google 从事 Gemini 和 Waymo 的工作。然后，当 Claude Code 在 6 月发布时，三人的速度再次倍增。

Vulcan 的 AI 驱动监管分析帮助弗吉尼亚州新房平均价格降低了 24,000 美元，通过识别冗余和重复的监管要求，每年为弗吉尼亚人节省超过 10 亿美元。弗吉尼亚州州长非常喜欢 Vulcan 的工作，以至于他[签署了第 51 号行政命令](https://www.govtech.com/artificial-intelligence/virginia-to-use-agentic-ai-to-power-review-of-regulations)，要求所有州机构使用"智能体式 AI 监管审查"。

### **公司构建的民主化**

对于 Jones 来说，Claude Code 的影响超越了生产力指标。

"如果你理解语言并且理解批判性思维，你就能很好地使用 Claude Code，"他说。"我实际上认为，对于学习人文学科的人可能存在一些边际优势，因为我们与 AI 交流的媒介是语言。如果你有很强的语言驾驭能力，并且擅长构建组织良好的有序列表、嵌套要点和深思熟虑的流程，你的提示词可能会执行得更好。"

Jones 称赞 Claude Code 是 Vulcan 成功的主要组成部分："在四个月内，三位创始人中只有一位是真正技术背景的，我们获得了州和联邦政府合同，并从一些顶级风投那里筹集了 1,100 万美元的种子轮。没有 Anthropic 令人难以置信的工具，这一切都不可能实现。"

Vulcan 的 CTO Christopher Minge 拥有"真正技术"的训练背景，他也经历了对工程思维方式的转变。

"感觉有点像我在 Google 有一个同事，我把所有的想法和任务都交给他，他们经常犯错，但我的角色是委托给多个 Claude Code 实例，并擅长检查常见错误和有效沟通想法，"Minge 解释道。

## **来自 YC 创始人的最佳实践**

这三家初创公司已经开发出经过实战检验的方法来最大化 Claude Code 的影响，包括：

### **1. 将研究、规划和实现分为独立的会话**

"不要让 Claude 在做研究的同时试图规划，同时试图实现，"Stettner 建议。"使用独立的提示词，并将它们变成独立的步骤。"

这种模式防止了上下文污染，并允许每个阶段专注于其核心目标。为每个主要阶段启动一个新的 Claude Code 会话，只传递提炼后的结论，而不是拖拽整个上下文历史。

### **2. 有意识地管理上下文**

Stettner 对其他创始人的建议集中在有意识的上下文管理上：

"上下文至关重要。当我看到意外或低质量的输出时，通常是因为我在某个提示词中存在矛盾，"他解释道。"在你选择将什么信息放入系统提示词或何时开始新对话时，要非常刻意，因为你不想污染你的上下文。如果你的提示词中有任何矛盾，你就会收到质量更低的输出。"

### **3. 监控并中断思维链**

"试着审视思维链，观察它在做什么，"Jones 建议。"让你的手指放在扳机上，随时准备退出并中断任何不良行为。"

这在运行多个实例时尤为重要。在早期——前几次工具调用内——就发现错误方向，比让 Claude Code 完成整个错误方法节省的时间要多得多。

## **新型构建者的优势**

这三家初创公司展示了使用 Claude Code 等工具构建公司方式的根本性转变。HumanLayer 在转型和扩展的同时，编纂了现在被整个 YC 生态系统使用的上下文工程实践。Ambral 用精简的创始团队大规模解决客户成功问题。Vulcan 以非工程师身份赢得了政府合同。

构建软件的传统壁垒——技术专长、团队规模、开发时间——正在让位于新的竞争优势：清晰的思考、结构化的问题分解，以及与 AI 有效协作的能力。
