# CodeRabbit 如何用 Claude 构建智能体编排系统
_在我们的系列文章_ **_初创公司如何用 Claude 构建产品_** _中，我们重点介绍初创公司如何借助 AI 变革各自所在的行业。本文分享 CodeRabbit 如何构建一个智能体编排层，在 AI 生成代码之前先进行规划。_

| 快速概览 |
| --- |
| 名称 | CodeRabbit |
| 成立时间 | 2023 |
| 创始人 | Harjot Gill，CEO |
| 技术栈 | Claude Platform、Claude Code |
| 规模 | 每周为 15,000+ 客户审查 200 万个 PR |

AI 编码工具已经大幅缩短了从想法到可运行原型之间的时间。AI 代码审查平台 CodeRabbit 注意到，在吞吐量攀升的同时，另一种趋势也在抬头：代码能够编译、通过测试，但并没有实现团队真正想构建的东西。

CodeRabbit 的 AI 副总裁 David Loker 将原因定位在模型的上游。经验丰富的开发者常常假设编码智能体理解与自己相同的上下文，因此不会写下那些对自己来说显而易见的需求。编码智能体随后便用它认为合理的任何内容来填补这些空白。

为了弥合这一差距，CodeRabbit 使用 Claude 设计并构建了一个智能体编排系统，在生成任何代码之前先运行一个结构化的规划阶段。团队的工作假设是：规划质量决定输出质量，而代码生成越便宜，走错方向的代价就越高。

## **解决 AI 编码中的内部知识鸿沟**

当 CodeRabbit 团队研究其客户群中由 AI 生成的拉取请求（PR）时，最常见的失败模式是代码能够编译、通过测试，却仍然没有解决它本应解决的问题。

"随着我们作为开发者积累经验，我们会把知识内化，"Loker 说。"所有这些都在我们脑子里，我们假设其他开发者也懂。但随后我们又对 AI 系统做了同样的假设，认为它也隐式地理解。我们甚至没有意识到自己正在做这些假设。"

模糊的提示词迫使底层系统用它认为合理的任何内容来填补空白。这种猜测往往与开发者心中的想法相去甚远。

Loker 举了一个亲身经历的例子。在一个副业项目中构建记忆系统时，他与编码智能体反复迭代了数小时，直到一切都能运行。当他问智能体如何使用它时，说明里让他传入一个用户 token。但系统里根本没有登录页面。他指定了系统需要用户，却从未说明用户需要一种登录方式。智能体填补了这个空白，数小时的工作最终落在一个缺少前门的产物上。

"最终发生的情况是，你在它之上构建了更多东西，然后很久之后才发现有问题，"Loker 说。"在 AI 工作流中，迟到的验证可能非常昂贵。"

## **在 AI 编码方案之前运行的编排层**

CodeRabbit 的应对方式是在代码生成之前插入一个规划系统。它协调多个 Claude 模型来分析需求、暴露假设，然后产出一份结构化的执行计划，明确应该构建什么以及需要满足哪些约束。

"这个规划系统并不是要取代 Claude Code 的计划模式，"Loker 说。"它是在 Claude Code 之前进行的更高层级编排，把它指向一个非常狭窄且正确的方向，让所有需要明确的内容都变得明确，并且让我们清楚意识到正在做出的所有假设。"

输出是一份协作式的产品需求文档（PRD）：一份在完整上下文下创建、由团队各利益相关方验证、并在实施开始前经过审查的计划。Claude Code 接手这份计划，并据此生成细粒度的实施计划。该计划成为一份共享产物，记录了决定了什么以及为什么，这不仅帮助团队避免返工、在事后验证输出是否符合最初意图，还能帮助新工程师入职（onboarding）。

## **在 Claude 模型系列之间进行路由**

CodeRabbit 将每个模型层级与任务复杂度相匹配，以优化成本和延迟。Opus 负责驱动编排循环，以及理解问题、设定整体方向等更高层的战略性工作。Sonnet 接手其输出，将其编排为结构化的规划步骤。Haiku 处理范围狭窄的操作，例如上下文蒸馏和有针对性的工具调用，这类问题足够具体，较小的模型就能很好地回答。

"如果 Haiku 在某项任务上表现得和 Sonnet 一样好，我们就用 Haiku，"Loker 说。"如果评估（eval）执行框架（harness）告诉我们，给 Opus 更多空间能提升计划质量，我们就给它更多空间。我们不靠猜。"

## **为计划质量构建评估执行框架**

CodeRabbit 有一套成熟的代码审查评估系统，但在评估规划输出方面则是一片空白。构建这套基础设施本身就成了一个项目。

该系统从手工调优的示例和人工检查开始。团队开发了一个 LLM 评判器库，对计划质量的特定维度进行评分。由于计划最终会产出代码，团队还可以衡量生成的代码是否可用、是否包含额外范围，以及达到目标消耗了多少 token。对同一任务分别在有无规划步骤的情况下运行，让他们得以隔离出规划本身的价值。

"我们当时并没有意识到计划的合适详细程度应该是多少，"Loker 说。过于细粒度的计划在代码库一变动的瞬间就会过时。过于高层的计划则给智能体留下了填补假设的空间，而这正是规划层本要解决的原始问题。找到可行的抽象层级需要反复迭代，而评估执行框架让这成为可能。

## **在写下任何代码之前捕获错误**

在 AI 原生的编码工作流中，许多过去在代码审查阶段才浮现的决策，现在提前在规划层做出。在代码生成开始之前构建一份团队可以审查并对齐的计划，能够及早发现错误。

"我们用 Claude 生态构建的，是一个团队级的规划系统，"Loker 说。"计划本身成为质量关卡。如果我们能确保计划的质量在前期就非常好，下游效应会非常显著。最终你会得到好得多的代码。"
