# 守护前沿：JetBrains 如何评估与部署 Claude Fable 5
JetBrains 打造全球开发者使用的工具，从 IntelliJ IDEA、PyCharm 到 Kotlin 编程语言，服务超过 1250 万活跃用户以及《财富》世界 100 强中的 88 家企业。JetBrains 智能体系统 CTO Vladislav Tankov 与 Anthropic 交流了他的团队如何评估新模型、如何决定何时使用 Claude Fable 5，以及在与前沿模型合作时如何看待数据留存与护栏。

## 对 JetBrains 而言，前沿 AI 在 2026 年发生了哪些变化？

我在 JetBrains 工作了 10 年，我们是最早一批 LLM 提供商的客户。过去一年里，我们的客户和公司内部原本对 AI 持怀疑态度的人，转变为认识到 AI 已成为常态。这是技术行业一次重大而根本性的变化。公司里每一个原本怀疑的人，态度都变了。

## 你们如何评估新模型，并决定何时使用它们？

我们是一家做编程的公司，因此有一套庞大的评估（eval）流水线：在私有代码库（包括我们的 monorepo）上运行大型评估集。我们会仔细考察一个模型在真实工作中是否配得上它的基准测试分数——有些模型针对公开基准测试做了调优，得分很高，但在实际任务上却表现不佳。有了私有代码库，这一点就容易核查得多。我们还维护着最佳质量、最佳单任务成本、最快模型这几张排行榜。虽然 Claude Fable 5 的每 token 价格更高，但在某些情况下它的单任务成本更低，尤其是对于更复杂、长时程的工作。

## 与之前的模型相比，Claude Fable 5 在你们的评估中表现如何？

Claude Fable 5 比之前的模型既更准确也更高效。它在我们的测试套件中取得了最好的 Python 通过率，为 44.3%，而 Opus 4.8 为 28.2%，提升了 16.1 个百分点。在直接对比中，Claude Fable 5 解决了 18 个 Opus 4.8 未能解决的 Python 任务，只丢了 2 个。它的答案也更可信：当它生成的代码运行时，通过我们测试的频率远高于两个 Opus 模型。这一点很重要，因为能运行但产出错误答案的代码，是发现代价最高的一类失败。

效率方面的表现同样有意思。Claude Fable 5 达到解决方案所需的步骤比 Opus 4.8 少约 22%，因此它能以更少的试错得到可运行的代码。它还把精力用在了正确的地方。在 Java 任务上，Opus 4.8 反复尝试引入外部资源，而这些资源在我们的环境中几乎从不起作用，而 Claude Fable 5 完全跳过了这一步，直接处理眼前的代码。总体而言，它展现出更好的工程习惯。

## 你们什么时候会选用 Claude Fable 5 而不是其他模型？

Opus 被视为一匹干活的驮马：你可以非常确信它会把活干完。当你确实需要良好的推理能力、几乎像需要一个伙伴一样、而你自己也不确定该怎么做时，就会去找 Claude Fable 5。例如，我们的一位技术负责人决定实现一个富文本编辑器组件，这个组件我们过去几年尝试过几次，而 Claude Fable 5 几乎一次就搞定了。

Claude Fable 5 另一个常见用例是长时程的智能体式编程实验。我们给运行 Claude Fable 5 的智能体提供规格说明（以文本和图片的形式），让它实现复杂的类 IDE 应用。有意思的是，规格说明也可以由智能体基于现有应用生成。把这两个部分结合起来，我们就能在近乎黑盒的环境中，把应用从一个运行时、框架或语言重写到另一个。

## 面对当今的前沿模型，你们如何看待安全与数据留存？

我们不是一家试图自己打造最安全模型的公司。我们期望 Anthropic 一侧所做的红队测试及其他工作足以让人相信模型是安全的。然后我们采取系统化的部署方式，确保安全：围绕模型和智能体执行框架（harness）构建基础设施与安全网，而不是去调整模型本身。

安全也是 Claude Fable 5 最大的用例之一。我们对自家产品运行白盒测试以发现漏洞，而我们的安全团队正在为这样一个事实做准备：不仅我们在运行该模型——公司外部的人也会运行 Claude Fable 5 或同级别模型，来探测我们所有产品的漏洞。由于我们服务受监管行业的大型企业，做好准备对我们很重要。Claude Fable 5 是在支持我们的工作，而不是阻碍。

所以这是一种微妙的平衡：你这一侧的分类器越不激进，别人在我们产品中发现的漏洞就越多——包括那些此前无人知晓的漏洞。

这也不是秘密：我们更希望零数据留存（ZDR）。但我看不到还有其他办法能让你理解当时提出了什么请求、分类器又可能在哪里判断有误。只要审查仅用于调查被标记出的最严重案例，我就可以接受。我认为，为了获得让我的团队发挥最佳水平的前沿智能，这是一个公平的取舍。

## JetBrains 的 AI 路线图下一步是什么？

我们预计 LLM 提供商构建的底层模型会持续变得更强。现在重要的是某种软件开发驾驶舱：一个智能体与人协作的空间，人们可以在其中管理开发流程。

对 JetBrains 来说，这是一次巨大的转型。我们看到了一个机会：围绕驱动这个驾驶舱的智能体式软件开发生命周期，构建下一代产品。开发者将借助智能体交付更多、更好的代码，非技术角色将在软件创造中发挥更大作用，组织也将获得所需的治理与清晰的投资回报。
