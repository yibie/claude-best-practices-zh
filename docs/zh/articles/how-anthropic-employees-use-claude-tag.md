# Anthropic 员工如何使用 Claude Tag
[Claude Tag](https://www.anthropic.com/news/introducing-claude-tag) 将 Claude 带入 Slack 等聊天工具。你可以在话题串中像 @ 同事一样 @Claude，它会接续对话上下文、完成任务，并在话题串中回复答案或结果。它还能[跟进对话](https://claude.com/resources/articles/claude-tag-now-reads-even-more-of-the-room)，并借助可用的上下文、记忆以及被赋予的常设指令，自行判断何时参与聊天。过去几个月里，Anthropic 的各团队一直在使用 Claude Tag 在共享频道中[自助进行数据分析](https://claude.com/resources/articles/self-service-data-analytics-in-slack-how-anthropic-deploys-claude-tag-for-ad-hoc-questions)、处理支持工单，或帮助查找棘手缺陷的[根本原因](https://www.anthropic.com/news/introducing-claude-tag)。

我们整理了十多个[Claude Tag 用例示例](https://claude.com/docs/claude-tag/users/use-cases)，灵感来自我们在 Anthropic 的工作，并附有具体的提示词和设置说明。在本文中，我们重点介绍 Anthropic 员工使用 Claude Tag 提升工作流和流程效率的三种方式，并附上他们使用的提示词，供你借用或调整，以最贴合你的工作。

## 将 Slack 话题串变成一份精修文档

在最近一次功能发布期间，一位销售代表需要一份非技术性物料，向客户和潜在客户说明该功能如何运作；产品营销团队的 Hema Thanki 在 45 分钟内，把随后产生的 Slack 话题串变成了一份可供评审的文档。

那个 Slack 话题串有 15 条以上消息，多人参与提出建议或补充需求，围绕实际需要什么、现有技术材料是否足够，还带有一丝紧张气氛。Hema 没有先去澄清含糊之处，而是在话题串中 @ 了 Claude：

‍`@Claude，通读这个 Slack 话题串，整理出 [提出需求的人] 所要的一页纸文档。`

Claude 在大约两分钟内生成了一份两页的草稿，涵盖该功能的通俗说明、其商业价值、实施涉及的内容，以及一个包含更详细信息的附录。

接下来，Hema 让 Claude 核实其回答：

‍`@Claude，这份文档里的所有内容都属实且正确吗？`

Claude 将文档中的说法分为两类：一类是已对照公开文档核实过的，另一类是它自己的表述，后者被标记出来，需由产品负责人签字确认。Hema 提供了两份包含相关信息的官方资料，Claude 据此重写了其中一节，使其与这些资料中已批准的措辞一致。



对 Claude 的后续指令也在 Slack 中进行。此图片为示意用例而生成，不包含真实信息。

此时，Hema 注意到被截断的话题串使表述出现了偏差，于是她粘贴了更完整的上下文。她与 Claude 来回迭代，总共出了四个版本。在首次提出需求约 45 分钟后，她把文档分享给该功能的产品负责人评审。Hema 没有花数小时研究和起草文档，而是把时间用在质疑准确性、提供来源、决定纳入哪些信息上——这些都是需要人类判断的任务，也让这份客户物料更加扎实。

除了从 Slack 话题串生成简报，Hema 在日常工作中也使用 Claude Tag。她与 Claude 保持一个私有的 Slack 频道，在其中不同的话题串里提出请求，像 @ 同事一样 @Claude。在该频道中，Claude 会读取她粘贴或附上的任何内容，搜索 Slack 工作区和公开文档，并在后台工作，发布一份进度清单并随进展更新。Claude 的访问权限被刻意限定：它只能使用[已被授予访问权限](https://claude.com/resources/articles/agent-identity-access-model)的频道和文档，当它无权访问这些资源时会告知她。

## 汇总并跟进散落在各个 Slack 频道中的需求

新功能发布时，销售代表通常会持续跟踪，并通知他们所支持、曾提出该功能需求的客户。这些需求通过 Slack 或产品反馈中心传达，可能散落在数月之久的历史记录中。产品战略与运营团队的 Steph Soderborg 能够汇总与一个即将发布功能相关的所有需求，并直接通知每一位代表客户提出需求的销售代表，整个过程约 26 分钟。

首先，Steph 向 Claude 发送了搜索目标、一句话的匹配定义，以及她想要的输出示例——一份来自此前发布活动的七条清单：

‍`@Claude 我们即将 GA [一个新功能]。你能搜索 Slack……找出所有为其客户提出过此功能需求的人……包括他们的 Slack 用户名和团队、提出需求的客户账号，并附上 Slack 中该需求的链接。`

‍

Claude 在多个频道及整个工作区中运行了约 20 种搜索变体。产品反馈中心阻止了它的直接访问，因此它改为通过 Slack 交叉引用找出反馈中心里的条目，并合并了另一个内部助手已发布的第一版清单，对两者去重。汇总清单约 26 分钟后返回，包含约 24 个客户账号，每位需求者一行，包含其 Slack 用户名、团队、客户账号以及原始需求的链接。



让 Claude 生成一份在 Slack 中提出过某特定功能需求的所有人清单。此图片为示意用例而生成，不包含真实信息。

随后，Steph 交给 Claude 一项规模更大的汇总工作，这项工作她自己根本没有余力完成：她想要了解企业客户在过去一周报告的所有产品问题，包括哪些出了故障、哪些已修复，以及哪些报告（如果有）指向同一个底层问题。她让 Claude 读取所有涉及事故、升级、支持和产品反馈的 Slack 频道，约 50 分钟后，Claude 发布了一份按产品领域组织的报告，包含 23 个仍未解决的问题和 14 个已解决的问题，由约 120 条原始发现压缩而成。每个问题都包含摘要和指向来源话题串的链接。随后 Steph 让 Claude 检查自己的工作，它又发现了 15 个问题。

Steph 估计，梳理、分析并综合如此大量的信息，至少需要她一周的全职工作，或者根本不会有人去做。而借助 Claude Tag，她只花几分钟完善需求，Claude 便在后台工作。

Steph 也在一个私有频道中与 Claude 协作，一开始就发送完整指令，包括在哪里搜索、什么算作匹配，通常还会给出输出格式示例。Claude 会搜索工作区、读取它被邀请加入的频道，并在工作时发布进度更新。当反馈中心阻止访问时，Claude 会尝试通过可访问的文档和频道收集相关或有关的信息，甚至会请求获得这些频道的访问权限。

## 加速法务文档审查

Anthropic 的法务团队会在每篇博客、落地页、邮件或任何其他物料公开发布前进行审查。在产品发布前的几天里，营销团队可能在紧迫的截止期限下排队提交数十份不同物料等待审查。这还不包括流经审查队列的所有其他营销物料，从一段话的社交文案到 2,500 词的博客草稿、带十几个以上标签页的规划文档，以及跨多个触点的多版本邮件系列。法务团队的产品法律顾问 Molly Villagra 创建了一个专用 Slack 频道，由 Claude Tag 先审查每一份营销物料，将营销法务审查的周转时间从每份物料一天（或更长）压缩到 30 分钟。

为请求法务审查，营销人员会在 Slack 频道中发布文档链接，而没有任何工程背景的 Molly 已为 Claude 设置了具体的规则和指令。Claude 不仅能发现法务问题（如缺乏依据的营销声明），还能帮助核查营销内容中的事实陈述，因为它可以访问公司 Slack、内部知识索引和公开网络。如果有需要标记的问题，Claude 会列出这些问题并给出具体的处理说明，并直接与请求者协作处理。对于仍需法务签字确认的遗留问题，Claude 会 @ 相应的产品法律顾问，后者可以快速审查被标记的陈述。

例如，在最近一次新闻邮件审查中，Claude 标记了三个关键事项，几分钟后，它在未受提示的情况下，从内部文档中找到了所需信息，并解决了其中一项。Molly 让它在营销法务审查频道中 @Claude，将这一做法设为默认：

‍`你的三条要点提得很好，但它们都可以由你来核实。以后你标记这些问题时，能否实时尝试核实？`

应 Molly 的要求，Claude Tag 将这条新指令加入其指令集，在未来所有审查中遵循，使其能够借助频道反馈实时改进。

这一反馈循环启发了 Molly 建立一项新例程：让 Claude 每周五审查当周法律顾问的反馈，并提出对共享指令的更新建议，供她审批。
