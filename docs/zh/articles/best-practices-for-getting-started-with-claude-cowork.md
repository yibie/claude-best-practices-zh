# Claude Cowork 入门最佳实践
2024 年，Claude 还在一个聊天窗口里。你问一个问题，得到一个答案，但要把答案变成有用的东西，还得靠你自己。2025 年，Claude Code 让工程师们的交付速度快到让我们其他人有点羡慕。

今年，我们所有人都能靠 [Claude Cowork](https://claude.com/product/cowork) 追上来了。

去年我开始用 Claude Code 处理聊天无法胜任的、长时间多步骤的任务。一周之内，我就从不知道终端是什么，发展到搭建出[能在 30 秒内完成 30 分钟任务的 Claude Code 工作流](https://claude.com/resources/articles/how-anthropic-uses-claude-marketing)。我当时用 Claude Code 做非技术工作，是因为那时 Claude Cowork 还不存在。

现在，我 90% 的工作都在 [Claude Cowork](https://claude.com/product/cowork) 里完成。在这篇文章中，我会告诉你如何判断哪些任务适合放在那里，带你走一遍我自己工作中的真实例子，并让你在大约十分钟内产出第一个完成的交付物。

## 使用 Chat、Claude Cowork 还是 Claude Code

如果你的工作是非技术性的知识工作——邮件、演示文稿、电子表格、文档、会议，以及"你能帮我整理一份总结吗"——那么 Claude Cowork 就是为你准备的。你不需要会写代码。你不需要知道什么是"智能体"，也不需要知道怎么构建一个。

如果你过去两年一直在一个 AI 聊天标签页里工作，旁边还开着 100 个其他标签页和文件，把提示词或问题复制粘贴进去，再把答案复制粘贴出来，那你已经知道怎么用 Claude Cowork 了。就是那样，只是不用复制粘贴。

驱动聊天、Claude Cowork、Claude Code、Claude Design 以及 Claude 出现的其他所有地方的，是同样的 Claude 模型。它们是各自独立的工作空间，用于不同类型的工作，但里面运行的都是同样的模型。下面是一个框架，帮你思考何时该用哪一个：

-   **Chat** 通常是知识工作者接触 Claude 的方式。你把手头的东西带给 Claude：上传一个文件、粘贴一些文本、描述一下情况，然后得到一个答案。Chat 用于获取答案、头脑风暴和边想边说。
-   Claude 桌面应用中的 **Claude Cowork** 则反过来。不是把你的工作带给 Claude，而是把 Claude 带到你的工作中。你把它指向电脑上的一个文件夹，连接到你已经在用的应用，然后告诉它你想完成什么。用 Claude Cowork，你描述一个结果，走开一会儿，回来时工作已经完成。**‍**
-   **Claude Code** 是为构建和交付软件的开发者打造的。如果你的工作存在于代码中，就从那里开始。

很多人不知道，Claude Cowork 和 Claude Code 底层运行在同一个[引擎](https://code.claude.com/docs/en/how-claude-code-works)上。

### 什么时候应该使用 Claude Cowork？

理解何时使用 Claude Cowork、何时使用聊天，是大多数人卡住的地方，所以这是我的经验法则：

-   **使用聊天**，如果你想要的东西几次交流就能搞定，比如一个问题、一个解释、一次头脑风暴，或一次直觉判断。
-   **使用 Claude Cowork**，如果你需要的是一个交付物，例如一个别人会打开的文件、一份别人会演示的演示文稿，或一个需要整理排序的电子表格。凡是多步骤的、涉及不止一个文件/文件类型或不止一个应用的，或者你会把它描述为一项任务而非一个问题的，都用它。用 Claude Cowork，你是在把工作_委派_给 Claude。

几个例子说明这条线划在哪里：

| 示例问题或任务 | 使用 |
| --- | --- |
| 我们的业务回顾会议上应该讲些什么？ | Chat |
| 读取这个 Google Drive 文件夹里过去三个月的会议记录，用我们的模板给我做一份 QBR 演示文稿。 | Claude Cowork |
| 我怎么做 VLOOKUP？ | Chat |
| 翻一遍我的电子表格，把所有 VLOOKUP 都改成 INDEX MATCH。 | Claude Cowork |
| 为这个页面建议一个更好的标题标签和元描述。 | Chat |
| 用这个表格里这 30 个页面的新标题标签和元描述，通过 CMS 连接器更新它们。 | Claude Cowork |

最常见的错误是凡事都用聊天，从而永远感受不到 Claude Cowork 能带来的差别。相反的错误则是用 Claude Cowork 处理一次性问题，然后干等着聊天五秒钟就能给出的答案。

### 适合 Claude Cowork 的任务的五个要素

如果你刚开始时不确定哪些项目该委派给 Claude Cowork，就用这份清单过一遍。你不需要满足全部五个标准，但一个好的候选任务会命中其中几项：

1.  **输入不止一样东西。** 多个文件、一整个文件夹，或一个文件加上一些连接器。如果只有一个输入，聊天在大多数情况下大概就能处理好（不过你还是应该试试）。
2.  **输出是一个文件。** 你需要一个可以附上、演示、分享或再利用的交付物：一份文档、一份演示文稿、一个电子表格，或一个 CSV。
3.  **你还会再做一次。** 一次性任务也可以，但重复性任务才是最佳场景。你可以安排它们在你还没坐到桌前时就运行。
4.  **你已经知道"好"是什么样。** 你熟悉输出的形态，所以能在 15 秒内判断输出是对、是错，还是完成了 70%。**‍**
5.  **中间部分是无聊的部分。** 思考发生在开头（决定你想要什么）和结尾（判断它是否正确）。中间的一切（提取、汇总、核对、重新格式化）就是你交出去的部分。

## 我在 Anthropic 如何使用 Claude Cowork

我在 Anthropic 负责增长营销，所以我的例子带有营销色彩。不要指望从这些例子里照搬一个工作流——长期来看那不会有帮助。注意看每一个例子如何命中上面清单中的几项，因为那才是你在自己的 Claude Cowork 工作流中要寻找的模式。

### 每日简报

营销人员每天收到的 Slack 频道消息和邮件数量可能让人不堪重负。我有一个"每日简报"任务，每天早上 6 点运行。Claude Cowork 连接了我的 Slack 和 Gmail，我的提示词让它查看我的未读邮件和我关心的频道，把它们分门别类，并生成一份简短报告。



这份报告给我一份该关注什么的 TLDR、按类型分组的标记邮件、频道摘要，以及任何可能影响营销的夜间产品相关事件。任何被 Slack 和邮件淹没的人都可以运行这个工作流的某个版本。

### 预算节奏

我的工作之一包括效果营销的预算节奏管理。这是那种没人愿意做的工作，因为它无聊又繁琐。许多效果营销团队在 Google Sheets 中跟踪每日花费和消耗速率，以估算达成目标的节奏。要么你手动从每个渠道导出每日花费并粘贴到表格里，要么你付费购买第三方工具来为你提取、转换和加载数据。



用 Claude Cowork，我连接 Google Ads 和 Meta Ads，并在桌面应用中创建一个实时 Artifacts（基本上就是一个 HTML 仪表盘），它会自动拉取我的每日花费并为我计算节奏。我也可以用平实的语言直接告诉 Claude 如何筛选我的广告系列以及要留意什么。

拿它对照上面的清单：多个来源输入（每个渠道的花费），一个文件输出（在这个例子里是仪表盘），我不断地重跑它，而中间是那种无脑又折磨人的下载-复制-粘贴苦活，我绝对不想自己干。由于广告平台是通过我的连接器集成的，我可以随时更新这个仪表盘。

### 报告

与其导出一堆 CSV 再手动建数据透视表或合并文件，我把 Claude Cowork 连接到 Google Search Console。它拉取我关心的内容（查询词、国家、页面），并核对汇总到一张表里，而不是像 Google 在你手动导出数据时默认的那样每个维度一个 CSV。



我还会给 Claude 提供关于该关注什么的上下文，比如看最近七天对比前七天、只筛选特定国家、标记任何有显著变化的内容，并按我想要的模板撰写报告。之后我可以继续调整任何内容，或向 Claude 提出后续问题。

借助 Claude Cowork 的定时功能，这个任务每周自动运行。报告过去每周要花我约 30 分钟；现在只需五分钟，我把这五分钟花在需要我判断的部分上：补充缺失的上下文，以及推敲要点说明。

这些只是我使用 Claude Cowork 的一些例子，但它们只是冰山一角。看看我写的另一篇文章，其中重点介绍了一个[更详细的演练](https://www.linkedin.com/feed/update/urn:li:activity:7448056387772833795/)，涉及另一个复杂用例，涵盖插件、Skills（技能）、本地 MCP 和 [Dispatch](https://support.claude.com/en/articles/13947068-assign-tasks-from-anywhere-in-claude-cowork)，以了解更多最佳实践。

## 你的 Claude Cowork 最初 10 分钟

第一次打开这个应用？下面是如何上手：

1.  打开 Claude 桌面应用，切换到 Claude Cowork 标签页。
2.  给 Claude 一些可以处理的东西。放入几个文件，把它指向你电脑上的一个文件夹，或连接一个你经常使用的应用（Slack、Gmail、Notion、CRM 等）。平庸的 Claude Cowork 输出和出色的输出之间的差别，几乎从来不是你的提示词，而是你是否提供了足够丰富的上下文供 Claude 使用。
3.  告诉 Claude 你想要的结果。描述你最终想要的交付物，并提供任何必要的上下文。
4.  从一个你非常熟悉的真实任务开始。你会立刻看到它强在哪里、哪里需要你提供上下文，而且你已经知道对它来说"好"是什么样。
5.  让 Claude 在开始前先问你问题。这是我养成的最有用的习惯。把这一点作为提示词的一部分：_在我们开始之前，把我的要求复述给我，以确保我们理解一致，然后尽可能多地问我澄清问题。_

这会暴露出你没想到要说明的事情，比如我们看的是哪个时间段、这里"好"是什么意思，或者你知道但 Claude 不知道的边界情况。陷阱在于假设 Claude 已经知道对你来说显而易见的东西。事先回答五个问题只花你 30 秒。事后发现同样的缺口则要耗费时间和 token，而且修起来很麻烦。

还是不确定该交出去什么？问 Claude。Claude 有记忆，可以搜索你过去的对话，所以你可以问它你最常做哪些任务，以及哪些适合在 Claude Cowork 里尝试。



### 我什么时候仍会用聊天

我仍然大量使用聊天来讨论定位问题、在做出承诺前对某个想法进行压力测试，或者问一些随机问题，比如我的狗为什么老是舔床。

重点不是聊天是"旧"的东西。聊天适用于输出是你头脑中的一个想法，而 Claude Cowork 适用于输出是你会交给别人的东西。

## 去构建点什么吧

挑一个你每周都做的重复性任务，试着用 [Claude Cowork](https://claude.com/product/cowork) 来做，看看会得到什么。最初几个任务可能感觉有点别扭，但试过几次之后，你很快就会从"我该怎么用这个"变成"接下来我该交给它什么"。
