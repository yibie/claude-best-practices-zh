# Outtake 如何在 Claude 上构建网络调查员
_在我们的系列文章_ **初创公司如何用 Claude 构建产品** _中，我们重点介绍初创公司如何借助 AI 变革各自行业。本文分享 Outtake 如何构建一个自主网络调查员，用于检测、调查并瓦解数字威胁，从克隆的登录页面到整个对抗性网络。_

即便拥有强大的防护措施和控制手段，恶意行为者仍能将他们对 AI 的使用伪装在看似无害的用途之下，以掩盖其恶意意图。代码生成平台可以创建以假乱真的登录门户，智能体式的 go-to-market 工具可以驱动钓鱼攻击的分发，图像生成能力可以伪造身份。传统网络安全防御难以跟上步伐。

“如果你站在恶意行为者的角度，现在其实是发动攻击的大好时机，”AI 网络安全平台 [Outtake](https://www.outtake.ai/) 的创始人兼 CEO Alex Dhillon 说。“拜 AI 所赐，普通攻击不仅执行得更快，而且还能获取更深的访问权限。”

Outtake 将完整的[数字信任攻击链](https://www.outtake.ai/blog/2026-digital-trust-industry-pain-report)统一为单一防御体系，使用成群的 AI 智能体自主检测、调查并瓦解针对其客户的威胁，这些客户包括领先的 AI 实验室、大型对冲基金和美国联邦机构。

以下是 Outtake 团队近期如何利用 [Claude Code](https://code.claude.com/docs/en/quickstart) 和 [Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview)，在 Claude 上构建 Recon Agent 这一长时程自主网络调查员的过程。

## **智能体式的攻击需要智能体式的防御**

在针对一家公司时，攻击者通常遵循相同的流程：将公开数据武器化 → 构建仿冒身份作为诱饵 → 利用内部系统。这一流程已被 AI 加速。

在入侵任何目标之前，他们会收集关于某个组织及其高管和员工的公开信息。

随后，他们将这些情报转化为诱饵，例如带有欺诈性登录页面的虚假网站，诱骗受害者交出凭据。通过这些诱饵获得的访问权限，帮助攻击者进入边界内部，触达组织最有价值、最敏感的资产。


这个三阶段序列是可预测的，但传统安全工具每次只能守护其中一个环节：

-   威胁情报工具监控公开数据阶段，
-   品牌保护工具监视仿冒行为，以及
-   端点工具守护内部系统。

Outtake 的 Recon Agent 会调查仿冒行为背后的完整网络。例如，该智能体不只是下架一个克隆的登录页面，而是从仿冒事件中收集并分类证据。

它顺着这些线索追踪到相关联的基础设施，例如一个自称“客户支持”的虚假 Telegram 账号，并在图谱中绘制出这个对抗性网络。该智能体的最后一步是生成一份报告，说明调查过程、威胁行为者的画像，以及攻击者行为的重建时间线。

为了执行这一复杂的工作流，Recon Agent 能够读取、编写和运行代码。它甚至可以直接与恶意登录页面交互，查看被盗凭据究竟流向何处。

这些调查可能要求智能体长时间自主运行。智能体会话的中位运行时长为 16 分钟，但经常延长到一小时甚至更久；迄今为止最长的一次运行持续了两个小时的智能体式工作才返回结果。

## **Outtake 如何用 Claude 构建一个复杂的长时程智能体**

Outtake 大致分四个阶段构建了 Recon Agent。每个阶段的核心都是理解一次好的调查是什么样子，然后逐步将这种判断力交给智能体。



### **第 1 步：先成为专家。**

在构建智能体的任何部分之前，Outtake 的工程师们亲自执行了真实的网络调查，并从客户和设计合作伙伴那里汲取领域专业知识。

目标是定义“好”是什么样子。对于这类调查而言，这意味着确定哪些证据重要、如何组织证据，以及什么能将可付诸行动的结论与猜测区分开来。这一标准成为他们在后续每个阶段都会回归的固定参照点。

“构建长时程智能体最重要的一点是，你必须真正理解_好是什么样子？智能体应该做什么？_”Outtake 智能体平台工程负责人 Jack Hayford 说。“因为归根结底，你要确保智能体每一次都能做到这一点。”

### **第 2 步：在 Claude Code 中做原型**

最初，Outtake 团队使用传统的智能体框架，将他们正在标准化的调查逐步自动化。

然而，他们很快意识到，Recon Agent 不能只是一个简单的调查员。它需要编写、运行代码，即时构建工具，并真正与恶意域名交互。

“每一次调查都不同，而且技术性很强，”Hayford 说。“智能体需要编码能力和实力，而 Claude Code 是一个强大的初始执行框架（harness），让我们能够真正验证这些假设，并开始越来越多地实验。”

正是在 Claude Code 中做原型的过程中，他们锻造出了核心设计原则：在编排层面严格约束智能体（_‘调查某个域名时始终执行 X、Y、Z’_），但在需要判断时让它自由发挥。

### **第 3 步：升级到生产级执行框架**

“我们非常喜欢 Claude Code 引入的模式，但我们需要额外访问更底层的原语，而这些我们并不打算自己构建，”Hayford 说。

使用 Claude [Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview) 是将 Recon Agent 投入生产的自然下一步。从 Claude Code 沿用 Skills 和模式，确保团队在获得对 Recon Agent 的记忆、上下文和文件系统更紧密控制的同时，没有损失任何速度，也无需在智能体循环和会话处理方面重新造轮子。

### **第 4 步：构建由评估（eval）驱动的紧密迭代循环。**

在网络安全领域，廉价且响应迅速的迭代能力尤为关键，因为攻击者一旦得知某种防御工具存在，就会立即调整策略。团队从一开始就集成了智能体评估（eval），并打造出一套强大的评估套件，可同时运行多个场景。这让他们能够安全、自信地进行大规模变更，例如模型升级和完整的记忆系统重构。

这也让团队得以跳出智能体循环。例如，当 Recon Agent 完成一次调查并反馈说，如果拥有某个它没有的工具本可以做得更好时，另一个编码智能体就会读取这些建议，编写新工具，并构建一个测试场景来试用它。

只有在最后，才由人类介入查看结果：智能体使用该工具后调查做得更好了吗？“我们才是瓶颈，而当你构建这些长时程、复杂的智能体时，让反馈循环自动化非常重要。它快得多，而且作为开发者也会更有成就感，”Hayford 说。

## **构建长时程智能体的经验教训**

在智能体的早期，构建者会预先用硬编码的、确定性的、逐步的路径来编排智能体行为，以防它偏离轨道。如今，精心设计的工作流正被执行框架（harness）所取代：一个由记忆、工具、Skills 和护栏组成的支持性环境。

以下是 Outtake 团队在实施 Recon Agent 构建过程中的一些心得。

### **工具：一个文件系统加 bash 就够了**

文件系统使记忆能够在上下文压缩（compaction）后存续。智能体通常会被赋予非常具体且细致的工具，但为智能体提供一个文件系统，外加编写、读取和运行代码的能力，有助于智能体应对障碍。

“把那些极其强大的开放式工具和能力交给智能体，是一个巨大的飞跃。我们观察到很多案例：智能体的某个工具因网络波动之类的原因而失败，它就直接找到了正确的变通方法并继续下去，”Hayford 说。“因为我们构建的执行框架其余部分足够强大，也因为它让智能体有机会利用这些强大的开放式工具进行即兴发挥，它仍然能够取得成功的结局。”

### **提示词只是建议**

提示词在需要时提供灵活性，但尽可能硬编码能确保稳定性。“当你构建这些随时间推移变得复杂的长时程智能体时，提示词只是建议，”Hayford 说。“当智能体没有做你想要的事时，自然的反应是往智能体最具可塑性的部分添加内容。把‘当 X 发生时，确保执行 Y’塞进系统提示词，起初可能有效，但随着这个智能体运行得越来越久，那个提示词里的每一个字最终都可能被忽略。”

正确的做法是围绕这种可能性来构建：找出智能体每次都应该始终执行的事情，并将其纳入智能体护栏。“把这些东西从提示词中抽出来，放进执行框架里，”他说。“这样智能体就不必再考虑它了，它也有了更多的上下文空间和注意力，可以投入到它真正能大展身手的领域。”

### **评估是为了速度，而不仅仅是可靠性**

将人工“反思”作为通往自动化评估的路线图，以收紧开发周期。传统观点认为，评估是保障可靠性的质量关卡。然而对于长时程智能体而言，更大的回报在于速度。

早期，每当 Recon Agent 运行一次，团队都会人工审查其表现。但阅读智能体 30 分钟的全部行为记录既痛苦又无法规模化。

“在现代智能体开发中，评估输出是循环中最昂贵的一步，”Jack 说。

评估（eval）不过是这种反思的结构化、可评分、可自动化的版本。一旦你将“好是什么样子”固化为可重复的检查，你就可以让一个智能体坐在裁判席上，阅读那 30 分钟的记录并为本次运行打分。

“我认为有些工程师对构建评估感到不安，因为这有点像构建一个完美案例的想法，”Jack 说。“从最开始就构建某种版本的评估，无论它们有多正式或‘完美’，都会让你更快地构建出那个智能体。”

### **保护你的智能体**

[提示词注入](https://www.anthropic.com/research/prompt-injection-defenses)是真实威胁，因此将智能体放入沙箱或为它披上铠甲至关重要。Outtake 团队选择 Claude 的部分原因正是它在抵御提示词注入方面的实力。

“安全是我们构建 Recon Agent 时的一大重点，”Hayford 说。“我们给了它文件系统和 bash，还把它送进对抗性环境，所以我们必须解决的最重要问题，是构建某种防爆箱（blastbox），让你能够将智能体与敏感内部信息隔离开来，同时又不真正妨碍它。”

他们的方法假设智能体可能被劫持，因此周边系统被设计为控制损害。然而，安全因智能体的用途而异，并非所有智能体都是防爆箱的候选对象。

Outtake 现在正在智能体触达互联网的确切节点上评估信任级别，实施一个检查点来评估智能体即将接触的任何内容：‘这个页面是仿冒的吗？是恶意软件吗？它此刻是否正试图对智能体进行提示词注入？’随着智能体穿行于日益对抗性的互联网，这可能正是它们所需的铠甲。

| Outtake 团队的最佳实践 |
| --- |
| 你知道“好”是什么样子吗？ | 先自己成为智能体。亲自运行真实任务，并从客户和设计合作伙伴那里汲取领域专业知识，这样你就有了一个固定标准，用来衡量之后的每一次迭代。 |
| 每一分复杂度都是挣来的吗？ | 找到最简单的可用版本，然后逐块自动化。只有当结果证明其合理性时才增加复杂度——与传统软件同样的纪律。 |
