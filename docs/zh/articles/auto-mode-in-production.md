# 在生产环境中运行自动模式
[自动模式现已成为](https://claude.com/resources/articles/auto-mode-default-in-claude-code) Claude Code 的默认设置。它不再要求你批准智能体想要运行的每一条命令，而是由一个分类器评估每个操作，并阻止那些看起来可能有害的操作。

自动模式的设计解决了智能体式编程中一个常见的权衡：速度与安全。审查每一条命令能让人类留在循环中，但一旦会话延长到数小时或并行增多，这种监督就会成为瓶颈。完全跳过权限检查速度更快——但提示词注入、范围漂移以及偶尔被删除的生产资源也正是这样溜进来的。

自动模式弥合了其中大部分差距。在内部评估中，分类器发现的危险操作比开发者手动点击权限提示时发现的还要多，而且它的表现在第三方红队测试下依然稳健。此外，由于会话暂停的频率更低，Claude 在两次中断之间的工作时长比之前的默认设置长 9 倍——这适用于所有 Claude Code 用量。

为了解自动模式在生产环境中的表现，我们与 Nuro、Gusto 和 Garner Health 的团队进行了交流，了解他们如何以及为何将自动模式作为日常主力，在生产环境中平衡速度与安全。

### 在 Nuro 驱动更长时程的自主智能体

Nuro 是一家开发通用 Level 4 自动驾驶技术的物理 AI 公司，于 2025 年底采用 Claude Code，到 3 月它已成为公司内最受欢迎的智能体式编程工具。

在自动模式发布之前，资深软件工程师 Kai Zhou 就已经开始原型化一个内部替代方案：一个钩子（hooks），将每个待处理操作发送给一个小模型，90% 的常规操作自动批准，任何敏感操作则路由到 Slack 供人工审查。这个原型回应了一个真实的矛盾：工程师讨厌守着审批提示，但从公司安全和法律的角度来看，直接跳过权限又太危险，无法获得批准。自动模式发布后，Kai 搁置了这个副项目。

如今，Kai 写的一切代码都运行在自动模式下。

“我不想一直坐在那里点批准，”Kai 说。“我 100% 的编程工作都使用自动模式。大多数时候，我同时打开三四个运行自动模式的会话并行工作，需要时再查看一下。”

例外是涉及其他团队的工作。例如，当 Claude Code 代表他审查拉取请求（PR）时，Kai 会切回交互模式，在发出之前逐一审查。

自动模式也并非不受约束地运行。Nuro 大量依赖 [skills](https://agentskills.io/home)，工程师会在设置中直接拒绝最危险的命令，比如递归删除。分类器就是在这些护栏之内做出判断的。

然而，自动模式更大的解放在于能够启动在工程师下班后仍持续运行的工作。具体来说，Kai 的团队使用自动模式来驱动长时间运行的研究智能体，这些智能体会对其自动驾驶技术栈背后的评估指标进行爬山式优化：这些任务有清晰、可度量的信号，智能体可以据此自行迭代。

一整夜，智能体可以研究评估套件标记出的假阴性，起草提案，运行实验，并持续根据结果迭代。这种方法适用于任何有明确评估方法的任务——Nuro 的另一个团队用它来缩减某个特定二进制的内存占用——因为指标本身就能告诉智能体它是在改进还是在退步。

“前几天，我晚上 10 点启动了一个智能体，它一直运行到凌晨 5 点——早上给了我三个 PR，”Kai 说。“我觉得这相当了不起。只有自动模式才能支持这种工作负载。”

### 在 Gusto 更快、更安全地交付 PR

在 Gusto 这家领先的中小企业技术公司，转向自动模式最初是作为一项主动的安全升级。

在公司 AI Dev Tools 团队工作的 Martin Emde 观察到权限疲劳拖慢了团队。自动模式让他们在不牺牲控制或安全的情况下获得了同样的速度，而且随着工程部门广泛采用，整体的权限负担已明显下降。

自 12 月以来，Martin 已启动 2,425 个 Claude Code 会话，自动模式是他的日常主力。过去因文件夹访问审批而停滞的跨仓库工作现在可以不间断地运行，而无人值守的任务，比如从 GitHub、Slack 和 Jira 汇总每日笔记，也能自行运行。根据他团队自己的分析，自 2026 年 5 月中旬以来，大约 10% 的会话记录中包含了一次自动模式拒绝，这证明分类器确实在发挥作用，同时没有拖累正当任务。

“自动模式为我们提供了速度与控制之间更安全的平衡，”Martin 说。“我们得以移除重复的提示，在不牺牲安全的情况下提高生产力。我们能看到自动模式在正确的时机进行阻止，这让我们有信心快速推进。”

Gusto AIT Cloud Engineering 团队的成员 Chad Kunsman 从另一个方向得出了同样的结论。他的工作——端点调查、日志审计、连接器管理、跨一组 MCP 服务器的文档摄取——以二十分钟的短时爆发运行，而非通宵马拉松。他并不追求更长的运行时间；他想要的是绕过权限模式那种放手不管的节奏，同时又不承担坏提示词或提示词注入溜进来的风险。

“考虑到它对提示词注入的防护，以及它检查你正在做的事情是否确实与你要求的一致的方式，它比绕过权限模式更好，也比权限提示快得多，”Chad 说。

在分类器确实介入的少数情况下，Chad 说它判断得很准。“当它阻止我时，它说得有道理，并解释了原因。它偏离了我最初的要求，于是它来确认了一下。它完全没有搞错。”

Chad 在最敏感的工作中仍会退出自动模式。当会话深入到生产基础设施——Terraform、AWS、针对实时 API 的直接 POST 调用——他会切换到接受编辑模式，并手动验证每一次工具调用。“你必须权衡你节省的时间与它可能合理犯错的地方，以及那会有多灾难性，”他说。“归根结底，你仍然要对发生的事情负责。”

这种判断运行在一个更广泛的纵深防御体系之内：Gusto 将其 MCP 流量通过一个带有工具护栏和提示词检查的受治理代理层路由，因此智能体在自动模式介入之前就已经在严格限定的权限范围内工作。

### 在 Garner Health 加速软件开发生命周期（SDLC）

医疗健康技术公司 Garner Health 于 2 月向全部 550 名员工、覆盖所有职能推广了 Claude Code。该工具已接入包括 Salesforce、Zendesk 和 Snowflake 在内的所有核心系统，并鼓励员工每周花大约两个小时自动化工作中最重复的部分。

在自动模式之前，这种规模伴随着额外开销。Garner 的平台工程经理 Evan Magnussen 将权限管理描述为一个乏味的循环：手工整理已批准的命令列表，然后看着管道命令被拒绝。

如今，Evan 和他的大多数同事在每个会话中都使用自动模式，从研究代码库到通过 MCP 管理外部集成。

“我们为整个工程组织构建了一套标准化的软件开发生命周期，而这实际上只有借助自动模式才可能实现，”Evan 说。“员工们觉得如释重负。他们不再需要连续数小时盯着自己的智能体了。”

这套生命周期以标准化 skills 的插件形式运行。智能体接手一个任务，探索它可以访问的上下文，将上下文文件提交到仓库，运行 Evan 所说的“对抗性研究”来压力测试自己的假设，然后进入实现阶段——只有在需要它自己找不到的上下文时才暂停等待人类。Evan 指出，这些研究密集的阶段在自动模式之前是不可能实现的。

开箱即用，分类器几乎不需要调优。Evan 唯一的调整与 Nuro 的 Kai 如出一辙：他配置自动模式不批准与他人沟通的操作，比如发送 Slack 消息或电子邮件。

“我个人不喜欢 Claude 在我与另一个人沟通时代表我行动，”他说。从事核心知识产权工作的团队——在自动模式之前对跳过权限最为怀疑——学会了调整分类器注入的提示词，使其对自身工作更宽松或更严格。

他对其他推广此功能的企业有什么建议？积极投入并构建正确的控制措施，这样你就能赋能工程师，同时确保安全部署。“如果我们说，大家都去构建自己的工作流吧，而我们没有遥测，那将非常危险，”Evan 说。“因为我们有遥测，因为我们构建了相对标准化的工作流，我们才有更多的信心。”
