# 智能体时代的产品开发

作为 AI 时代的产品经理，其中一个讽刺之处在于：我的工作感觉比以往任何时候都更有人情味。

产品管理这份工作一直是专业技艺与对齐协调的混合体。在我职业生涯的大部分时间里，我的一周都被后者占据：与跨职能利益相关方和团队成员开会、写状态报告、与工程团队一起梳理工单积压。我习惯了凭直觉快速做决定，然后经历一场场艰难的战斗去倡导、说服、争取资源；交付有影响力的产品往往更像交易，而非创造。

有了 Claude，我可以对想法做压力测试、自动化工作流、摆脱卡点。我终于能把真正的时间花在用户和团队身上，投入到这份工作中始终最重要的部分：专业技艺。这些新的工作流改变了我的日常工作，但最有意义的转变发生在我们开始开发 [Claude Managed Agents](https://claude.com/resources/articles/claude-managed-agents)（目前处于 beta 阶段）的时候——这是一套可组合的 API，用于大规模构建和部署云端托管的智能体。

在这篇文章中，我将分享 Managed Agents 如何改变了作为产品经理的我工作方式，以及一些你可以借鉴到自己工作流中的模式。

## **产品开发，今昔对比**

API 设计过去存在于文档和评论线程中；在 AI 的指数级发展曲线上，我们用交付的东西来构建。一份在文档里读起来优雅的规格，第一次照着它动手构建时就可能崩塌。有了 Claude Code，我可以基于 API 规格的预生产版本草拟一个智能体，一个下午就能端到端跑起一个真实的原型。

我们根据用自家基础组件构建时的所学，多次重塑了 API 抽象和 Claude Console 的 UX——这些改动即便经过数周的文档评审也永远不会浮现，否则只能等到用户反馈时才姗姗来迟。我们仍然会推敲各种形态、运行原始的 curl 请求，以确保对裸机体验满意，但 Claude Code 能让我在同一次坐下工作的时间里，从基础的 "hello world" 测试走到一个可用的智能体。在构建这些智能体的过程中，我能更具体地预判我们的执行框架（harness）和 API 可以如何灵活适配下一波模型与任务的演进。

起初，这些原型只是为了塑造产品，但现在它们也在改变我的日常工作。作为产品经理，我的工作流现在清晰地分布在我们的各个产品上。我用 **Claude** 和 **Claude Cowork** 做开放式研究和探索——那是模糊的早期阶段探索，我希望保持持续的对话。一旦我对要完成的任务有了更清晰的认识，我就用 **Claude Code** 编写并交付一个定制的智能体，构建在 **Managed Agents** 之上。

这种双管齐下的回报是最大的突破。一方面，能轻松地基于自己的产品进行构建，抬高了我对下一步能交付什么的想象上限。另一方面，产品上线后，同样的开发能力让我能自动化那些过去一直卡在积压清单里的长尾运营工作。

## **产品经理的 Managed Agents 用例**

现在，我会为任何"要完成的任务"搭建专属智能体。构建一个很简单：我在 Claude Code 中加载 Managed Agents skill，快速勾勒出我想要的东西。开发者也可以使用最新版本的 Claude Code 和内置的 `claude-api skill` 来基于 Managed Agents 构建——只需向 Claude 输入"_start onboarding for managed agents in Claude API_"即可开始。调用这个 skill 后，Claude 会构建智能体，并沿途解释其集成步骤，因此我可以根据需要轻松调整方向。

这些智能体的例子包括：

-   **采用情况分析。** 一个智能体持久访问我们的内部数据库，并具备理解我们数据 schema 的 skill，运行查询以找出有趣的异常值和模式。借助对以往运行轮次的[记忆](https://claude.com/resources/articles/claude-managed-agents-memory)，它可以基于先前的发现继续推进，不断深化自己的视角。
-   **开发者情绪监测。** 一个智能体配备预置的[网页搜索工具](https://platform.claude.com/docs/en/managed-agents/tools#available-tools)和关于关注领域的指引，扫描一份特定的域名列表以获取最新的开发者反馈，并汇报常见主题。由于要分析的内容太多，它会把研究任务分发给[多个智能体](https://platform.claude.com/docs/en/managed-agents/multi-agent)并行处理，等待结果并综合发现。
-   **演示构建。** 一个智能体可以访问演示用 GitHub 仓库、品牌素材和活动演示文稿，把预置模板转化为针对相关受众（例如会议或客户会议）量身定制的精致演示。

Managed Agents 的会话在云端运行，所以我可以走开，回来时发现工作已经完成。那些因为每次发布都有各自的特殊之处而永远无法规模化的流程，现在用 Managed Agents 就能轻松自动化，而且每一次智能体运行都让人感到充满干劲，而非枯燥乏味。

## **腾出空间打磨专业技艺**

一年前，这类工作都只能通过跨职能的人员调配申请、混乱的电子表格，或者我始终没机会尝试的半成品概念缓慢推进。现在，有了 Claude 和 Managed Agents，我可以扩展自己，把时间用于与团队合作开发最有影响力的产品。我的一天现在包括与客户一起激发创新想法、与工程同事一起钻研模糊而棘手的问题，以及在前沿产品工作上投入真正的创造力。

如果你是一名产品经理，还没有构建过智能体，那这就是我建议你本周开始的地方。那些你一直希望存在的实验和工具，只差一个提示词和几次 API 调用。
