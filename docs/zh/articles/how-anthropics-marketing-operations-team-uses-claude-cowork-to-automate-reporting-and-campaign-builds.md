# Anthropic 的市场运营团队如何使用 Claude Cowork 自动化报告与营销活动搭建

市场运营团队会把相当一部分时间花在让营销项目背后的系统与业务保持同步上。虽然自动化明确属于他们的职责范围，但很多工作却远非如此：营销技术工具之间无法顺畅集成，报告需要手动汇总，落地页只能一个一个地搭建。

Anthropic 市场运营团队的 Ian Chan 过去每周要花一到两天时间汇总每周营销指标回顾。专注于营销活动运营的 Annabel Custer 过去每举办一场新活动，都要依次在 Salesforce、HubSpot、Swoogo 和邮件工具中逐一点击设置。如今，两人都通过在 Claude Cowork 中搭建工作流，把原本需要数天的手动工作压缩到了数小时。

省下来的时间改变了他们工作的形态。Ian 和 Annabel 现在花在点击系统上的时间更少，更多时间用于赋能、验证，以及维护营销团队所依赖的底层数据与流程——随着公司里越来越多的人自行拉取数据、推动自己的项目，这些工作变得愈发重要。

## **生成每周营销指标报告**

在理想情况下，Ian 为营销团队和管理层准备的每周报告中的每一项指标都应该存在于仪表盘中，他的工作只是把叙述串起来。但现实中，有些指标已经在仪表盘里，有些还没从数据仓库进入仪表盘，还有些甚至尚未接入数据仓库。新出现的指标可能只存在于某条 Slack 消息或某次通话记录中。

在 Anthropic，业务变化的速度快过传统报告流水线所能跟上的节奏，Ian 过去每周要花一到两天追踪数据并加以验证。现在，Claude Cowork 承担了大部分数据搜寻工作。

一个定时任务每周日晚运行，提示 Claude 阅读上一周的回顾和最新的会议记录，查看 Slack 中销售团队关注的重点，查询数据仓库，并留下一个包含各项数字和若干建议关注领域的文件夹。

周一早上，Ian 打开 Claude Cowork，拉取初始报告，其中包含指标表格和建议的标题，即关注领域。



此处展示的每周业务回顾摘要使用演示数据创建，所有信息均已匿名化或修改以便公开发布。

Ian 审阅这些内容，一旦确认或决定了叙述的重点，他就让 Claude 用支撑细节和示例对它们进行展开。有些周团队是在响应销售优先事项，另一些周则是在响应产品发布。到了季度交替时，Ian 会让 Claude 以季度计划为主线，并输入季度回顾文档。

Claude 基于同样的数据和叙述生成面向管理层的幻灯片：发生了什么变化、为什么变化，以及各团队正在如何应对。任何后续事项都会转化为 Asana 任务。



此处展示的每周指标报告使用演示数据，所有信息均已匿名化或修改以便公开发布，其中包含关键指标和建议的关注领域。

当数字对不上时，Claude 会标记出不一致之处，而不是猜测。例如，销售团队重组之后，营销部门的报告不再与他们的报告匹配。Claude 标记出了这一差异，并询问 Ian 如何处理。

该流程依托于连接团队所用营销平台和工具的连接器（Connectors），以及 Ian 搭建并持续更新的三个 Skills（技能）：

-   **一个准备技能（prep skill）** 驱动报告组装，包括重点、标题以及用支撑细节进行展开。
-   **一个校对技能（proofreading skill）** 对照经验证的来源检查草稿中的每一个数字。
-   **一个行动事项技能（action-items skill）** 将后续事项转化为 Asana 任务。

在每周会话结束时，Ian 会让 Claude 总结本次出现、应当回写到 Skills 中的内容。例如新的销售重组结构、他做出的更正，或者他希望标题采用的新表述方式。对 Ian 而言，整个流程过去最多要花两天，现在最多只需两小时。

如今，Ian 有相当一部分时间转向了帮助营销人员厘清他们的问题、优化他们的提示词，以及在他们自行从 Claude 拉取数据时解读返回的结果。他也有了余力深入数据层，确保 Claude 对数字、定义和区域结构的理解与数据仓库保持一致。

人工验证已成为两条工作流中不可或缺的一环——随着 Claude 将传统上占据营销分析师大量时间的琐碎手动任务自动化，这一转变正在加速。

## **自动化活动搭建与数据导入**

搭建营销活动背后的基础设施，历来是营销中最手动化的流程之一。每一场活动、网络研讨会或整合营销活动，都需要在 CRM 中、在负责运行邮件序列及其背后自动化的营销自动化平台中，以及在承载注册页面和活动落地页的活动管理平台中分别进行设置。这些通常来自不同的供应商，而它们之间的集成很少是完整的。

在使用 Claude Cowork 之前，Annabel 会从一个专门的 Slack 频道接收每一个请求，然后手动走完整个流程。她的新设置几乎完全由 Claude 处理。流程始于一个接收表单，请求者在此说明所需帮助的类型：活动搭建、数据导入、申请参会（apply-to-attend）或审批支持。

每小时，一个**调度技能（dispatcher skill）** 会读取该频道，挑选最紧急的请求，给工单打上标记以避免重复处理，然后将其交给 Annabel 搭建的五个专项技能之一来完成所需工作。它本身不做任何活动设置；它的职责是决定接下来运行什么，而将其独立出来，让 Annabel 可以单独优化每个专项技能，而无需改动路由逻辑。



调度技能（为公开发布已编辑，以展示演示数据和信息）读取频道，并将请求交给五个专项技能之一来完成所需工作。

对于活动搭建这一最复杂的请求类型，一个**活动搭建技能（event-build skill）** 端到端处理完整流程：CRM 营销活动创建、带工作流和列表的营销自动化活动、活动平台设置、邮件起草、落地页生成，以及它们之间的所有集成。



活动搭建技能（节选并编辑以便公开发布）编排两条 Slack 更新：一条在 Claude 接手请求时，另一条在落地页可供请求者审阅、审计接手时。

搭建完成后，它会交给一个新的智能体进行审计。**审计智能体（audit agent）** 从零上下文开始，在线上落地页提交一次测试注册，在 Gmail 中打开确认邮件，如果一切正常，就将 Asana 任务标记为完成。Annabel 会在每次结果发布前进行审阅。

该工作流依托于连接 Annabel 所用营销平台和工具的 Connectors，以及她在发现新边缘情况时搭建并更新的若干 Skills：

-   **一个调度技能（dispatcher skill）** 读取接收频道，并将每个请求路由到下方对应的专项技能。
-   **一个活动搭建技能（event-build skill）** 驱动跨平台的端到端设置。
-   **一个网络研讨会落地页创建技能（webinar-landing-page creation skill）** 为网络研讨会搭建落地页。
-   **一个审计技能（audit skill）**，由另一个全新的 Claude 实例运行，在任务标记为完成前验证活动搭建技能的输出。
-   **一个申请参会技能（apply-to-attend skill）** 处理注册流程进行中的变更：
-   **一个审批支持技能（approval-support skill）** 处理活动审批，并按预定节奏发送相应的邮件。
-   **一个数据导入技能（data-import skill）** 清洗名单并处理参会者数据。

她还保持着一个独立的“管理者”智能体常开。当某次运行出现偏差时，她会打开这个管理者，让它查看发生了什么并提出调整建议。任何值得保留的内容都会回写到相应的技能中。

虽然这些自动化工作流将大大节省 Annabel 日常工作中的时间，但她搭建它们的主要动机是工作质量。随着营销团队规模扩大，营销人员从手边任意一个模板克隆活动页面可能会产生缺陷，例如确认邮件显示出错误的城市名，或者落地页损坏。借助 Claude Cowork，她能够大规模地获得一致的搭建质量。

随着 Claude 承担起营销活动运营中重复性的部分，Annabel 可以专注于更具战略性的项目，例如赋能，以及为获得更好的洞察而自动化或优化流程与营销活动架构。

## **给市场运营团队上手 Claude Cowork 的建议**

-   **把重复的更正转化为 Skills。** 当你发现自己就同一件事不止一次地更正 Claude 时，这些反馈就应该写入一个技能。你也不必自己搭建技能：Claude 可以替你完成。
-   **先搭建一个校对技能。** 校对技能会检查 Claude 放入报告中的每一个数字是否都能追溯到经验证的来源。
-   **让 Claude 反思。** Claude 阅读指令的方式与人类书写指令的方式不同，因此在新工作流的头几次运行之后，问问它这些指令哪里难以理解。Annabel 会把浮现出的问题回写到技能中，这是她持续更新技能这一更广泛实践的一部分。
-   **善用定时任务。** 每周日晚或每小时自行运行的工作，就是没人需要记着去做的工作。
