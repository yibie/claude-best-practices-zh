# 在前沿工作：Cursor 如何判断 Claude Fable 5 已准备好应对最难的 1% 问题
Cursor 是一款用于构建专业软件的 AI 编码智能体。它既支持所有主流前沿模型，也支持 Cursor 自研模型，这使该公司成为评判各模型实际表现的、格外中立的裁判。

Nate Schmidt 就是维护这份评分表的工程师。他在 Cursor 从事评估（eval）与模型行为方面的工作：研究模型如何成功、如何失败，以及是什么让开发者在任务进行到一半时悄悄换掉某个模型。当同事和客户想了解某个新版本的表现时，都会来找他。

随着时间推移，Schmidt 的团队注意到，公开基准测试的分数与开发者对这些模型的真实反馈已经对不上了，于是他们构建了自己的评估：CursorBench。

CursorBench 的构建初衷，是捕捉工程师实际向模型提问时那种混乱、描述不充分的方式。其中一个评估任务只是粘贴一段堆栈跟踪，外加一个词「fix」，模型必须自行推断意图、找到根因并验证改动。另一个任务则告诉模型错误的模块出了问题，看它是质疑用户的假设，还是顺着假设走进死胡同。

当 Claude Fable 5 运行该评估时，模型在 Max effort 下取得了 72.9% 的成绩，创下新高，也展现了智能体式编码工具在搭配合适模型时所能达到的能力。

但当 Schmidt 将模型用于自己的工程工作流和个人测试时，他发现自己不再需要反复重申目标。那种不断的照看——提醒模型上下文、把解决方案讲清楚、审查结果——已经不再必要。他可以把一个问题交出去，从一直拖延的棘手重构，到对微妙边界情况的推理，Claude Fable 5 都能解决。

「我不觉得自己需要先给 Claude Fable 5 做引导，它才能理解我所处的世界和我试图解决的问题，」Schmidt 说。「这个模型一上手就有那种感觉。」

### **对整个任务进行推理**

当 Schmidt 的团队让新模型跑 CursorBench 时，得出正确答案只是基本要求。他们真正评分的是模型是否理解了它被要求做什么。

「很多评估是这样的：这里有一个定义明确的问题，这些是约束条件，去解决它。但我们从真实用户那里收到的提示词并不是这样，」Schmidt 说。「模型必须推断出用户遇到了问题、想表达什么，找出根因、修复它、验证修复，然后汇报结果。」

Claude Fable 5 在这些模糊任务上得分太高，Cursor 团队开始感到怀疑。

「只有两种可能：要么这个模型非常聪明，要么它在作弊，」他说。于是团队深入查看追踪（trace），阅读模型在最难任务上的实际推理过程——那些提示词看起来简单、但要破解却需要理解整个系统的任务。

「我们不断看到这个模型挖出其他模型此前做不到的胜利，」他说。而且它用更少的操作就达到了目标：相对于完成的工作而言，token 效率很高。

随后，Schmidt 把 Claude Fable 5 放到了他最喜欢的个人测试之一上：登月。

几周前，他曾把一个可编程航天飞行模拟器接入 Claude Opus，用一句提示词——造一枚火箭并让它登上月球——让它在第二块显示器上跑了十二到十六个小时。模型会发射，在轨道上耗尽燃料，于是加了很多燃料，结果又因为火箭太重而无法飞出大气层。

他用同样空白的提示词重跑了这个实验，这次使用 Claude Fable 5。几分钟后，火箭升空，停在低轨道，然后又掉了下来。和之前一样的失败。接着 Schmidt 读了对话记录。

「Fable 决定第一次不直接去月球。它想先做一次初始任务，只是进入轨道并收集遥测数据，然后用这些数据指导下一次飞行。」几次尝试之后，他第二块显示器上的引擎噪音停了。月球上出现了一个着陆器。整个运行轮次（run）花了几个小时，而 Opus 跑了十二个多小时却毫无结果。

「用 Opus 时，它做的是局部推理——思考刚刚发生了什么、接下来马上会发生什么，」Schmidt 说。「用 Fable 时，它是全局推理。它在思考整个任务。」



Cursor 让所有模型都跑 CursorBench，这是他们内部的基准测试，用于在模拟真实开发者工作的任务上评估模型。

### **何时该追求全局最优**

对于何时该用 Claude Fable 5 而非更便宜、能力更弱的模型，Schmidt 已经定下了一条简单的规则。

「如果你清楚从 A 到 B 的路径长什么样，你可能不需要 Fable。如果你在 A 点，却完全不知道 B 在哪里，Fable 是极佳的选择，」他说。「当我想以正确的方式构建某样东西时，Fable 是我第一个想到的模型。」

Claude Fable 5 还让他的团队得以专注于此前被搁置的项目——那些大家都认同会更好、但没人能证明值得花上几周去做的重写——因为模型能承担足够多的骨架工作。「它降低了这类任务的启动门槛，」Schmidt 说。「它让我们能够去追求全局最优，而不是局部最优。」

它也改变了团队的协作方式。Cursor 的团队很精简，强调个人高度负责，站会很少。现在，在改动共享代码之前，Schmidt 会让一个智能体阅读队友最近的提交并标记冲突，这样两人都不必停下手中的工作去同步。

为了平衡成本与性能，他的团队将 Claude Fable 5 与更快、更轻的模型搭配用于日常工作，并在能力成为瓶颈的问题上引入它。他说，在这种配置下，这个组合是他们运行过的最有效的方案。

「如果我遇到一个真正棘手的问题——问题中的 p99——我要优化的目标是解决时间，」他说。「而我认为 Fable 是解决我们最难问题的最佳模型。」



Nate Schmidt 在各种评估中测试新模型，包括让它在航天飞行模拟器中接受考验。

### **下一步**

尽管已经在 CursorBench 上让模型接受了考验，还把它送上了月球，Schmidt 仍在寻找 Claude Fable 5 的极限。接下来，他想看看这个模型能在无人值守的情况下管理一个后端系统多久；持续数天到数周的运行轮次是他的下一个实验。在 Cursor 内部，团队正用这个模型主动排查性能瓶颈和用户痛点，而不是等待报告，同时也在构建更复杂、更接近现实的评估环境，用来衡量未来出现的一切。

「有一类问题人们甚至都没去想过，因为看起来无从下手，」他说。「有了 Fable，我很兴奋去攻克它。」
