# 为每个任务打造执行框架：Claude Code 中的动态工作流
上周，我们在 Claude Code 中发布了[动态工作流](https://code.claude.com/docs/en/workflows)。Claude 现在可以即时编写自己的[执行框架（harness）](https://code.claude.com/docs/en/glossary#agentic-harness)，针对手头的任务量身定制。

虽然默认的 [Claude Code](https://claude.com/product/claude-code) 执行框架是为编码而构建的，但它对许多其他类型的任务也很有用，因为事实证明，许多任务都与编码任务相似。但有几类任务，我们不得不在 Claude Code 之上构建自定义执行框架才能达到最佳性能，例如[研究](https://support.claude.com/en/articles/11088861-using-research-on-claude)、[安全分析](https://support.claude.com/en/articles/11932705-automated-security-reviews-in-claude-code)、[智能体团队](https://code.claude.com/docs/en/agent-teams)或[代码审查](https://code.claude.com/docs/en/code-review)。

工作流让你能够动态创建构建在 Claude Code 之上的执行框架，使 Claude 能更原生地解决所有这些类型的问题。你还可以与他人分享和复用这些工作流。

在本文中，我将介绍我最初使用工作流的经验和心得，以便你充分利用它们。请记住，最佳实践仍在发展中：动态工作流通常使用更多 token，最适合复杂、高价值的任务。

## 示例提示词

在深入技术细节之前，我想先给出几个示例提示词，让你思考工作流的可能性：

“这个测试大约每 50 次运行会失败 1 次。建立一个工作流来复现它。针对这个竞态提出相互竞争的理论，直到有一个理论经得起证据检验才停止。”

“使用工作流，浏览我最近 50 个会话，挖掘我反复做出的纠正，并把反复出现的纠正转化为 `CLAUDE.md` 规则。”

“使用工作流深入挖掘 Slack 中 #incidents 频道过去六个月的内容，找出没有人提交工单的反复出现的根本原因。”

“拿我的商业计划书运行一个工作流，让不同的智能体分别从投资者、客户和竞争对手的角度对它进行拆解。”

“这里有一个包含 80 份简历的文件夹，使用工作流为后端岗位对它们进行排名，并复核前十名。使用 AskUserQuestion 工具就评分标准采访我。”

“我需要为这个 CLI 工具起个名字。使用工作流头脑风暴出一堆选项，然后运行一场锦标赛选出前 3 名。”

“使用工作流把我们的 User 模型在所有地方重命名为 Account。”

“浏览我的博客文章草稿，使用工作流对照代码库验证每一项技术论断，我不想发布任何错误的内容。”

## 动态工作流的工作原理

动态工作流执行一个 JavaScript 文件，其中包含几个特殊函数，用于生成和协调[子智能体](https://code.claude.com/docs/en/sub-agents)：

![agent(prompt, opts) 函数及其选项注释：prompt 是唯一必需的输入，schema 返回经过验证的 JSON，model 选择 opus、sonnet 或 haiku，isolation 为 worktree 或 remote，agentType 选择子智能体。其下方，parallel() 扇出并等待全部完成；pipeline() 让每个条目流经每个阶段。](https://claude.dev/media/405c8b387ec2cc574e6d48edba5431e02e23e4fca7c31d51184fc9738eaef70b.png)

**图 A** 工作流脚本的三个构建块：agent() 生成一个子智能体；parallel() 和 pipeline() 组合多个子智能体。

动态工作流还包含标准 JavaScript 函数，如 JSON、Math 和 Array，以帮助处理数据。

特别有用的一点是，动态工作流可以决定智能体使用哪个模型，以及子智能体是否在各自的 worktree 中运行，从而让 Claude 选择所需的智能水平和隔离程度。

如果工作流被中断，例如因用户操作或退出终端，恢复会话将允许工作流从上次中断的地方继续。

## 为什么需要动态工作流

当你让默认的 Claude Code 执行框架执行任务时，它需要在同一个上下文窗口中同时进行规划和执行。对于许多编码任务来说，这非常有效，但在长时间运行、大规模并行、高度结构化和/或对抗性的任务中，它可能会失效。

这是因为 Claude 在单个上下文窗口中处理复杂任务的时间越长，就越容易受到几种特定失败模式的影响：

-   **智能体式惰性**是指 Claude 在完成一项特别复杂的多部分任务之前就停下来，在取得部分进展后就宣布任务完成，例如在安全审查中只处理了 50 个条目中的 35 个。
-   **自我偏好偏差**是指 Claude 倾向于偏好自己的结果或发现，尤其是在被要求根据评分标准验证或评判它们时。
-   **目标漂移**是指在多轮对话中逐渐偏离原始目标，尤其是在上下文压缩（compaction）之后。每次总结步骤都是有损的，诸如边缘情况要求或“不要做 X”之类的约束等细节可能会丢失。

创建工作流有助于对抗这些问题，方法是编排具有各自上下文窗口和专注、隔离目标的独立 Claude 子智能体。

## 动态工作流与静态工作流

你之前可能使用 Claude Agent SDK 或 `claude -p` 创建过静态工作流，将多个 Claude Code 实例协调在一起。

但由于静态工作流需要适用于所有边缘情况，它们通常更通用。借助 [Claude Opus 4.8](https://www.anthropic.com/news/claude-opus-4-8) 和动态工作流，Claude 现在足够智能，可以为你量身定制编写专属的执行框架。

![“我们应该把结账服务迁移到新的提供商吗？”这个问题以两种方式处理。静态执行框架运行五次网络搜索，获取结果，验证并总结成一份通用的研究报告。动态工作流读取计费代码，对照新提供商的文档检查每项功能，按真实交易量计算价格，运行一个反方论证，最终给出具体的建议。](https://claude.dev/media/fb7abff3846443de3b59b23208f0019bad6eb2555e5dd945594438ce4ee143c1.png)

**图 B** 静态执行框架对每个问题运行相同的步骤；动态工作流则针对眼前的问题量身定制。

## 使用动态工作流时的实用模式

你可以直接让 Claude 创建一个工作流来开始使用动态工作流，或者使用触发词“`ultracode`”来确保 Claude Code 创建工作流。

但建立对动态工作流工作原理的心智模型，将有助于你理解何时使用它们，以及如何通过提示词引导 Claude。

Claude 在构建工作流时可能会使用并组合几种常见模式：

![六种工作流模式的小图：分类并执行、扇出并综合、对抗性验证、生成并过滤、锦标赛，以及循环直到完成。](https://claude.dev/media/0a60d2d8c1dbddc23694ead5848908e1f2c9ef9e57ed0fbdbf53a0dc11e9ed16.png)

**图 C** Claude 组合使用的六种工作流模式。

### 分类并执行

使用分类器智能体决定任务类型，然后根据任务路由到不同的智能体或行为。或者，在最后使用分类器来确定输出。

### 扇出并综合

将任务拆分为许多更小的步骤，对每个步骤运行一个智能体，然后综合这些结果。当有大量较小步骤时，或者当每个步骤受益于自己干净的上下文窗口以免相互干扰或交叉污染时，这特别有用。综合步骤是一个屏障——它等待所有扇出的智能体完成，然后将它们的结构化输出合并为一个结果。

### 对抗性验证

对于每个生成的智能体，运行一个单独生成的智能体，根据评分标准或条件对其输出进行对抗性验证。

### 生成并过滤

就某个主题生成若干想法，然后根据评分标准或通过验证进行过滤，去除重复项，只返回最高质量、经过测试的想法。

### 锦标赛

与其划分工作，不如让智能体就工作进行竞争。生成 N 个智能体，每个都使用不同的方法尝试同一任务。然后由提示词或模型以两两比较的方式评判结果，直到产生一个赢家。

### 循环直到完成

对于工作量未知的任务，循环生成智能体，直到满足停止条件（没有新发现，或日志中没有更多错误），而不是固定次数的遍历。

## 用例

创造性地思考何时以及如何让 Claude Code 创建动态工作流。我发现工作流有时对非技术工作甚至更有用。

### 迁移与重构

[Bun](https://bun.com/) 使用工作流从 Zig 重写为 Rust。你可以在 [Jarred 的帖子](https://x.com/jarredsumner/status/2060050578026189172)中了解更多相关信息，或了解我们如何在数百万行的代码库中运行 [AI 代码迁移](https://claude.com/blog/ai-code-migration)。

关键在于将任务分解为一系列需要操作的步骤，例如调用点、失败的测试、模块等。在 worktree 中为每个修复生成一个子智能体来进行修复，然后让另一个智能体进行对抗性审查，并合并它们。考虑告诉智能体不要使用资源密集型命令，以便你可以最大程度地并行化而不会耗尽机器资源。

### 深度研究

我们在 Claude Code 中发布了一个使用动态工作流的深度研究 Skill（技能）（`/deep-research`）。具体来说，它会扇出网络搜索、获取来源、对抗性验证其论断，并综合出一份带引用的报告。

但你可能不仅仅为网络搜索做这类研究。例如，让 Claude 从 Slack 中的上下文汇编一份状态报告，或通过深入探索代码库来研究某个功能如何工作。

### 深度验证

![一份报告流入论断提取器，后者扇出到论断检查器 1 到 N，每个检查器后面可选地跟随一个来源审计器，最终汇聚成一份经过验证的报告。](https://claude.dev/media/14981a07d95b7a4f10f6e995e34ea589c6a87836a753f3ffd70047363adb34dd.png)

**图 D** 深度验证：每个事实性论断对应一个检查器智能体，每个检查器后面可选地跟随一个来源审计器。

另一方面，如果你有一份报告，想要检查并溯源它引用的每一项事实性论断，你可能想生成一个工作流，让一个智能体识别所有事实性论断，然后生成一个子智能体详细检查每一项。你还可以让一个验证智能体检查来源子智能体，以确保其来源质量高。

### 排序

![1,000 个条目进入一个对阵图：第一轮将条目与每次比较的新智能体配对，获胜者在第二轮相遇，最后一次比较决定决赛，输出是一个排序后的列表。](https://claude.dev/media/be7b8dc2e6f8a2791efb3c4589fa182f0c90b380bb56d8b41a1f18fc7cb04394.png)

**图 E** 锦标赛排序：每次比较都获得一个新智能体，因此没有单个上下文需要容纳全部 1,000 个条目。

你可能有一个列表，想按某种你认为 Claude Code 擅长评估的定性指标进行排序，例如：按 bug 严重程度对支持工单排序。但如果你试图在一个提示词中对 1000 多行进行排序，质量会下降，而且无法放入上下文。相反，运行一场锦标赛、一个两两比较智能体的流水线（比较性判断比绝对评分更可靠），或并行分桶排名然后合并。每次比较都是自己的智能体，因此确定性的循环持有对阵图，只有当前排序留在上下文中。

### 记忆与规则遵循

![一个 +142 和 −87 行的差异对照五条规则进行检查，每条规则一个验证器智能体。两条规则标记了第 42 行和第 90 行；其余返回干净。一个怀疑者智能体重新阅读每个标记，以区分真正的违规和误报，只留下已确认的违规。](https://claude.dev/media/fd6d2a8544c5541442fb2df1c24374ff8e2984274cc2bf796fe5e632bfcc400a.png)

**图 F** 逐规则审查：在干净的上下文中每条规则一个验证器，然后由怀疑者过滤标记。

如果你有一组特定的规则，发现 Claude 即使把它们放进 `CLAUDE.mds` 也会遗漏或难以遵守，那就创建一个工作流，列出必须由验证器智能体检查的规则——每条规则一个验证器。创建一个怀疑者人格的子智能体来审查规则以确保它们符合要求，将有助于避免过多误报。

反过来也成立：挖掘你最近的会话和代码审查评论中你反复做出的纠正，用并行智能体对它们进行聚类，对抗性验证每个候选（这条规则本可以防止一个真实的错误吗？），然后将幸存者提炼回 `CLAUDE.md`。

### 根本原因调查

调试的最佳方式是提出几个独立的假设并测试它们，但如果你只使用一个上下文窗口，Claude 可能会遇到自我偏好偏差。

工作流可以通过从不相交的证据中生成智能体来产生假设，在结构上防止这一点。例如，为日志、文件和数据分别设置独立的智能体。然后每个假设可以面对一个验证器和反驳者小组。

这不仅适用于代码。工作流可用于销售（为什么三月份销售额下降？）、数据工程（为什么这个流水线失败？）或任何事后分析演练。

### 大规模分诊

![一个不可信的支持工单、bug 报告和用户反馈积压进入一个带有只读工具的隔离区，读取器智能体在其中对每个条目进行分类，对照已跟踪的内容去重，并只输出结构化摘要。一个带有高权限工具的可信区包含一个行动者智能体，它对摘要采取行动，尝试修复并在可修复时打开 PR，否则升级给人类。/loop 持续运行它。](https://claude.dev/media/ebf352766b6bb484729e8a8c08f9a72f918b19f78d02e998fe3384fcf3fd88e3.png)

**图 G** 先隔离，再行动：读取器智能体以无权限方式接触不可信内容；行动者智能体只看到它们的摘要。

每个团队都有支持队列、bug 报告或其他无法由人类完全处理的积压。

分诊工作流对每个条目进行分类，对照已跟踪的内容去重，并采取行动。这可能意味着尝试修复或升级给人类用户。

分诊工作流的一个有用模式是隔离。这涉及禁止读取不可信公共内容的智能体采取高权限操作，这些操作改由负责对信息采取行动的智能体完成。

将分诊工作流与 /loop 配对，让 Claude 持续执行此操作。

### 探索与品味

在探索解决方案的不同方法时，工作流可能很有用，尤其是当它基于品味时，比如设计或命名，并且会受益于评分标准。

试着让 Claude 探索一堆解决方案，并给审查智能体一个关于好解决方案应该是什么样的评分标准。当审查智能体觉得已满足标准时，任务就完成了。解决方案也可以根据评分标准通过锦标赛进行排序或选择。

### 评估（eval）

你可以通过在工作树中生成独立的智能体，然后生成比较智能体来对照评分标准比较和评分特定输出，从而为特定任务运行轻量级评估。例如，[评估并改进](https://claude.dev/blog/automating-eval-design-and-hillclimbing/)你创建的某个 Skill（技能）以符合特定标准。

### 模型与智能路由

创建一个针对你的任务调优的分类器智能体，决定使用哪个模型。当你的任务涉及大量工具调用，且在执行前进行研究可以确定最适合该工作的模型时，这可能会有所帮助。

例如，对于“解释 auth 模块如何工作”这个任务，最佳模型取决于 auth 模块中有多少文件以及代码库的形态。分类器智能体可以进行这项研究，然后根据任务的预期复杂度[路由到 Sonnet 或 Opus](https://claude.dev/blog/building-with-claude-sonnet-5-5/)。

## 何时不应使用动态工作流

工作流是新的。虽然有许多用例会产生超常的结果，但它们并非每个任务都需要，并且最终可能会使用显著更多的 token。

最好创造性地使用工作流，以你以前未曾尝试过的方式推动 Claude Code。对于常规编码任务，试着问自己：它真的需要更多算力吗？例如，大多数传统编码任务不需要 5 名审查者组成的小组。

同样的判断适用于更高一层的架构层面：[多智能体与单智能体](https://claude.com/blog/building-multi-agent-systems-when-and-how-to-use-them)的决策遵循类似的逻辑——并行化和专业化必须证明其协调成本是值得的。

## 构建动态工作流的技巧

### 提示

使用我们上面描述的特定技术为动态工作流编写详细的提示词，会产生最佳结果。

工作流不仅仅适用于大型任务。你可以提示模型使用“快速工作流”。例如，你可以对一个假设创建快速的对抗性审查。

### 与 `/goal` 和 `/loop` 结合使用

当使用可重复的工作流时，例如分诊、研究或验证，将它们与 `/loop` 配对以[定期运行](https://claude.com/resources/articles/getting-started-with-loops)，并与 /goal 配对以设置硬性完成要求。

### token 用量预算

你可以为动态工作流设置明确的 token 用量预算，以限制任务使用的 token 数量。你可以用类似“使用 10k token”的预算来提示它，这将设置上限。

### 保存和分享动态工作流

你可以在工作流菜单中按“s”来保存工作流。你可以将它们保存到 `~/.claude/workflows`，或通过 Skill（技能）分发它们。

![Claude Code 中的动态工作流面板列出了三次运行，包含智能体数量、token 总数和持续时间：review-changes（14 个智能体，482k token，6 分 12 秒）、find-flaky-tests（6 个智能体，仍在运行）和 deep-research（22 个智能体，1.1M token，11 分 3 秒）。底部按键：select、enter view、s save、esc close。](https://claude.dev/media/c8b4b65c4c43f1d01be880efd0851cdfc50e8bd9c8517a57d16a761ce7d0331a.png)

**图 H** 动态工作流面板——按 s 将一次运行保存为可复用的工作流。

要通过 Skill（技能）分享它们，请将你的 JavaScript 工作流文件放入 Skill 文件夹，并在 `SKILL.md` 中引用它们。为了获得更大的灵活性，你可能想提示 Claude 将 Skill 中的工作流视为模板，而不是需要逐字运行的脚本。
